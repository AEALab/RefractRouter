# 四策略审查与改进依据

核对日期：2026-09-27。产品方向由本次用户要求确定；研究结果只作为设计依据。

## 源码与研究基线

Switchyard 固定到 `66bac290869494dcf162fd61456e019ef8dbd057`（2026-09-26）。
它仍将路由放在模型接口与后端之间。其 Stage 从工具信号评分并保持强模型，
Escalation 先生成再判别并锁定强模型。参见
[固定 Stage 实现](https://github.com/NVIDIA-NeMo/Switchyard/blob/66bac290869494dcf162fd61456e019ef8dbd057/crates/libsy/src/algorithms/util/stage.rs)与
[固定 Escalation 说明](https://github.com/NVIDIA-NeMo/Switchyard/blob/66bac290869494dcf162fd61456e019ef8dbd057/docs/routing_algorithms/escalation_router_routing.md)。

上游 Stage 的分数幅度不是任务成功率，且存在探索/停滞的编码场景先验。
我们的普通检索不会直接计为停滞。上游 Escalation 对无法解析的 verdict 可能放行低成本回复，
我们继续停止并保留费用；上游的会话级锁定不等同于我们任务内锁定。
这些是刻意保留的差异，不能把当前实现称为 Switchyard 原样复现。

该提交还增加请求字段省略配置，涉及 Codex Responses 接入所需的协议限制。
对本项目的启发是分离协议转换与策略，不应为了兼容而在策略中插入某个 Agent 的提示或工具逻辑。
[固定提交](https://github.com/NVIDIA-NeMo/Switchyard/commit/66bac290869494dcf162fd61456e019ef8dbd057)。

| 原始研究 | 方法与适用边界 | 本项目采用或建议 |
| --- | --- | --- |
| [RouteLLM](https://arxiv.org/html/2406.18665v4) | 以偏好数据训练强弱模型选择器；阈值控制使用强模型的比例，能力迁移需测量 | Task 能借鉴轻量判别和团队反馈校准；不以模型名称或未经校准的 0.8 分数证明质量 |
| [FrugalGPT](https://arxiv.org/abs/2305.05176) | 利用模型级联与回答评分控制成本；收益依赖数据和级联配置 | Escalation 必须把起始、Judge、接管三者费用全部计入；不能仅看最终模型账单 |
| [AutoMix](https://arxiv.org/html/2310.12963v3) | 自验证与不确定性驱动模型升级；验证本身也有误差和费用 | 分开统计漏放缺陷与误升级；Judge 校验不通过不能自动当成合格 |
| [MixLLM](https://arxiv.org/html/2502.18482v1) | 预测质量和输出成本，结合时延约束与在线更新；论文含模拟的时延条件 | 区分预算硬上界与预期费用；需要本团队、同路线的等待测量，不能直接复制论文速度 |
| [RouterBench](https://arxiv.org/abs/2403.12031) | 使用预先取得的多模型结果评估选择器 | 可用于离线策略排错，但回放不能证明换模后的工具轨迹质量；保留固定模型基线即可，避免无限扩大实验 |

以上公开收益不能转写成本项目已经实现的节省百分比。
本轮不运行新的付费对照实验。

## 本轮实际修改

| 策略/边界 | 审查发现 | 本轮处理 |
| --- | --- | --- |
| Static | Random 把互斥的两个候选费用累加；单次调用额度也可能误挡 | 先按冻结 seed 选模型，再只预留选中模型，续接保持同一选择 |
| Stage | 同 ID 重放可被当成重复失败；旧失败影响保持结束后的新探索 | 去重并要求新失败证据才能重新增加困难分；规则记为 `stage-v4` |
| Task | 模型描述硬编码 DSH 传输；核心缺少标准 API 入口 | 改为通用模型描述，新增独立 Chat/Responses 协议适配，复用已有质量门槛和费用排序 |
| Escalation | 预检忽略本次较小输出上限；云端 Judge 期限没有传到实际调用 | 使用请求与策略上限的较小值，核心签发期限，插件与独立传输共同遵守 |
| 并发 | 同任务的第二个 step 会使第一个在途调用被停止 | 明确拒绝冲突请求，原调用继续正常结算 |
| 证据 | 策略文件直接解析 DSH 事件字段 | 解析移入 DSH 适配文件，核心增加中立事实入口；标准工具文本不伪造退出码 |

Static 是稳定的固定/随机路线，不宣称自动理解任务或优化质量。
现有随机设置仍是高效/强执行两角色的兼容配置；任意大小的 Static 模型池属于后续设置改进。
Task 继续按任务冻结模型，不因普通工具续接额外调用 Judge。
Escalation 继续先审核未交付候选，丢弃工具不交给宿主，接管后不再审核。

## 建议的下一步，按产品价值排序

1. **先补协议真实验收。** 固定各客户端实际版本，分别记录使用的 wire API、工具类型、
   reasoning/replay、取消与会话标识。优先接入实际团队在用的客户端；不能只靠模型名称列出兼容品牌。
2. **分开预算与预期费用。** 硬预算继续使用保守上界；有足够相似任务记录后，
   用实际输出长度和缓存命中估计预期费用来排序。缺证据时保留明确的不确定性。
3. **最小质量反馈闭环。** 记录用户是否接受交付、测试是否通过、是否返工；
   只在冻结模型/推理档位/任务类型内校准。无需为了上线再做大规模研究实验。
4. **控制路由开销。** Stage 保持零额外 Judge，Task 每任务最多一次。
   Escalation 显示 Judge 成本占比及升级后的额外等待；判别负收益时让团队选用 Static/Task。
5. **减少不必要换模。** 后续根据可核对缓存与 token 成本评价保持窗口，
   不能仅因为强模型标价低或单次快就立即切换。
6. **用真实时延作第三排序因素。** 记录用户首次可见输出和端到端 P50/P95，
   区分本地 Judge 冷启动、排队、推论及远程网络时间；没有同条件样本时不补造延迟排名。

这些是改进建议，不是本轮已完成的新学习算法或节省收益。
现有本地 Laya 回复审核未通过日常质量门槛的限制仍保留。

## 有限完成标准

本轮以核心升级、实际插件兼容、职责边界和确定性修复为交付。
独立 HTTP 接口的文本/function 子集已有无网络验收；全品牌客户端、所有多模态和
上游逐 token 透传仍需按协议逐项接通。详见
[独立模型接口边界](independent-model-router.md)与
[升级验收记录](../reports/dsh-router-upgrade-20260927/README.md)。
