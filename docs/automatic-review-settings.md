# 自动路由的独立最终审核设置

## 使用方式

在 DSH「RefractAgent 自动路由」设置卡片的「最终回复审核」区域设置：

| 设置 | 含义 | 未设置／0 |
|---|---|---|
| 审核模型 | 复用模型池中的实际路线，独立指定最终审核用途 | 沿用模型池角色选择 |
| 审核推理等级 | 从该路线宿主支持的值中选择，只影响最终审核 | 未设置沿用路线参数；提供方默认不传等级 |
| 审核等待上限 | 最终审核开始后最多等待多久 | 未设置或 0 沿用任务剩余时间 |
| 为审核预留时间 | 规划及执行阶段提前留下的任务时间 | 未设置默认 60 秒；0 不预留 |
| 任务总期限 | 覆盖规划、执行与最终审核 | 未设置沿用部署值；0 不限时 |
| 审核输出上限 | 独立于执行输出容量，包含提供方计入的推理输出 | 未设置默认 8192 tokens；不接受 0 |

「填写已验证的审核限制（180 秒）」只修改待保存的审核等待、预留及输出参数，
保存后生效。它不改动模型绑定、执行推理等级、现金预算或默认路由策略。
180 秒仍受任务剩余期限约束：任务只剩 90 秒，审核最多等待 90 秒。
预留时间是对执行阶段的时间保护，不保证提供方在该时间内完成。

已有配置缺少新字段时继续读取原行为。高级模型池中的审核角色与此处共享同一选择，
换审核模型时清除旧的独立等级，避免把上一条路线的等级传给新模型。
独立审核用途通过 Python 编译为新的用途绑定，同一 provider／model 的规划与执行
保留原参数；物理路线共用审核器的准入要求继续有效。

## 核心及展示

`dshModelPool.judgeReasoningEffort` 保存独立审核参数；
`liveExecution.reviewTimeoutMs`、`reviewReserveMs`、`reviewMaxOutputTokens`、
`taskTimeoutMs` 保存运行包络。Python 验证实际等级、选取审核绑定并计算最终期限；
插件仅传递配置与宿主调用。核心和标准模型接口不新增 DSH 工具执行职责。

`automatic-review-envelope-v2` 记录审核模型、等级、等待上限、任务期限和派发时实际
可等待时间。旧轨迹缺字段继续显示旧记录，不用当前设置补写历史。
取消、未知用量保留预留、零 HTTP 自动重试及数据域准入继续生效。

认定参数矛盾前核对用途及条件。原正文与一份明确标注未知的修正版各做一次审核，
结果分别拒绝／通过；这是两例针对复验，不代表普遍准确率。该复验仅发送公开任务、
材料与正文，没有复制完整宿主系统上下文，不能把变化单独归因于提示修订。

原记录不追改。新合同安装后的同任务复查及失败后独立复验，结果追加在
[实际使用记录](../reports/automatic-applicability-20261008/review-settings-daily-use.json)。

180 秒。未来选择有限任务期限时，保存的 60 秒预留才作为执行余量生效。

费用与回放；未通过质量审核、工具证据或输出限制的候选仅留运行证据。
