# 规划路由原生输出预算

对应 [#223](https://github.com/AEALab/RefractRouter/issues/223)，核心 0.16.35、插件 0.33.22。
统一预算预检、必要调用路径和实际预留，不修改六策略算法、模型池、阈值、默认策略，
不增加真实调用或 HTTP 自动重试。独立 DAG 与 W09 专用研究包络保持原入口和历史证据。

## 原生上限与费用保护

旧规划入口可将原生 `maxTokens` 交给宿主，底层历史 Chat 预留却只按 8192 计算；
一些部署的上限还只约束回答，思考仍计入全部输出。
现在 `planning_output_budget.reservation_bound` 是预检、整条必要调用路径、现金/参考
成本准入和实际原子预留的共同计算来源。

| `scope` | 参数约束范围 | 预留方式 |
| --- | --- | --- |
| `answer-only` | 回答，思考另计 | 完整输入与全部输出的共享上下文，按最高边际价保护 |
| `answer-and-reasoning-total` | 回答与思考合计 | 输入包络加原生全部输出容量，使用保守价格 |
| `unknown` | 旧配置未声明或未核对 | 按配置共享上下文保守保护，记录未验证，不取得新发布资格 |

实际请求保持配置的原生上限；接入方或既有策略合同显式指定的更小上限仍保持原行为，
不新增缩减，也不自动扩大用户预算。修正后，原先错误准入的预算可能在首次派发前被拒绝。
“全部输出”已经包含思考及提供方计入输出用量的其他生成 token，不再重复加一次思考费。

共享上下文为 `C` 时，以 `C × max(普通输入价、缓存读取价、缓存写入价、输出价)` 保护。
已确认全部输出上限时，以“输入包络 × 最贵输入价＋原生全部输出上限 × 输出价”保护。
未来复审输入也有冻结包络；预检先覆盖全部必要调用，尚未生成的输入与全部输出共享上下文，
不将各自最大值重复相加。价格统一到每 token，币种独立。

官方动态价格采用保守最高价，订阅参考阶梯采用冻结档案覆盖的最高价；
实际结算仍按派发时价格或实际输入阶梯。预留不是已消费，现金与订阅参考金额不重复相加。

## 配置及宿主边界

模型可添加下列声明，摘要须替换为所核对资料/部署验收材料的真实 SHA-256：

```json
{
  "outputBudget": {
    "scope": "answer-only",
    "parameter": "max_tokens",
    "contextTokens": 1024000,
    "sourceSha256": "aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa"
  }
}
```

`contextTokens` 缺省为 `contextWindow`，显式值不能小于后者；额外保守包络须有来源依据。
参数语义不能由名称推断，已知语义必须有来源摘要。配置容量与审核资料由可信维护者核对，
摘要只固定来源，不能证明供应商真实实现或保证故障后端遵守合同。

直接 Chat 网关只接受当前已接通的 `max_tokens` / `max_completion_tokens`，并检查冻结
声明与实际请求参数一致。`max_output_tokens` 仍只供支持该映射的宿主使用，不扩大直接网关协议。
DSH 只接受自身实际暴露的 `host-maxTokens`，无法验证直接 HTTP 参数时在首次调用前拒绝。
已知 DSH 参数语义须核对宿主及后端映射，不能直接复制其他入口的声明。
TypeScript 只做宿主类型与映射边界检查；预算、资格及费用计算仍全部由 Python 负责。

Python 签发原有 `maxTokens` 并附带输出合同。Chat / Responses 与 DSH 原生回执中的真实
思考细分均能穿过规划包装；缺失字段保持未知，不能用占位零证明没有思考。

## 结算、取消与迁移

账本记录线缆原生值、输出语义/来源、输入包络、全部输出保护量、共享总容量和保守价格。
已知全部输出按实际费用结算，回答上限另用真实思考细分核对。总量已知、细分缺失时费用
仍能结算；无法确认回答容量时停止后续执行，不把已知费用改成零。
提供方返回已知用量超出合同，仍先结算并保留已发生费用，再停止，不抹去失败记录。

用量或必要缓存写入费用未知时保留完整预留并停止本任务所有币种账本。
取消只释放未派发部分；在途调用继续结算。停止试用、回滚和重启不释放未知用量，不自动重发。

旧配置不会自动补造已验证来源，运行时记录 `scope=unknown` 并采用更保守的上下文预留。
要采用较紧的全部输出预留，须先核对部署再显式保存配置；预留增加不代表实际费用增加。

新发布使用 `routing-release-v2`，已知语义与实际参数绑定后允许大于 8192 的原生容量，
独立质量/收益门槛不放宽。旧 `routing-release-v1` 快照、组件、资格记录和费用只读保留；
不能借旧规则取得新资格。存在旧活动试用或旧默认配置时，明确要求重新冻结，
不会自动停旧试用并改走其他路线。两个历史夹具由实际核心 0.16.34 的 wheel 生成并回归校验。

## 零调用验收

- 131072 原生回答、249000 思考、250000 全部输出、1000 纯回答：线缆值保持，
  70 CNY 示例预算派发前拒绝；充足预算先保护 460.8 CNY，再按夹具实际用量结算 112.545 CNY。
  这些是固定价格回执的算术例子，不是真实供应商消费。
- 32768 原生全部输出不再按 8192 预留；超出回答、全部输出或共享容量的已知回执结算后停止。
- 实际本机 HTTP / SSE 与 DSH Python worker 覆盖原生参数、中文、思考细分及结算。
- 六策略必要路径、未来复审、缓存最高价、订阅/现金分账、取消、未知、回滚、重启不重发、
  不支持参数拒绝和旧快照均有回归；所有上游均为固定夹具。

本轮不调用真实模型，不赋予 Task / Stage / Composite 等新的收益资格，
不修复 #219 的旧文本任务输入合同或 #144 的父子共享预算，不更新用户当前服务与配置。
