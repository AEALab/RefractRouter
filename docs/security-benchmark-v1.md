# 安全约束混合路由基准 v1

本基准对应 Issue #112，目标是在安全可行路线内比较质量、模型调用费用与端到端时间。
它不再检验“DAG 普遍提高质量”，而是检验在用户可接受质量下，节点放置与并行是否足以
补偿规划、上下文重复、合流和额外调用。

## 四条路线

| 路线 | 输入视图 | 执行方式 | 用途 | 是否进入可部署前沿 |
| --- | --- | --- | --- | --- |
| `external-reference` | 公开或独立脱敏视图 | 外部强模型整任务执行 | 质量参照 | 否 |
| `trusted-direct` | 原始合成材料 | 全本地或可信云整任务执行 | 最直接的合法基线 | 是 |
| `constrained-direct` | 原始合成材料 | 在合法候选中选择整任务模型 | 检验整任务低成本路由 | 是 |
| `constrained-fixed-dag` | 原始合成材料 | 使用同一冻结 DAG，按节点安全等级放置 | 隔离异构放置与并行价值 | 是 |

外部质量参照不会因为得分高而成为敏感任务的部署候选。质量差距以它为参照，但费用与时间
的主比较必须相对于表现最好的合法路线。

## 开发任务矩阵

首批只含 5 个原创非生产任务，各运行一次，不用于确认性结论。

| 类型 | 目的 | 对 DAG 的预期 |
| --- | --- | --- |
| `separable` | 敏感事实与公开材料可分离 | 可能产生节点放置收益 |
| `all-sensitive` | 每个节点都受限制 | 检验可信域容量与合流开销 |
| `all-public` | 无敏感限制 | 检验纯费用与并行收益 |
| `short-negative` | 极短简单任务 | 应由整任务路线占优 |
| `strong-dependency-negative` | 子任务必须顺序传递 | DAG 并行收益应很小或为负 |

敏感任务另有不同的 `referenceView`，移除身份字段与内部标识后才能交给
`external-reference`。仓库内不包含生产秘密。

## 模型与部署层

冻结协议使用角色 ID，不把尚未确定的供应商名称冒充为真实部署证据：

- `external-strong`：外部强模型质量参照；
- `external-cheap`：公开节点的廉价、低时延候选；
- `trusted-strong`：用户批准的可信云候选；
- `local-worker` 与 `local-judge`：真实本地执行和评审角色；
- `simulated-local-worker`：研究专用，不进入可部署路线或前沿。

真实开发批次前必须把角色 ID 绑定到版本、端点、价格快照、上下文和信任策略。若当时没有
真实本地模型，可以另跑 `simulated-local` 探索调度与质量，但只能报告为模拟证据，不能用来
证明隐私部署可行。

## 指标与判定

质量门槛为 80，允许相对外部参照最多下降 3 分，隐私违规必须为 0。每条路线分别记录：

- 生成费用与评审费用；主指标另算不含评审的 `AFP/USD per accepted task`；
- 墙钟、节点关键路径、串行与并行等待；
- 对外部参照的质量差距，以及相对最佳合法基线的费用和时间差；
- 失败、未知用量、阻断阶段与是否交付。

本地边际调用费用可记为 0，但硬件折旧、排队、电力与运维另列，不能据此声称总拥有成本为
0。质量代理只用于冻结前筛除明显不足的配置，不是实测结果。

## 零调用排练结果

排练证据位于 `reports/security-benchmark-v1/rehearsal-01/`：

- 5 个任务、4 条路线，共 20 次计划运行；
- 28 次生产调用与 20 次独立评审，硬上限 64 次；
- 按声明价格保守合计 0.350500 USD；实际模型调用与费用均为 0；
- 每条可部署路线在静态合同下隐私违规为 0；
- `external-reference` 全部标为 `reference_only`，`simulated-local` 未进入任何主路线。

下一步只执行开发批次。完成后先检查质量门槛、失败归因与成本拆分，再决定是否冻结独立
留出材料；不会因为开发结果不理想而扩大样本或直接进入 #113。
