# 时间与 AFP 的开发对照协议

对应 [Issue #53](https://github.com/AEALab/RefractRouter/issues/53)。
从已合并的 PR #58 接续运行器、三态质量、真实账本与配对统计，先完成开发诊断。
本协议不替代 #52 尚未发生的独立真人材料审核、开发盲审和用途确认。

## 本批预定范围

使用 `data/quality-study-v2` 的六个开发任务，各运行九条路线、重复两次，共108次任务运行。
材料仍是原有的短构造任务；每类两题，直接、并行、先后依赖各两题。
新版本只完善六个开发任务的公开字段合同，十二个候选留出内容保持原样且不执行。
这是开发结果反馈后的新协议，不冒充未经调试的新留出验证。

路线为三种固定模型直接回答、整任务选模、共享图单模型串行/并行、共享图异构串行/并行，
以及在线自动图异构执行。三种模型都作为直接对照，候选别名不代表已证明的能力排序。
不新增随机混合和执行前直接/DAG策略的调用；它们在 #52 已完成链路验证，
本轮聚焦隔离并行与选模作用。困难后再拆继续留在 #55。

这批主要落实 [#51](https://github.com/AEALab/RefractRouter/wiki/12-GAP1文献复核与公平对照)
的机制诊断H2，并非完成全部B0–B5或验证输入感知策略H1。随机混合和条件策略的收益比较
仍是后续正式设计的待办。DAAO、FlowCompile、LLMCompiler尚无本任务域的忠实适配；
六个开发题不足以假定学习/画像已完成，本批不删减对手能力后声称胜出，也不报告论文优越性。

相同任务的四条共享路线使用同图；串行/并行使用相同模型分配。
图由小模型按材料生成，每任务仅生成一次；首次需要共享图时才生成，随后复用。
每任务首次共享路线记录实际计划创建加执行的冷计划时间，其余记录复用执行时间。
不同任务首次落在哪条共享路线由冻结顺序决定，不能将六次冷计划观察当成全部路线
公平配对的冷启动优势；应用进程启动及客户端绘制时间未纳入该指标。

每轮按任务交错，任务内路线顺序和随机种子复用核心冻结规则52052。
总调用最多654次；每阶段容量、AFP保守包络、deadline、模型、依赖锁文件及实现哈希
必须在付费前生成，运行时不可修改。上限按最大输入输出容量计算，不是费用预测。
全部尝试、失败、评审和准备费用保留。底层零重试、零规划修复、零节点回退和零再拆。
用量未知、认证或账本/证据异常停止整批；已结算的输出失败继续其他预定任务，禁止抽样到成功。

## 公开编码与事实核验

v1 的直接字符串比较曾将单条边的列表层级和带状态词的节点名统一记成字段失败。
本版公开声明字段类型和有限标签，分开输出 `encoding_status`、`field_status` 与最终质量。
数值和布尔不互换；单位字符串不自动转换为数字，未知标签不做模糊匹配。

`rules-02.required_edge` 接受 `[前置步骤,后续步骤]` 或只有这一条边的外层列表。
公开的端点别名仅有“签名通过→签名”和“打包结束→打包”，只用于辨识该边的端点；
它们不表示步骤已经完成，不适用于允许执行步骤、阻断步骤或正文。
反转方向仍是事实失败，未知状态/条件词不支持即记编码不合约、事实未核验。
程序保留原文、规范化操作与规范化结果；真人意见继续绑定原始输出哈希。

别名及格式容许在本批调用前统一冻结，不对某个模型单独宽免。
既有v1材料和报告继续使用原判定；模型评审不构成独立真值或真人签署。
结构化事实通过仍不证明正文中的条件、限制、引用或建议正确，最终保留待真人判定。

## 时间与费用审计

每个调用记录开始派发和完成的单调时间、阶段、真实用量与冻结费率；账本重新复算。
每个任务记录进入、首条进度发出、计划就绪、正文就绪及在线结束事件。
`first_progress_emitted_ms` 是CLI服务端完成发送的时刻，不能解释为用户界面已经看到。

在线时间连续拆成规划/选择、节点执行与汇总、解析及交付评审三段，三段之和必须等于
实际在线总时长。每个在线调用必须落在该时段内，研究judge不得提前开始。
节点资源耗时、运行区间并集、实际重叠、排队及最大并发单列；资源耗时不冒充用户等待。

在线AFP包括规划、选路、节点、汇总和交付judge；共享图准备与研究judge单列。
用量未知不填写零；丢失任务和未知指标阻止完整配对比较。
研发历史费用另列，不能只汇总最后一次有效结果。

准备成本按1、3、10、100次复用分配，并逐任务计算相对强模型直接回答的回本次数。
只有复用执行本身比直接执行便宜或快，才存在对应维度的回本分母；否则返回无回本点。
时间摊销只是分配情景，不能代替实测冷计划时间，也不代表质量已经相同。

## 分析与后续决定

预定六项开发比较：单模型并行、异构并行、串行选模、并行选模，
以及自动全链路分别对强模型直接回答、对整任务选模。
先在任务内汇总全部重复，再按来源族配对重采样10000次，种子53053。
区间只作探索描述，不用多次挑选后最有利的一项作确认性检验。
类别和结构分层沿用核心统计，全部失败留在预定分母。

输出每次运行和调用CSV、费用阶段拆账、均值/中位数、配对区间与两张可导出的图。
未获真人质量确认的点一律空心标注，不画合格前沿；即使模型评审和字段检查都通过也如此。
另在预定AFP/时间约束点筛查观测资源均值和逐次违反数，明确是事后筛查，
不称作系统已在这些预算下执行或保证约束。

开发结果只用于决定优先审查哪些输出、哪些任务值得新材料验证，以及是否继续扩大策略。
即使发现资源更低，也必须等待真人确认质量后，才能声称可接受成果下的权衡。
若简单构造题上没有足够收益信号，先收窄研究或更换有实际需求依据的材料，
不通过强制拆分、取消线上评审、筛掉失败或引入复杂策略制造正结果。

## 复现入口

```bash
uv sync --frozen --extra dev --extra deepagents --extra analysis
uv run python experiments/run_bound_quality_study.py \
  --study-dir data/quality-study-v2 \
  --task-ids analysis-01 analysis-02 rules-01 rules-02 decision-01 decision-02 \
  --arms direct-cheap direct-mid direct-strong task-selector shared-single-1 shared-single-2 \
    shared-heterogeneous-1 shared-heterogeneous-2 auto-heterogeneous \
  --repeats 2 --output-dir /tmp/pareto-preflight-new
uv run python experiments/run_bound_quality_study.py --live --progress \
  --study-dir data/quality-study-v2 --frozen /tmp/pareto-preflight-new/frozen.json \
  --output-dir /tmp/pareto-live-new
uv run python experiments/analyze_pareto_development.py \
  --study-dir data/quality-study-v2 --run-dir /tmp/pareto-live-new \
  --output-dir /tmp/pareto-analysis-new
uv run --extra analysis python experiments/render_pareto_development.py \
  --analysis /tmp/pareto-analysis-new/analysis.json --output-dir /tmp/pareto-figures-new
```

所有输出均使用新路径。`--rehearse` 仅验证流程，模拟账本不得计作实际调用或AFP。
生成真实输出匿名包时，私有路线映射只交协调者，初审人员不能接触该映射。
