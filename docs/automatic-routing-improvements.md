# 自动路由改善与有限验收

## 优先顺序

2026-10-06 用户要求集中改善自动路由，当前客户端范围保持 DSH 与 Codex。
标准模型接口不进入 DAG；DAG 仍为独立自动路由入口。用户无需先手动测试才能推进开发。

1. 修复可执行性：选模前排除预算不足的路线，保留质量与安全约束。
2. 审计固定开销：复用已完成调用记录，分别看结构判别、规划、执行、工具续接、评审；
   只有证据支持时再精简步骤，不自动跳过最终验收或降低品质门槛。
3. 检查拆分价值：独立子任务只是可拆分证据，不是必然更便宜的证明；保留直接执行候选。
4. 改善解释：每次说明为什么拆／不拆、候选为什么被排除，以及参考成本与现金成本。

不新增策略，不启动大规模收益实验，不改用户单任务预算。确有必要的付费验证另按现有
授权范围与冻结调用包络执行；本次预算修复用无网络模型验证即可。

## 第一项：现金预算提前准入

此前金额配置已在真实调用前强制检查现金余额，但节点分配只以参考预算作为硬约束。
选模可能报告 selected，随后第一步因现金不足失败；DAG 与 direct 的比较也可能把
无法承担的候选当成可执行路线。

新增 `cash_max` 为 Python 节点搜索的可选独立约束：

- 从任务账本获取已结算及在途预留后的生产现金余额。
- 同时作用于生成 DAG 与直接执行候选；不足的分配计入 cash 拒绝数量。
- 订阅节点的新增按量现金为零，参考成本仍受约束，质量不合格也不能选用。
- 配置中的 0 继续表示不限额；运行中的已耗尽余额 0 表示不能新增现金支出。
  搜索接口用 None 表示无现金上限，避免二者混淆。
- 保留实际派发前的原子预留；预测准入不承诺任意长工具续接、回退或输入增长均有额度。
- 评价现金独立核算；本次节点准入只筛选生产现金，不挪用评价额度。
- 旧配置不传入新约束，历史分配与记录不变。

轨迹增加「现金费用不满足的分配数、最低预计现金、剩余现金」，与参考费用并列展示。
该变化不会因预算不足自动降低模型质量或重发请求。

## 验证

新增确定性测试覆盖：耗尽现金后合格订阅可用、不降低品质、不绕过参考额度、非法额度、
在途预留、取消释放、配置 0 与运行余额 0 的区别，以及现金不足时自动运行零派发。
相关测试与 TypeScript 类型检查通过。完整回归与发布状态以当前验收记录为准。

## 已有执行记录的固定开销核对

`reports/automatic-tool-evidence-20261005/live-summary.json` 的回显工具任务包含一次规划、
两次执行、一次评审：原始记录中规划 4.185 AFP、评审 4.26645 AFP，占该历史 AFP
总额约 35.83%；四次调用合计输入 52029 tokens，输出仅 395 tokens。另有结构 Jev
0.0001674467298 CNY，不能与 AFP 相加，也不追溯换算旧记录。

这说明该样本的规划和长输入值得关注，但不能据此直接删去工具评审：该评审负责核对
宿主确实运行命令，而不是模型凭空给出答案。当前 v4 结构合同已支持 SINGLE，使单项
工具工作可以直接执行；上述旧样本不能当成当前版本仍会付规划费的证明。

因此本轮不增加关键词特判、不绕过 Judge、不修改现有 reviewPolicy。下一项先核对
当前版本的 SINGLE／COUPLED／SEPARABLE 与实际是否调用 planner 的一致性；只有出现
可复现的不必要规划才改门控，不以旧版本样本反复调新规则。
