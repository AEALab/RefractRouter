# 节点名称、任务类型与 DAG 图

DSH 的「任务 DAG」页签展示当前已加载会话中最近一次自动拆分，包含节点、依赖箭头、
模型、类型、难度、风险和执行状态。节点规划完成后出现，执行期间更新。
图中的箭头从上游指向下游，表示下游消费上游结果；没有依赖的同层节点可以并行。
共同读取原始任务不构成依赖。宽图可以横向滚动，完整文字见图下方的节点说明。

## 自由命名的节点

`node_id` 是规划器根据具体职责生成的名称，没有固定枚举清单，也不直接决定模型。
下面只是常见名称的解释，正式类型须看实际计划中的 `node_type`，不能按名称猜测。

| 名称示例 | 通常表达的职责 | 可能的正式类型，非固定映射 |
| --- | --- | --- |
| `forecast` | 预测未来情况，说明假设和不确定性 | `generation`、`synthesis` |
| `drivers` | 分析影响结果的驱动因素 | `extraction`、`synthesis` |
| `trend` | 识别变化趋势、阶段和拐点 | `extraction`、`synthesis` |
| `answer` | 汇总并交付用户要求的最终回答 | `generation`、`synthesis` |
| `evidence` | 整理已有材料中的证据 | `extraction` |
| `check` | 检查事实、推理或覆盖范围 | `verification` |

例如 `forecast` 不是固定的「预测类模型」，`answer` 也不保证使用最贵模型。
最终节点由计划的 `final_node_id` 指定，不要求必须叫 `answer`。

## 自动 DAG 的正式类型

当前应用运行时在 `src/refractrouter/task_plan.py` 中只接受以下五种类型。

| `node_type` | 中文 | 职责与例子 |
| --- | --- | --- |
| `planning` | 规划 | 明确问题、安排分析路径，例如制定比较维度。与运行时最初规划整个 DAG 的调用须区分。 |
| `extraction` | 提取 | 从用户已有材料提取事实、数据、限制和证据；本类型不会自动增加联网搜索能力。 |
| `synthesis` | 综合 | 合并多份输入、比较方案、解释趋势与驱动因素，处理冲突和遗漏。 |
| `generation` | 生成 | 撰写分析、预测、建议或最终正文。预测仍须明确材料、假设和不确定性。 |
| `verification` | 验证 | 检查事实、逻辑、格式与要求覆盖；图中验证节点不同于运行时最后的独立评审调用。 |

历史实验可能存在其他专用节点类别，不代表当前自动文本 DAG 接受这些类别。
简单任务可以只有一个节点，不强制拆分，也不强制不同节点使用不同模型。

## 其他任务特性

| 字段 | 取值或含义 | 用途 |
| --- | --- | --- |
| `difficulty` | `low` / `medium` / `high`：低／中／高难度 | 规划器对当前职责难度的估计，可用于匹配模型画像。 |
| `risk` | `low` / `medium` / `high`：低／中／高风险 | 规划器对出错风险的估计，不是经过校准的错误概率。 |
| `input_budget_tokens` | 节点输入容量预算 | 应容纳任务、指令与父节点交接内容。 |
| `expected_output_tokens` | 预期输出规模 | 描述节点输出需求。 |
| `parents` / `inputs` | 上游节点及消费字段 | 确定依赖边、等待顺序和交接内容。 |
| `checks` / `covers` | 验收要求及原任务覆盖项 | 约束节点产物及最终交付。 |

模型分配综合正式类型、能力要求、上下文和输出容量、预算、候选模型配置，以及质量、
成本与时延预测。用户配置的预测不是实测质量或 SLA。

## 展示边界

Python 核心提供实际状态与分类，宿主插件负责图形展示。客户端从同一份插件进度展示
读取完整条目与增量，不从任务正文重新推断依赖、分类或模型，不发起模型调用。
展示格式通过生产端与客户端联合契约测试固定；不完整的流式条目等待补齐后再显示，
未知依赖和环形结构不绘制。旧记录缺少正式类型时显示「未提供」。
取消后保留最后收到的状态，不把尚未确认的运行节点标为完成。

该页签使用 DSH 0.1.1-rc.2 的客户端扩展接口，不修改 DSH 宿主代码。
它只显示当前加载窗口内的记录；更早会话需先在对话页加载对应历史。
