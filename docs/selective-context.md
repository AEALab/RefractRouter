# 材料与字段交接优化

本页对应 [Issue #72](https://github.com/AEALab/RefractRouter/issues/72) 第二阶段，
建立在[必要拆分策略](minimal-dag-optimization.md)之上。目标是减少中间节点的重复输入，
最终成果质量仍由原有评审与独立人工准入判断。

## 显式启用

通过 Python 应用入口或 `refractagent --request-file` 提交请求，暂不增加 DSH 设置项：

```json
{
  "task": "按全部规则分别核对费用与实施风险，保留例外后给出完整建议。",
  "template": "auto",
  "plannerPolicy": "minimal-v1",
  "contextPolicy": "selective-v1",
  "materials": [
    {"id": "rules", "text": "所有方案均须保留免责条款。"},
    {"id": "cost", "scope": "local", "text": "费用上限为 100。", "requires": ["exception"]},
    {"id": "risk", "scope": "local", "text": "实施风险为中等。"},
    {"id": "exception", "scope": "local", "text": "临时方案须额外核对条件。"}
  ],
  "acceptanceCriteria": ["覆盖全部规则、费用、风险和例外"]
}
```

材料 `id` 是稳定的来源标识，不是临时节点编号。每份材料包含原文 `text`，不进行模型压缩。
`scope` 默认 `global`，只有调用方明确标为 `local` 的材料才能被中间节点省略。
`requires` 声明该材料必须一并读取的其他材料，例如例外或术语定义；Python 计算传递闭包。
循环引用会收敛为材料集合，不会无限递归。未知 ID、重复 ID、错误结构在付费调用前拒绝。
ID 使用小写字母开头的小写字母、数字及下划线，最长 64 字符；
来源 ID `task` 保留给原始任务说明及对话。

任务说明、对话、验收条件、全局材料及其依赖始终保留。没有结构化材料时，完整任务原文
继续传递，不能把模型猜出的段落边界当作可靠材料分区。调用方须审查全局/局部标记和
`requires` 的语义完整性；代码无法发现被误标为局部且未声明依赖的全局例外。

`contextPolicy` 默认 `full`，原有请求不受影响。优化声明保存在运行记录中，`plan.json` 单独不包含来源选择；当前实验开关只支持自动规划，
不支持仅提交已保存计划来复用材料选择。直接回答对照也可接收同一份 `materials`，
全文送入执行及评审，且无需规划调用。零调用预检仍展示模板，不证明实际规划选择。

## 规划器与核心各自负责什么

同一次必要拆分规划额外输出 `context`，按原始节点 ID 声明三项内容：

- `sources`：所需局部材料的来源 ID。全局材料和依赖由 Python 补齐。
- `fields`：中间节点需要交付的字段，选择 `facts`、`evidence`、`conclusion`、`uncertainty`。
  至少包含证据、不确定性，以及事实或结论之一；最终节点为 `text`。
- `uses`：按父节点选择需要传递的字段，必须保留 `evidence` 与 `uncertainty`。

Python 检查来源与字段引用，编译既有 v2 节点契约，然后提取原文。不会增加分类器、
压缩模型或规划评审调用。若第一阶段声明节点合并，材料与职责字段取并集，内部交接消失，
外部父节点引用映射到合并后的节点。

中间输出采用 JSON 契约，字段值仍为非空字符串。内容围绕当前部分的事实、依据、结论及
限制，不要求重复撰写完整报告。下游只得到其声明的字段；最终节点取得所有直接父节点的
输出字段及完整原始材料，原有最终交付评审同样取得全文。未给最终答案增加字数上限。

## 来源摘录核对

`evidence` 中的原文摘录使用以下形式：

```text
[source:cost]「费用上限为 100。」
```

核心检查来源是否属于当前输入或上游来源集合，并检查摘录是否逐字存在于原文。
无结构化材料时可引用 `[source:task]「任务或对话中的原文」`。
引用格式错误、来源未知、原文不存在或字段缺失，会令该节点失败并停止下游；
已发生的模型调用仍记账，在途兄弟节点按原有规则结算，不静默截断或补造证据。

逐字摘录检查只证明引用与已提供来源一致，不能证明它足以支持结论，也不能证明材料选择
没有遗漏。每个中间节点的 `evidence_validation.semantic_support_verified` 均为 `false`；
整体的 `semantic_source_coverage_verified` 也保持 `false`。正式质量门槛仍依赖 #52。

## 容量、记录与适用范围

容量预估、整图准入和实际派发使用同一份按节点生成的任务材料。
`result.json`、`summary.json` 的 `context_selection` 记录策略版本、来源 ID、输出及交接字段、
裁剪前后的任务字节数与实际材料哈希。执行节点另记 `handoff_bytes`，原调用账本继续保存
实际输入、输出和 cached token、耗时、费用与完整请求证据。

这些字节数只衡量任务材料，不包括全部系统指令、契约及上游结果，更不是 token 或 AFP。
字段结构、来源摘录和规划声明也有额外开销，收益须结合全部调用进行真实对照。

最终节点仍须容纳全部原文；本策略不能绕过最终模型的输入容量。

第一版限于已提供材料的文本任务，与原生工具或 `maxDynamicSplits > 0` 组合时明确拒绝。
工具动态证据的来源注册、动态子图材料继承尚未实现；原有工具与动态模式在关闭本开关时
继续使用既有路径。取消、预算、在途结算和模型容量限制继续有效。

## 验证与下一步

新增确定性模拟验证包括：全局及传递依赖保留、分支材料隔离、最终节点/评审全文、
中间字段过滤、合并后的材料并集、原文引用错误、未知引用、全文回退、并行调度以及
直接回答对照的相同材料输入。模拟模型不会发起网络或付费调用。

模拟样例中的完整任务材料为 3,975 字节，费用分支为 2,243 字节，风险分支为 2,176 字节；
最终节点保持 3,975 字节。样例包含重复测试材料，只验证数据流，不能作独立研究样本，
也不能把这些数字当作 token、AFP 或真实响应速度的改善。

后续按 #72 第三阶段验证稳定前缀与缓存，随后冻结开发集对照调用包络，统计规划、
节点执行、交付评审及全部失败费用。正式独立留出实验继续等待真人材料与质量准入。
