# Advisor 本地 Judge 实验接入

日期：2026-09-28。根据用户决定，Advisor 设置同时提供 DSH 语言模型和本地
Laya-MLX 两种审核器。本地选项明确标记为实验功能，可以配置、加载并进行后续验收；
目前不宣称已达到日常使用质量。

## 接口与执行边界

「Advisor 审核 LLM」继续引用 DSH 模型目录。本地 Laya-MLX 使用独立的
`advisor-local-review-v1` 结构化 Choice 问题，不冒充 DSH 语言模型，也不复用 Task
选模或 Escalation 接管判别。审核对象是已接受历史、工具证据和尚未交付的候选。

本地结果分为 `APPROVE`、遗漏要求、证据不足或冲突、`UNRESOLVED`。后两种缺陷
分别映射为 `REDO` 和固定类别的返工反馈；它不是模型生成的自由文字理由，也不能提供
精确证据位置。低于配置确定性门槛或完整输入超出实际 tokenizer 容量时，停止本轮并
丢弃候选，不将其视为批准。进程故障同样不自动切换云端。

本地进程必须提前下载、核对 revision、加载和预热；任务执行不隐式下载。候选回复
在审核完成前保持缓冲，未接受的工具调用不交给 DSH 执行。推论无 API 费用，实际
模型、原始分类、确定性、耗时与调用次数单独记录。原有 Advisor LLM 配置按旧行为读取。

## 验证状态与下一步

[Escalation 冻结题集](../reports/escalation-acceptance-20260927/README.md)中，当前
多语言 Laya checkpoint 的 24 条判别仅匹配 5 条，六条合格回复均未放行。它不是
Advisor 专项验收，不能推断 Advisor 准确率。此证据意味着目前不能把该 checkpoint
视为可靠的日常审核器；用户仍可在明确启用实验模式后测量其表现。

接下来应冻结独立的中英混合 Advisor 题集，覆盖合格回复、明确缺陷、合理工具探索、
信息不足及返工反馈的可执行性。必须报告原始分类、阈值前后结果、误放行、误拒绝、
容量失败、冷暖启动及等待时间，再决定是否调整模板、checkpoint 或产品默认值。
DSH 原生工具续接中的批准、返工和停止也需要分别真实验收；无网络模拟只证明接线行为。
