# Advisor 本地 Judge 接入决定

日期：2026-09-28。结论：保留 Advisor 当前的 DSH 语言模型审核路线；本地 Laya-MLX 暂不列入
Advisor 可选审核器。此决定不改变 Task、Escalation 或实验性 Stage 的本地 Judge 配置。

## 当前边界

设置卡片中的「Advisor 审核 LLM」引用 DSH 模型目录。Advisor 在执行模型准备交付时调用它，
解析 `APPROVE`、`REDO` 或 `UNRESOLVED`；`REDO` 还需要能用于续作的具体反馈。审核调用单独
计费。正常工具探索沿用宿主流程，只有触发停滞审核的工具候选会在审核前保持缓冲。

本地 Laya-MLX 不属于 DSH 语言模型目录。它通过独立常驻进程回答结构化问题；Task 和
Escalation 已有不同的问题模板，Stage 有独立的实验模板。这些模板不能直接代替 Advisor 的
交付审核和返工反馈。把本地权重名称加进 DSH 模型列表，既不能提供相同的请求接口，也不能
使 Advisor 获得可用的审核结果。

[Escalation 冻结题集](../reports/escalation-acceptance-20260927/README.md)中，当前多语言
Laya checkpoint 的 24 条判别仅匹配 5 条，六条合格回复均未放行。该题集不是 Advisor 的
专项验收，因此不能推断它在 Advisor 上的准确率；它足以说明目前没有证据支持将这个权重
作为日常默认审核器。2026-09-28 的 DSH 实际界面核对证实：原「审核模型」只列 DSH
目录模型；Stage 历史轨迹原先会铺开长证据 ID，累计金额带有浮点尾数。构建后在同一
profile 刷新检查：Advisor 专属说明、次数控件和新角色名称出现；Stage 轨迹显示已完成、
金额正常格式及可展开的证据 ID。Advisor 只在未保存草稿中预览，刷新后原会话仍选 Stage，
用户保存的模型、策略、凭证和额度没有修改。

## 本地 Advisor 的实施门槛

后续要开放本地选项，应作为单独的版本化 Advisor 合同交付：

1. 冻结任务要求、已接受历史、工具证据、尚未交付的候选及结束状态的输入投影；用实际
   tokenizer 检查完整容量，不静默截断，也不让候选内容覆盖审核规则。
2. 定义 `APPROVE / REDO / UNRESOLVED` 的结构化判定。`REDO` 必须有能对应任务要求或
   可信证据的可执行反馈；若本地模型无法给出可靠反馈，不能生成空泛返工指令或冒充批准。
3. 保持候选缓冲、工具调用不提前执行、审核次数与返工次数限制、取消及迟到回执隔离。
   本地推论没有 API 费用，但必须记录实际推论、排队和等待时间。
4. 冻结独立的中英混合审核题集，覆盖合格回复、明确缺陷、合理工具探索和信息不足。
   合格回复至少 5/6 放行，明确缺陷不得放行；未达标只保留实验状态，不给日常选项。
5. 在 DSH 原生工具续接中验证批准、返工和停止各一条完整路径，并核对回复来源、轨迹、
   预算及旧 Advisor 配置兼容。通过后才在 Advisor 设置中显示本地 Judge 类型。

这些门槛针对 Advisor 的实际交付行为，与 Stage 的下一步选模或 Escalation 的强模型接管
各自独立。后续可更换或专门适配本地 checkpoint，但不能通过单纯降低门槛把当前失败的
验收样本改写为通过。
