# 三类任务的质量协议与材料审查

对应 [Issue #52](https://github.com/AEALab/RefractRouter/issues/52)，承接
[#51 的文献复核](https://github.com/AEALab/RefractRouter/wiki/12-GAP1文献复核与公平对照)。
目标是在最终成果达到用户可接受质量后比较等待时间与 AFP；不是继续使用统一 85 分，
也不把“同质量”当成未经统计验证的事实。

## 当前状态

当前已增加实际运行器与统计冻结入口，详见
[运行绑定与研究边界](quality-study-freeze.md)。下文保留材料、质量和历史校准的说明；
文末标注的草案仅用于解释初版设计，不再作为新入口的执行协议。
真人审查尚未完成，#52 仍保持开放。
已准备 18 个本项目原创的虚构任务：6 个开发任务和 12 个候选留出任务，
每类任务各 6 个，包含直接处理、可并行、必须先后处理各 2 个。
这些是短小的流程校准材料，不是现实业务的采样；任务形态是待审查标签，不强制 planner 生成对应图。
是否足够困难、有代表性、来源/模板结构是否真正独立，需要独立审查者确认。

全部材料的构造者是 Codex，参考事实和语义规则也由构造者拟定。
独立材料审查文件目前为空，没有任何真人签署。
哈希和不同族名只能发现机械错误，不能证明来源或语义独立。
不把这批材料包装成真实来源数据，也不声称拥有 12 个已经通过独立审核的新留出任务。

构造材料的来源、说明与使用范围在每个任务的 `provenance` 中；本批不含第三方网页摘录。
未来加入真实材料时必须冻结原始 URL/版本、取得日期、使用许可与正文快照哈希，
并在报告中将真实来源与构造材料分开统计。旧展览/舞台输出仅保留为历史回归。

## 输入与参考答案分开

| 文件 | 使用者与用途 |
|---|---|
| `data/quality-study-v1/public/tasks.json` | 公共材料、用户交付要求、字段及语义验收条件 |
| `data/quality-study-v1/review/references.json` | 独立材料审查和评分；包含参考事实，禁止进入模型执行输入 |
| `data/quality-study-v1/review/calibration-cases.json` | 仅基于六个开发任务的正负例；不能用候选留出材料调评分器 |
| `data/quality-study-v1/review/material-reviews.json` | 当前为空；记录未来真实独立审查 |
| `data/quality-study-v1/protocol.json` | 文件哈希、样本划分、质量建议、路线与容量包络 |

`execution_payload` 只投影五个公共字段，不包含参考答案、评分记录、split、
预设任务形态或模型偏好；相同 payload 用于所有路线。
公共验收要求必须对模型可见，参考答案和“应该用几节点”的研究标签不可见。
实际运行器只把该 payload 交给 planner/router，模型端没有文件工具或工作目录读取权限；
私有参考只参与离线审核与运行后评分。实际消息归档并有发送路径回归检查。

所有路线都输出正文及 `findings`（结论字段、值、来源 ID），用于明确可核对事实。
这是统一的实验交付合同，不要求真实用户写 JSON，也没有 250 字限制。
新运行器最终答案容量统一为 8192 output tokens；中间节点 2048，规划器 1200。
是否适配真实任务长度仍需开发校准；不通过截断某条路线的答案制造优势。

## 三态质量判定

每个任务的结构化关键事实、来源定位、顺序和全局计算可以由规则核对：
数值与布尔值不混用，集合与有向顺序分开，缺项和错误引用不能被平均分冲掉。
未支持的检查返回未验证。确定性通过只证明已实现检查的字段相符，
**不能证明自由正文正确，不能证明来源真的支持正文里的每一句主张。**

最终状态：

- `fail`：任一已支持的关键检查失败；不能被两个高分模型或真人勾选覆盖。
- `pending`：未支持检查、缺独立语义意见、意见冲突未裁决或材料不足。
- `pass`：关键检查通过，且规定的两位独立真人完成语义审查并一致通过，
  或意见冲突经第三位独立真人裁决通过。

真人意见绑定任务哈希、输出哈希和完整语义验收表，并记录身份与外部证据。
构造者自审、同一人重复提交、模型意见或缺证据的记录不构成独立双审。
结构化字段错误如需申诉，先修正版本化任务/评分规则并重评所有受影响路线，
不能临时给某一路线豁免。

当前函数仅核查记录格式和绑定关系，不认证人的身份；`reviewer_identity_verified=false`。
测试里的 `fixture://` 是测试数据，不是已发生的人类评审。
真人核验须由维护者依据真实参与与提交记录完成。

## 评审校准和盲审

修订后有 19 个开发样例：12 个正例/等价表达、5 个可由确定性检查发现的负例、
2 个字段正确但正文存在问题的负例（反写依赖、漏抽样限制）。
后两项在没有真人记录时仍为待判定，体现最终质量判定的证据边界。
辅助模型校准与材料交叉检查使用下述独立入口，原始结果保存在
`reports/quality-study-v1/model-calibration-01/`；真人分歧仍未知。
与作者标签一致或不一致，只是开发诊断，不能直接解释为相对独立真值的准确率。
同一答案的等价数值表达也不是新的独立样本。

首轮拟对所有最终输出实行两位真人独立盲审。开发校准样例先随机排列，
隐藏路线、模型和正负例标签，完成之后再由协调者解盲比较漏判与误杀。
正文语义不一致、错依赖、漏规则、错引用、局部正确但整体不符合的情况都必须覆盖。
缺材料标为待判定；不同意见交第三位真人，禁止由作者或另一个模型代签。

`blind-calibration-packet.json` 给审查者，`private-blind-mapping.json` 仅给协调者。
程序只移除元数据，不擅改最终正文；若输出正文自报模型/路线，协调者应记录盲法破坏，
按冻结规则重新编码或使用未参与初审的审查者，不能直接声称完全盲审。
`material-review-packet.json` 用于材料本身的独立审核，不是已完成的审查记录。

## 辅助模型的真实校准

校准分两步，必须先冻结精确请求，再使用新的输出目录调用：

```bash
uv run python experiments/run_quality_calibration.py \
  --output-dir reports/quality-study-v1/model-calibration-new-preflight
uv run python experiments/run_quality_calibration.py --live \
  --frozen-plan reports/quality-study-v1/model-calibration-new-preflight/frozen-plan.json \
  --output-dir reports/quality-study-v1/model-calibration-new
```

首批固定 36 个独立请求：原版 18 个开发正负例，以及 18 份候选材料的 AI 检查。
当前默认全量预检为 19 个开发样例加 18 份材料，共 37 次；这不是已安排的追加批次。
本轮修订仅追加 11 次定向复查，范围见 `model-calibration-02-preflight/frozen-plan.json`。
可用 `--calibration-cases` 和 `--material-tasks` 冻结子集；显式提供选项但不列值会跳过该类。
live 只接受冻结文件中的子集，不接受运行时扩大样本或重试。
模型、费率、消息、顺序、代码哈希和容量一起冻结；任意变化都必须重新预检。
校准只发送公共任务与候选输出，**不发送作者标签、正负例 ID、参考答案或确定性检查结果**。
材料检查可以查看参考事实及对应来源，但不生成或评价任何路线的留出答案。
候选留出任务仍是待审材料，不能拿这些审查意见调路由策略。

模型逐项检查正文、结构化结论、证据及原任务的语义要求；关键项失败不能被总体通过覆盖。
漏评、重复项、总体与分项矛盾、格式不合法或截断均记为无效输出，保留待判定。
模型意见的 `origin=model` 不会进入真人双审记录，也不会把最终任务状态改成 `pass`。

调用复用核心预算账本：串行、零重试，每次最多 2048 output tokens、45 秒 timeout。
逐请求按实际消息的保守输入容量预留，首批 AFP 上界为 192.521。
全部消耗属于离线评审成本，不是用户任务在线 AFP 或端到端时间收益。
1620 秒是 36 次 timeout 之和，不是经过强制中断验证的批次墙钟 SLA。
原始响应、请求、用量和账本逐次写入；未知用量保留预留并停批，总实际 AFP 为未知而非零。
已结算的无效输出保留费用并继续其他独立样例；基础设施或证据写入错误停止整批。

作者正例也可能漏掉语义要求。出现分歧时，应核对原材料和验收条款，保留原始标签、
评审意见及变更理由；不能默默重标原批次，或通过降低验收要求消除误杀。
修订仅用于新的开发版本，不能宣称完成了独立留出验证。
结果、误报核对与具体材料修订见
[真实校准分析](../reports/quality-study-v1/model-calibration-analysis.md)。

## 运行与统计协议的版本

初版 `preflight_quality_study.py` 与 `data/quality-study-v1/protocol.json` 仍保留其草案含义，
用于追溯早期预检与辅助校准。它们没有 `--live`，也不代表当前路线配置。
此前“#53 尚需绑定”的工作已在 #52 后续实现中接入 Python 核心。

新执行入口为 `experiments/run_bound_quality_study.py`，统计入口为
`experiments/analyze_bound_quality_study.py`，机器证据汇总入口为
`experiments/freeze_quality_protocol.py`。实际路线、共享图对照、顺序、请求容量、
真实时间、AFP 分类、质量门槛、非劣方法、探索范围与真人导入方式统一见
[运行绑定与研究边界](quality-study-freeze.md)。

## 尚需真人完成的部分

1. 独立审核材料、参考事实、语义要求、来源/模板隔离、任务难度和用途代表性。
2. 两位真人完成开发正负例盲审，记录漏判、误杀和分歧，必要时由第三人裁决。
3. 确认研究用途与已定义的质量、非劣、样本量和失败标准是否适用。

材料不足时须先补充再冻结，不能用 AI 意见代签。正式实验产生的最终答案，
再按双审协议核验。历史 #40 的 35 份真人计划复核独立保留，不替代本批审查。
