# 三类任务的质量协议与材料审查

对应 [Issue #52](https://github.com/AEALab/RefractRouter/issues/52)，承接
[#51 的文献复核](https://github.com/AEALab/RefractRouter/wiki/12-GAP1文献复核与公平对照)。
目标是在最终成果达到用户可接受质量后比较等待时间与 AFP；不是继续使用统一 85 分，
也不把“同质量”当成未经统计验证的事实。

## 当前状态

首版是 **可运行的零调用协议草案**，尚未达到正式冻结或关闭 #52 的条件。
已准备 18 个本项目原创的虚构任务：6 个开发任务和 12 个候选留出任务，
每类任务各 6 个，包含直接处理、可并行、必须先后处理各 2 个。
这些是短小的流程校准材料，不是现实业务的采样；任务形态是待审查标签，不强制 planner 生成对应图。
是否足够困难、有代表性、来源/模板结构是否真正独立，需要独立审查者确认。

全部材料的构造者是 Codex，参考事实和语义规则也由构造者拟定。
独立材料审查文件目前为空，没有任何真人签署。
哈希和不同族名只能发现机械错误，不能证明来源或语义独立。
不把这批材料包装成真实来源数据，也不声称拥有 12 个已经通过独立审核的新留出任务。

构造材料的来源、说明与使用范围在每个任务的 `provenance` 中；本批不含第三方网页摘录。
未来加入真实材料时必须冻结原始 URL/版本、取得日期、使用许可与正文快照哈希，
并在报告中将真实来源与构造材料分开统计。旧展览/舞台输出仅保留为历史回归。

## 输入与参考答案分开

| 文件 | 使用者与用途 |
|---|---|
| `data/quality-study-v1/public/tasks.json` | 公共材料、用户交付要求、字段及语义验收条件 |
| `data/quality-study-v1/review/references.json` | 独立材料审查和评分；包含参考事实，禁止进入模型执行输入 |
| `data/quality-study-v1/review/calibration-cases.json` | 仅基于六个开发任务的正负例；不能用候选留出材料调评分器 |
| `data/quality-study-v1/review/material-reviews.json` | 当前为空；记录未来真实独立审查 |
| `data/quality-study-v1/protocol.json` | 文件哈希、样本划分、质量建议、路线与容量包络 |

`execution_payload` 只投影五个公共字段，不包含参考答案、评分记录、split、
预设任务形态或模型偏好；相同 payload 用于所有路线。
公共验收要求必须对模型可见，参考答案和“应该用几节点”的研究标签不可见。
这不是文件权限隔离：#53 仍需使 runner 只能把该 payload 交给 planner/router，
并核对所有实际消息。不得让执行模型通过工作目录读取 `review/`。

所有路线都输出正文及 `findings`（结论字段、值、来源 ID），用于明确可核对事实。
这是统一的实验交付合同，不要求真实用户写 JSON，也没有 250 字限制。
最终答案拟议容量统一为 8192 output tokens；中间节点 4096，规划器 1200。
是否适配真实任务长度仍需开发校准；不通过截断某条路线的答案制造优势。

## 三态质量判定

每个任务的结构化关键事实、来源定位、顺序和全局计算可以由规则核对：
数值与布尔值不混用，集合与有向顺序分开，缺项和错误引用不能被平均分冲掉。
未支持的检查返回未验证。确定性通过只证明已实现检查的字段相符，
**不能证明自由正文正确，不能证明来源真的支持正文里的每一句主张。**

最终状态：

- `fail`：任一已支持的关键检查失败；不能被两个高分模型或真人勾选覆盖。
- `pending`：未支持检查、缺独立语义意见、意见冲突未裁决或材料不足。
- `pass`：关键检查通过，且规定的两位独立真人完成语义审查并一致通过，
  或意见冲突经第三位独立真人裁决通过。

真人意见绑定任务哈希、输出哈希和完整语义验收表，并记录身份与外部证据。
构造者自审、同一人重复提交、模型意见或缺证据的记录不构成独立双审。
结构化字段错误如需申诉，先修正版本化任务/评分规则并重评所有受影响路线，
不能临时给某一路线豁免。

当前函数仅核查记录格式和绑定关系，不认证人的身份；`reviewer_identity_verified=false`。
测试里的 `fixture://` 是测试数据，不是已发生的人类评审。
真人核验须由维护者依据真实参与与提交记录完成。

## 评审校准和盲审

目前 18 个开发样例：12 个正例/等价表达、5 个可由确定性检查发现的负例、
1 个“字段正确但正文把依赖反写”的负例。最后一个应留为待判定，体现语义检查的边界。
目前没有运行 LLM judge 校准，没有测得真人分歧；相关指标必须保留为空或未验证，不能写为零。
这批作者样例通过，不等于语义评审具有高准确率。

首轮拟对所有最终输出实行两位真人独立盲审。18 个开发校准样例先随机排列，
隐藏路线、模型和正负例标签，完成之后再由协调者解盲比较漏判与误杀。
正文语义不一致、错依赖、漏规则、错引用、局部正确但整体不符合的情况都必须覆盖。
缺材料标为待判定；不同意见交第三位真人，禁止由作者或另一个模型代签。

`blind-calibration-packet.json` 给审查者，`private-blind-mapping.json` 仅给协调者。
程序只移除元数据，不擅改最终正文；若输出正文自报模型/路线，协调者应记录盲法破坏，
按冻结规则重新编码或使用未参与初审的审查者，不能直接声称完全盲审。
`material-review-packet.json` 用于材料本身的独立审核，不是已完成的审查记录。

## 质量与统计标准草案

用途限定为低风险内部研究建议。拟议策略通过率底线为 90%，
相对 `direct-strong` 的非劣容忍为 5 个百分点；最小有用时间或 AFP 改善暂拟 10%。
这些数值**尚未根据用途完成真人校准，也没有冻结**，不可据此启动正式实验。
此处提出数值是为了让审查具体可讨论，不是赋予系统质量承诺。

在六个开发任务上检查标准可执行性与评分分歧，再由维护者和独立审查者签署用途适配。
若需调整任务、标准、路线或提示，仅使用开发证据；任何改动都重新生成版本与哈希。
候选留出答案不可用来调阈值或选策略；已经暴露给执行/调参过程的任务改归开发，并补新来源任务。

12 个候选留出、每题重复 3 次，只适合探索；36 次调用不是 36 个独立任务。
即使 12 个独立任务全部通过，二项独立假设下一侧 95% 精确下界也约为 77.9%，
无法证明总体通过率至少 90%。因此首批输出可以是“观察到达标、非劣证据不足”，
不能写“同质量”“95% SLA”或“稳定 p95”。该二项示例只解释样本限制，
不替代重复和来源聚类的实际统计方法。

策略级统计保留 pass/fail/pending 全部分母，报告确认通过率。
两个主要比较（有界策略对强模型直接回答、对整任务选模）应事先指定多重比较控制；
按来源族/任务聚类，以配对方式估计差异与不确定性，类别和结构分层只作探索描述。
#53 需实现并冻结具体区间方法、操作点、样本量依据及分析代码；本轮只输出计数，
不会在代码里制造已通过的非劣检验。

## 路线、顺序与停止

拟议 12 条路线：三种固定模型直接回答、整任务选模、输入无关随机混合、
复用图单模型与异构、自动图单模型/异构 × 串行/并行四条、执行前选直接或 DAG 的策略。
混合权重目前为 1:1 占位，正式冻结前仅能用开发集调。
复用图、策略、内部提示及近邻方法适配尚未绑定，不能把包络称作已经可运行的 benchmark。

相同任务每次重复内随机路线顺序，按重复轮交错；种子记录在协议。
第一轮固定策略，不用留出结果在线更新。自动图最多六节点，包含最终汇总节点，
不另漏算合并调用。同图消融中如何共享计划及分配规划成本由 #53 按 #51 约定实现。

底层零重试、零 planner repair、零节点模型 fallback、零动态再拆。
困难后再拆属于 #55 的独立冻结对照。
节点失败停止下游并结算在途请求；未知用量、认证或账本/证据写入错误停止整批。
无路线、超时与失败不从分母消失，不能“再跑到成功为止”。

## 零调用预检

```bash
uv run python experiments/preflight_quality_study.py \
  --output-dir reports/quality-study-v1/preflight-01
```

每次使用不存在的新输出目录。入口没有 `--live`，不创建任何模型客户端。
报告逐路线给出最多调用数、online/research AFP 上界、调用 timeout 之和及独立输出路径。
规划、执行、汇总和交付 judge 计入 online；独立研究 judge 另列。
画像、训练、近邻适配的离线设置开销仍未知，当前包络不是整项研究总预算。

AFP 按冻结 manifest 的未缓存输入/输出费率计算，不是实际消耗，也不是预测价格。
时间上界目前是拟议调用 timeout 之和加清理宽限，不是已经由 runner 保证的 deadline，
更不是预测用户等待；#53 必须绑定真实请求预算、在途结算和墙钟计时。
`formal_run_ready` 故意固定为 false；本模块只做准备，不是正式运行审批器。

## 完成 #52 还需要什么

1. 独立审查全部材料、参考事实、语义评分和来源/模板隔离；补充足够代表真实目标任务的材料。
2. 两位真实审查者完成开发正负例盲审，记录误杀、漏判和分歧；校准辅助 LLM judge。
3. 根据用途与开发证据签署质量、非劣、样本量和失败标准，替换当前占位值。
4. 把路线和 prompt 绑定到真实 runner，冻结离线设置开销、完整 AFP/时间包络与防泄漏检查。
5. 最后保存不可混淆的冻结版本，再启动正式模型实验；此前不关闭 #52。

历史 #40 的 35 份真人计划复核独立保留，不替代这里的任何新审查。
