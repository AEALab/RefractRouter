# 自动路由轨迹展示合同

## 入口与职责

DSH 的「路由轨迹」页同时展示自动路由与规划路由。任务 DAG 页签、两张插件设置卡片
和原生模式菜单继续存在。Python 返回 `automatic-routing-trace-v1` 的只读证据投影，
TypeScript 负责会话引用、读取和展示，不重新判别、选模或计算业务预算。

新增 NDJSON `automatic-trace` 操作和能力握手，不改变 `/4` 协议或已有路由操作。
读取轨迹不查询价格、不调用 Judge，也不重新执行历史任务。新运行同时在结果和 replay
中保留结构化轨迹；DSH 当前会话视图没有暴露 replay，所以插件从自己输出的运行 ID
标记读取本地证据。旧助手记录通过受控摘要中的运行记录引用兼容。

## 展示事实

| 分区 | 展示内容 | 解释边界 |
|---|---|---|
| 任务判别 | 结构规则、Judge 原始答案、合并动作、最终 direct／DAG、规则版本 | Noul 概率及规则派生类别分布不是 Choice confidence 或任务成功率 |
| 候选模型 | 当时完整配置目录、实际 provider/model、推理等级、数据域、逐节点准入、分配与预算检查 | 画像／容量／数据域合格不保证预算合格；质量画像是先验 |
| 路线比较 | direct 与 DAG 预测、规划探测、选中节点数、费用和时延范围 | 未选路线没有实测质量或费用；不限工具时没有完整任务成本上界 |
| 费用 | 生产／评审参考占用、现金用量结算、待核对预留、冻结预算和余额、独立 Jev | 参考成本包含按量调用，两项不相加；订阅费不按调用分摊；现金估算不是提供方账单确认 |
| 调用 | 账本预留顺序、真实来源、用途、原单位、用量、首字／总耗时 | 预留顺序不等于并发完成顺序；底层首字时间不等于用户首字等待 |
| 工具与评审 | 回执 ID、工具与节点、回执状态、审核原始分数与结论、质量门槛、停止原因 | `completed` 仅表示工具返回；审核返回通过仍可能低于门槛 |
| 状态与范围 | 运行、中断、缺失证据、实验标识、费用覆盖范围 | 状态缺失不能显示为完成；未知用量不能显示为零费用 |

## 候选预算诊断

选模搜索过程中保留每节点每模型的画像质量、参考／现金预测、可行组合数及各约束的
排除组合数。被支配候选单独标为覆盖，不误标成预算不足。不同约束的排除数可能重叠。
该信息由原搜索过程产生，不额外搜索，也不改变候选、打分、预算或最终模型选择。

历史缺少逐模型预算诊断时明确标注缺项；只显示已有冻结额度及原整体检查，不用新算法
给旧模型补写结论。用户把现金额度改成 5 CNY 后，旧任务仍显示其当时的 2 CNY。

## 读取与恢复

- 仅读取当前已加载会话引用的最近 20 条受管运行 ID，不扫描其他会话。
- 核心拒绝路径、非法 ID、超过 20 条查询、符号链接及超过 32 MiB 的单个证据文件。
- 白名单输出不含凭据、provider 配置、任务正文、模型原始请求或工具参数。
- 运行时刷新只读检查点。换会话、取消或卸载后的迟到读取不能把旧记录写入新会话。
- 读取失败显示该条错误，不隐藏规划路由记录，不修改或重新派发原操作。
- 核心与插件缺少轨迹能力握手时提示升级，不把空白误认成没有运行。

原始记录保持原样，升级后的投影不追改历史判定、价格或费用。本次属于展示交付，
不新增付费实验，也不据历史预测宣称自动路由收益已得到证明。
