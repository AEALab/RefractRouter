# K3 整任务基线与成本约束 DAG 对照

本实验检验：同一份任务交给 Kimi-K3 一次完成，与拆成 DAG 后按节点选择质量达标的
低成本模型相比，质量、费用和延迟有什么变化。已有成功 K3 基线、Pro 参考路线与
21 份节点探针，状态为 `node-review-ready`，尚未形成独立质量对照。
首次超时的[停止记录](../reports/v0.5-k3-prepare-admission/README.md)与后续
[成功恢复证据](../reports/v0.5-k3-resume-admission-2/README.md)均保留。
2026-09-10 获批的独立节点评审在第二次请求超时后停止，仅完成一份有效评分，
已知费用 2.2194 AFP，另有一次未知用量；见
[评审停止记录](../reports/issue36-node-reviews-20260910/README.md)。
此前的 ABC 对照及原始评分保留为历史证据，不能当作本实验的结果。

## 固定主对照

| 项目 | K3 基线 | 节点选模 DAG |
|---|---|---|
| 任务 | `report_001`，相同冻结来源、简体中文要求及最终 HTML 契约 | 相同 |
| 生产方式 | Kimi-K3 整任务一次调用 | 固定七节点，逐节点选模后重新执行完整路线 |
| 候选 | K3 仅作基线 | Flash、M3、Pro；与当前清单中已接入的候选一致 |
| 外部评审 | 独立人工或独立模型，随机样本编号 | 同一已校准身份及最终评分规则 |
| 重复与重试 | 单轮、零重试 | 单轮、零重试 |

使用现有 Agent Plan 清单。历史 `judge` 槽位中的 K3 在本实验显式绑定为基线，
不再承担评审。此绑定仅属于新入口，不改变历史入口或模型清单语义。
所有真实调用只允许 `/api/plan/v3`。其他已收录模型并未自动进入当前候选池。

生成阶段移除 `expected_claims`，避免把预期答案直接交给模型；评审依据任务要求、
冻结来源和实际产物。A/B 都使用同样的变更。这里的一次调用只指 K3 生产报告，
不包括对这份报告的独立评审。

## 选模规则

先用全 Pro 七节点参考路线固定上游，再对每个节点执行三模型探针，共 21 格。
同一节点的候选面对相同参考上游。通过契约且完成独立评审的候选才可参与选择。

默认质量门槛为 `max(85, 当前节点最高分 - 5)`，在达标集合内选实际探针费用最低者。
费用相同则依次比较质量和模型标识。配置在预检时冻结，跨阶段修改会被拒绝。
质量阈值是待验证的实验参数，不能视作已经证实的最佳取值。

已知契约拒绝保留原始输出并排除；未知质量、缺失或重复矩阵格、无效上游、
无达标候选均阻断组合。选定后重新执行 DAG 并独立评审最终结果，不能将探针分数
直接拼成整份报告得分。探针费用受输出长度和缓存影响，不保证在新上游下仍然最低。
这是同一任务上的探索性选路，不能据此宣称对未见任务的泛化能力。

K3 基线是本次对照的前置条件。请求失败、最终契约不合格或产物为空时立即停止，
不再执行参考路线和探针。无用量的失败调用保留未知费用，不能以零费用继续放行。

独立排查可显式使用 `stage: "baseline"`：仅执行 K3 一次并保存产物，成功也停止。
该阶段等待上限为 300 秒，其他阶段仍为 120 秒；任务、提示、模型和输出上限不变。
用户明确要求的再次尝试作为新请求留证，不覆盖首次失败，也不视为 SDK 自动重试。
它不自动接续完整 36 次实验；后续复用产物需明确冻结配置与统计口径。

## 盲评与校准

`public/` 保存随机编号、打乱顺序的评审材料及空白评分模板，不包含模型与费用映射。
`private/state.json` 保存执行结果和映射。只向评审者提供对应的公开材料；
模型可能在正文中自报身份，元数据盲化无法消除该风险。

节点按正确性 40、来源支撑 30、完成度 20、下游可用性 10 评分。
最终报告按任务完成度 40、分析与取舍 25、来源支撑 25、呈现质量 10 评分。
最终评审还须明确判断是否完成实质比较、选型取舍和有依据的结论；任一项不通过时，
任务完成度最多 10 分、分析最多 5 分。原始分与施加上限后的有效分同时保存。

每条评分必须有样本中可定位的原文和理由。导入检查材料哈希、精确样本集合、
评审身份、评分维度、有限数值和布尔检查。不得使用 K3 或候选模型作独立模型评审。
人工与模型身份为外部声明；导入器不能证明人的身份或外部调用实际使用了哪个模型。
审阅者需同时阅读来源，原文引用校验本身不能证明评分语义正确。

初始校准材料来自此前归档：一份明确缺乏实质比较却曾被打满分的 Flash DAG 报告，
以及一份内容较完整的 M3 整任务报告。准入要求：前者识别为缺乏实质比较且不高于
50 分，后者至少 80 分，两者差距至少 20 分。
这两份是暂定边界控制，**不是人工金标准**；通过两例也不足以证明评审可靠。
后续应补充独立人工审核和更多盲化边界样本，再讨论扩大实验。

节点评审、最终评审必须与此前通过校准的评审身份一致。离线夹具不能用于真实阶段。
主生产入口没有默认评审模型调用。后续使用独立的 `review_k3_outputs.py` 入口，
复用 GLM-5.3 已通过的校准，逐项记录原始响应、评分、费用和错误，默认零调用。
该入口不修改历史材料或放宽生产阶段的代码快照校验，详细命令见
[历史基准验证交接](benchmark-validation-handoff.md)。
GLM-5.3 的独立两样本准入已准备为单独入口，详见
[校准方案](independent-calibration-admission.md)；它不会被主实验自动调用。

## 执行阶段与费用

| 阶段 | 工作 | 计划生产调用 | 生产费用预估 AFP | 满足当前预检所需的最小两位小数额度 |
|---|---|---:|---:|---:|
| 预检 | 冻结配置、生成两份校准材料 | 0 | 0 | 无 |
| `prepare` | K3 一次、Pro 参考七次、三模型节点探针 21 次 | 29 | 131.67 | 131.68 |
| `resume` | 复用 K3，Pro 参考七次、三模型节点探针 21 次 | 28 | 119.48 | 119.49 |
| `compose` | 导入节点评分并执行选定七节点 DAG | 7 | 46.94 | 46.94 |
| `finalize` | 导入最终评分并汇总 | 0 | 0 | 无 |
| 完整生产实验 | 不含外部评审与 DSH 外层 | 36 | 178.61 | 分阶段配置 |

金额使用当前冻结清单和每调用输入 4000、输出上限 8192 token 的保守估计，
输入数量不是严格上界。预算适配器在下一次调用前检查剩余额度；单次实际输入超出
估计仍可能使支出超过预测，不能把预检数字当作服务端硬账单上限。
评审最多 25 个样本项：两份校准、21 份节点、两份最终报告；样本数不等于外部请求数。
外部模型评审、人工工时与 DSH 外层费用未知，不能按零计入总成本。

汇总同时报告：

- K3 生产路线费用，以及所选 DAG 的七次生产费用。
- Pro 参考路线与 21 次探针的选路费用。
- DAG 首次使用费用，即选路费用加所选 DAG 生产费用。
- 整场实验生产支出，即 K3 加 DAG 首次使用费用。
- 路线关键路径延迟，以及参考关键路径、串行探针耗时和所选路线关键路径之和。
  后者不含评审等待，也不是全部流程实测墙钟时间。

质量差为 DAG 减 K3；费用节省率分别给出路线口径和首次使用口径。
描述性候选信号暂定质量差不低于 -3 分且费用下降至少 20%；主信号使用首次使用费用，
另列只看最终路线的信号。单轮结论始终为 `Insufficient-evidence`，不会自动 Go。
只有在新任务上验证可复用选路后，才有依据讨论摊销，当前不作该假设。

## 零调用使用方法

以下命令不会访问模型，也不需要凭据。输出必须是全新目录。

```bash
uv run python experiments/run_k3_baseline.py --output-dir /tmp/k3-preflight
uv run python experiments/run_k3_baseline.py --mode offline --output-dir /tmp/k3-offline
```

DSH 插件使用 Agent Plan 清单、`billingUnit: "AFP"`、`credentialEnv: "CODEX_ARK_API_KEY"`，
保持 `allowPaidRuns: false` 和 `maxRetries: 0`，调用：

```json
{"phase":"k3-baseline","stage":"prepare","executePaidRun":false}
```

## 后续真实交接

先确定独立评审方式、完成校准，再申请这次实验的分阶段生产及外部评审预算。
历史预算余额不代表新一轮授权；首次准备超时后不自动重跑。

1. 从预检目录复制 `public/calibration-template.json` 到目录外填写。
   外部评分文件使用对象 `{"calibration": 校准评分对象}`。
2. 新授权后经 DSH 原生工具调用 `prepare`：`inputDir` 指向冻结预检目录，
   `reviewsPath` 指向上述文件。返回 `node-review-ready` 表示等待节点评审。
3. 将新的节点模板交给同一评审者，外部文件使用
   `{"calibration": 原校准评分对象, "nodes": 节点评分对象}`。
   经 DSH 调用 `compose`，`inputDir` 指向 `prepare` 产物；成功后等待最终盲评。
4. 最终外部文件使用 `{"calibration": 原校准评分对象, "final": 最终评分对象}`。
   使用下面的纯读取汇总命令，不传付费开关：

```bash
uv run python experiments/run_k3_baseline.py \
  --stage finalize --input-dir /tmp/k3-composed \
  --reviews /tmp/k3-final-reviews.json --output-dir /tmp/k3-final
```

真实 DSH 请求另需 `executePaidRun: true`、获批的 `maxProductionCost` 和
`maxEvaluationCost`；新阶段内部无评审调用，所以后者可为零，不能据此把外部评审
列为免费。配置开关与预算上限只控制执行，不替代用户授权。

材料目录生成原始字节 SHA-256 索引，跨阶段同时核对模型、任务和 Python 代码快照。
不要修改冻结目录；模板复制到外部填写，原评分随交接保存。索引保证完整性核对，
不提供签名认证。阶段检查防止输入类型错误，不会阻止有人使用同一输入在另一个
新目录重新调用；每次真实调用仍需对应授权。

每次完成的生产结果追加到 `production-results.ndjson`，网络进度另记。
中断后不得自动重跑整阶段；先核对请求与用量，保留已有产物，再处理剩余工作。
插件只负责参数与宿主边界，选模、评审、核算及实验结论全部由 Python 负责。

2026 年 9 月 8 日的单次重试已取得 `baseline-ready` 材料，详见
[K3 单次重试结果](../reports/v0.5-k3-baseline-retry/README.md)。
`resume` 接收该阶段材料，复用原始基线继续参考路线与探针；`prepare` 仍从头生成 K3。
基线硬契约通过不等于独立质量评审通过。恢复阶段保持原有评分与提示，
不因编号标题触发精确匹配差异而改写原始报告或调整评分规则。

```bash
uv run python experiments/run_k3_baseline.py --stage resume \
  --input-dir reports/v0.5-k3-baseline-retry/output --output-dir /tmp/k3-resume-preflight
```

上述命令不调用模型。跨代码版本只接受
`data/benchmarks/k3-baseline-resume-compatibility.json` 中登记的精确源配置、目标配置和
原始证据索引；任务、模型、清单、数据集或质量阈值发生变化时直接拒绝。
未经登记的代码变化也会拒绝。新预检目录记录迁移凭据，旧目录保持原始字节不变。
再次升级代码时必须重新审查兼容性，不能自动更新白名单绕过检查。

`resume` 的预算只覆盖新增参考与探针调用，K3 已发生费用单列导入；
准备阶段累计费用只计成功基线加本次参考与探针，历史失败请求和 DSH 外层另计。
未知用量保留空值，不可据此计算完整首次使用节省率。
具体预算与验证结果见[恢复准备记录](../reports/v0.5-k3-resume-readiness/README.md)。
