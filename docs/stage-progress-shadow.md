# Stage 进展与恢复影子

关联 [#206](https://github.com/AEALab/RefractRouter/issues/206)、总计划 W05。
旧 `stage-v4` 规则的固定保持与 hybrid 的连续降档确认继续保留。
本版只在 `refractagent-planning-v8` 的独立规则 Stage 中显式启用 `stageShadow`，
记录另一种决策，不影响实际选择、已交付正文、预算或后续派发次数。默认关闭。

## 为什么要比较

相同命令退出失败可能是正常测试红灯，也可能是同断言无进展；写入文件成功不能证明
任务正确。固定保持若干轮后自动恢复，也可能在没有新验收时过早回到弱模型。
首版采用可解释的结构化证据，不把未经独立校准的语义 Judge 分数和规则分数混加。
本地 Laya 不因此获得默认启用或新的质量资格。

## 输入合同与信任边界

`stageShadow.schemaVersion=stage-progress-shadow-v1`，固定 `holdTurns`、
`stallConfirmations`（至少2）及 `checkers`。每个检查器完整指定 `id`、`revision`、
`suiteSha256`、`assertionIds`，不能在任务途中更换或只保留容易通过的断言。

宿主通过现有 `toolEvidence` 提交 `validation`，合同 `stage-check-evidence-v1`：

- 当前任务投影的 `taskSha256`；计算方式是 `task_outcomes.digest(task_projection.summary(...))`。
- `checkerId`、`checkerRevision`、`suiteSha256` 与全部 `checks`（`id/status`）。
- `snapshotSha256` 与宿主递增的整数 `codeGeneration`，范围0至2^53−1。
- `phase=expected-red|acceptance`、`complete`，检查状态为 `passed|failed|unknown`。

宿主负责绑定实际代码快照、检查器和代码代次；Router 不执行工具，也不能从任意工具正文、
模型自述或脚本打印的 JSON 认证这些事实。普通 DSH shell 退出码没有完整断言与代码代次，
仍按旧规则执行，其影子只能报告不可比/未知；本版不声称任意命令已接入完整验收。
具备这些结构化事实的接入方可使用宿主中立的 Python 合同。这里不提供 OS 级恶意宿主认证。

## 状态与边界

同事件身份重放不增加失败次数；矛盾事件停止影子处理，不能任选较有利版本。
旧代码代次的晚到结果不重建当前验收；同代次不同快照保持未知。
成功写入令先前快照过时，后续验证须跨过代码代次屏障。代次应由宿主跟随实际写入推进，
不能由模型自行声明；未知代次不能用于恢复。

首次合理失败或预期红灯不升级。同检查器、同版本、同完整断言集合下重复相同失败，
才形成无进展依据；失败集合缩小为进展，其他不相容失败保持未知。
同批已解决的困难不会残留为后续另一个首次失败的升级依据。

强模型保持轮数耗尽后，没有新验收继续建议强模型；正常读取或一次写入不能恢复。
所有冻结检查器在同一更新代码代次、同一改变后的快照上完整通过，且没有未解的环境或
未知证据，才建议恢复。部分通过、全量仍有失败或快照未变均不足。恢复后同断言再次失败
可以重新升级。任务投影摘要变化完整重置本任务影子状态，不能继承旧任务的强模型状态。
检查器只覆盖其冻结断言；通过不自动证明整任务质量。

权限、认证、网络、超时、资源等故障应由宿主归类为 `denied`、`infrastructure` 或未知，
不当作模型能力失败。常规宿主尚未提供可靠故障分类时保持未知，不根据正文猜测。
规则模式与 hybrid 分别记录；hybrid 已有保持和连续确认，本包不重复实现或重新命名为新能力。

## 离线比较与费用

`data/stage-progress-v1/cases.json` 冻结9个人工案例、40个边界，含2个不可评分边界。
旧事件、断言、代码代次、参数、预期和模拟价格一并固定；它们不是独立真实开发题。

```bash
uv run python experiments/replay_stage_progress.py \
  --corpus data/stage-progress-v1/cases.json --output-dir /tmp/新的Stage重放目录
```

输出全新，输入与输出分离，记录实际加载实现和输入前后摘要，失败另存。
对同一冻结轨迹报告误升级、过早恢复、强模型调用比例、换模次数和额外强模型轮数。
模拟完整费用包含全部冻结执行与共同审核，明确为重定价；实际模型改变后工具轨迹可能改变，
因此实际完整费用比较为未知，不把合成价格或相同轨迹算术当作真实节省。
`#210` 只有在前阶段合格时才对 Stage 作相同工具的独立真实验证。
