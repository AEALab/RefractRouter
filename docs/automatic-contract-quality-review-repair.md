# 自动路由合同、事实与评审修复

## 依据

模型容量复验执行五条路线后停止：两份规划出现非法 `analysis` 类型，一份 Direct
回复漏算费用组成项，另一份 DAG 的最后评审在任务期限内超时且用量未知。
见[原批次记录](automatic-model-capacity-recheck.md)。旧记录与未知预留保留。

这三类故障分别处理，不能把取消输出限制、模型给出高分或安装通过当成质量修复。
本轮改动位于独立 DAG 研究入口及其测试集成；标准模型 API 的宿主工具执行、权限、
上下文管理和任务推进保持由接入的 Agent 负责。

## 修复

### 已知类型别名

紧凑规划的兼容层接受一个明确别名：`analysis → synthesis`，表示对材料进行综合分析。
它不修改 job、难度、风险、节点数量、依赖或最终交付；不增加模型调用。
原始输出与 `compact-type-alias-v1` 转换记录共同保存。
严格图合同仍拒绝未知类型、未知依赖和冲突标识，不能把任意字符串猜成合法节点。
本次两份实际失败计划已作为仅含公开审查内容的夹具，检查转换后图结构和职责保留。

### 数值与验收

节点执行和最终评审增加独立列项、单位及计算式核对规则；账本问题明确：

- 参考成本合计包含订阅参考估值及按量费用。
- 现金占用包含已结算按量费用及未知现金预留。
- 订阅参考估值不是该次订阅调用的现金扣款；合计与各分项不可混淆。

原任务若明确采用其他定义，以原任务为准。这些约束不替模型执行用户任务或改写正文。
生成结果仍可能出错，不能承诺提示调整保证正确。
已冻结的旧文本节点回放显式使用 `legacy` 提示合同，原请求指纹与历史结果不改变；
首次修复使用 `numeric-v1`；有限真实复验后再增加 `numeric-v2` 的明确组成公式，
防止把「两账本不可相加」误解成参考合计中排除已结算按量费用。旧实验不追改。

Python 调用方可提供确定性最终校验器，研究 runner 将已有冻结答案检查接入此边界。
校验失败时保存证据与已花费用，记录 `quality-failed`，不派发付费最终 Judge；
模型高分不能覆盖已知错误。参考答案不提供给执行模型，其他没有明确验收器的任务
不会假装获得了确定性验证，也不自动追加返工或换模。

### 评审时间与输出

原批次两次成功评审分别耗时 18.547 秒与 39.970 秒，因此自动路由默认给最终评审
预留 60 秒，独立评审输出上限为 8192 tokens，并受模型容量约束。
执行模型的「不额外限制」保留；一个模型同时承担执行与评审时，只有审核调用收窄包络。
执行准入与节点请求期限使用任务总期限扣除评审预留后的时间，最终评审仍使用原总期限。
明确不限任务时间时不预留有限时间。旧独立 task API 未设置新字段时保留原行为。

执行器即使用量已确认，但迟到后剩余时间不足，也记录 `review-time-exhausted` 并停止，
不在几秒钟残余窗口里派发最终 Judge。若已派发请求认证失败、超时或用量未知，
仍按原规则保留待核对预留；本修复不能保证提供方永不超时。

新参数 `reviewReserveMs`、`reviewMaxOutputTokens` 冻结于任务预检；任务开始后不改变。
路由轨迹显示评审包络、确定性阻断及规划格式转换；旧记录缺字段时按原证据显示。

### 规划时间交接

有限复验发现一份合法四节点计划，全部模型时延先验均为每次 60 秒、并发为 1。
规划结束后只剩 230.138 秒执行窗口，计划预计 240 秒，准入正确阻断。
核心 0.16.10 将剩余时间、评审预留、规划期限、模型时延先验和并发上限传入规划材料，
让规划器在拆分前看到执行包络。该信息不是速度保证；Python 仍执行原准入检查，
不伪造时延、不改图依赖、不删交付要求、不自动延长期限。
若总时间连评审预留都不能容纳，在付费规划前停止。

## 第二轮修正：验收口径与规划规模

费用题的旧正文只写「已知参考」，两条失败回复都采用了订阅分项解释。标准答案要求
所有已结算调用的参考合计。旧材料虽展示按量结算的参考字段，却没有明示问题所求的
合计范围。因此旧分数可保留，但不能将两例全部归因为模型加法错误。

新增 `automatic-applicability-v4.json`，完整保留 v3 文件、原始来源材料和数字通过标准。
v4 在题目中明示总参考、现金、未知预留的定义，并将同一结构化账本交给模型。预检用
Decimal 从输入推导答案，检查冻结答案是否一致；测试再与实际 TaskCallBudget 的现金
快照和停止行为交叉检查。更改题目定义后的结果单独记录，不与 v3 混算收益。
核心执行提示采用通用 `numeric-v3`：按题目定义复算、区分合计分项及未知量，不将某道
费用题的领域定义写入所有用户请求。旧 `numeric-v1/v2` 与历史 legacy 回放仍可读取。

此前时间信息仅作提示。现在串行执行、所有候选都有有效时延先验且任务有期限时，
规划节点上限为执行时间包络除以最快候选先验，向下取整并受原六节点上限约束。
最终交付节点也占一个名额。并行、未知先验或无限期限不使用这个串行估算。
例如 300 秒任务扣 90 秒规划和 60 秒评审，60 秒先验对应最多两个节点。该限制不改写
交付要求，模型仍负责在范围内规划；返回超限计划则保留失败并停止，不擅自删节点。
后续模型资格、质量、输入、实际剩余时间与预算准入继续执行，先验不代表性能保证。
所有五种规划提示组合均覆盖时间合同，轨迹展示节点上限。标准 Base URL 策略不进入
这条 DAG 研究路径。
