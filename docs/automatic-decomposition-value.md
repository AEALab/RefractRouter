# 自动路由拆分价值门控 v3

## 目标与边界

先满足可接受质量，再降低全部模型费用，最后优化等待时间。2026-10-05 的变更
位于独立自动路由研究入口；标准模型 Base URL 与规划路由不进入 DAG 或内部工具循环。
实际部署仍继承用户的任务处理方式，不把安装升级当成自动开启 Judge 的授权。

## 本次定位的原因

1. 宿主系统提示与长历史被当成任务复杂度，导致简单请求也进入付费规划。
2. 结构问题没有区分「分支之间依赖」和「最终汇总读取分支产物」，容易误判并行工作。
3. 工具、交付格式与验收标准被当成必须拆分的证据，覆盖了正确的顺序依赖判断。
4. 旧时延观测混合不同请求规模；仅显示 `dag-infeasible`，无法核对具体约束。
5. 真实测试的 2048 token 包络可能全部被推理消耗。这是输出截断，不能伪装成
   拆分判断错误、自动重试或靠降低验收要求绕过。

## 决策顺序

1. 先检查显式任务模式与工具权限。用户强制选择保留原行为。
2. 严格识别少量封闭微型任务：单句定义、短算术。它们跳过 Judge 和规划；
   主模型仍看到原始请求，容量、权限和费用检查不跳过。
3. 其余自动任务使用已配置的规则或结构 Judge。默认 OpenRouter Jev 使用一次批次、
   两项 `Noul`：分支开始前是否需要另一分支的实际产物；是否存在值得分别处理的实质工作。
   不让 Jev 预测价格、生成完整 DAG 或执行工具。
4. v3 `COUPLED` 选择单路线；多材料、工具和交付约束仍影响评审及准入，不能单独证明需要拆分。
   两项答案相互矛盾时返回 `UNKNOWN`。历史 v2 的合并语义保留。
5. `SEPARABLE` 仅允许进入规划。生成器须避免把微型计算、核对和汇总拆成多次昂贵调用。
   Python 核验依赖、模型资格、输入容量、质量先验、预算和剩余时间。
6. 同时比较实际直接执行候选与生成图。先通过相同硬条件，再比较包含规划、执行、
   工具续接额度和评审的总费用；成本相同时比较调度时延。已花的规划费用始终记账。

顺序执行不等于没有工具；也不表示任务已经完成。任务执行与工具权限继续遵守宿主边界。
本版没有新增任意图编排、强制拆分比例或为了展示节点而放宽预算。

## 请求规模与时延

真实观测按 provider、实际模型版本、实际推理档位和本地范围隔离。
在最近 50 条成功调用中排除规划、评审、分类以及缺失用量的记录，再按输入／输出规模匹配。
同组至少 5 条使用最近秩 P90；不足时使用不低于 60 秒的保守先验，并保留已有更慢预测。
失败、截断和未知用量不作为快速成功样本。不为填满样本而发起付费探测。

输出无显式预测时仍使用本次输出上限，可能很保守。分组不校正缓存、服务负载和
所有任务语义差异；P90 不是 SLA 或真实完成时间保证。质量仍是独立资料先验，
不能与这些时延观测混称已校准的任务成功率。

## 可解释记录与兼容

记录规则结论、Judge 原始信号、最终决策、生成与选中节点数、各模型的规模分组和
匹配样本、质量／费用／时延拒绝数量、预计最短调度时间及剩余期限。
多个约束拒绝同一分配时计数可以重叠。旧记录缺字段仍可显示。

简单任务走 direct 后同样编译真实上下文与工具包络；长历史不会因为跳过规划而绕过容量检查。
核心为 0.15.13，插件为 0.29.10。无新增协议操作；原有 DAG、规划路由、模型与凭证保留。
