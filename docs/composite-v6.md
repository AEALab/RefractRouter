# Composite v6 设计与使用说明

## 定位

Composite v6 将两个已经独立验收的职责按任务边界组合：

1. Task 在新任务开始时，从 Composite 自己的模型池中选择常用模型；
2. Stage 在后续工具边界消费新增的可信执行证据，决定继续使用常用模型，或临时切换到
   用户指定的接管模型。

Router 只选择模型、记录判定和结算受管模型调用。工具执行、权限、上下文压缩、委派和任务
推进继续由 DSH、Codex、Hermes 等接入方负责。标准模型入口为 `refract/composite`，不建立
DAG，也不执行宿主工具。

## 任务级交接

Composite 使用 `refractagent-planning-v6` 的独立配置，不再依赖通用高效、强执行和判别角色：

- `pool`：Task 候选模型池及稳定优先顺序；
- `takeover`：Task 无法确定时的备援，也是 Stage 临时接管模型；
- `judge`：Task 的轻量 LLM 或本地 Laya Judge；
- `stage`：后续采用规则模式或规则＋本地 Laya 模式。

Task 只在任务开始时执行一次。单一合格候选会跳过 Judge。首次执行直接使用 Task 选出的
常用模型，不紧接着再做一次 Stage 判别。工具续接和追加指导沿用同一 Task 结果。

如果 Task 已选择接管模型，后续不再做没有实际切换意义的 Stage 判别，轨迹明确记录
“常用模型与接管模型相同”。模型名称和价格不作为能力更强的证明。

## 规则模式

默认参数为证据窗口 3、判断阈值 0.5、接管保持 2 次执行。两次执行包含触发切换的当前
调用和下一次调用。

- 新的同类可信失败连续出现时切换接管模型；
- 已消费事件不能再次触发切换；
- 保持期内继续使用接管模型；
- 保持结束后没有新的困难证据时恢复 Task 选出的常用模型；
- 单次合理失败、正常搜索、权限拒绝和基础设施故障不当作模型能力不足。

纯标准 Chat Completions／Responses 工具结果通常只有文本，Router 将其标为无法分类，
不会从“失败”等正文猜测退出状态。接入方可用版本化
`metadata.refract_tool_evidence` 提供与已完成工具调用绑定的可信事实。事实必须匹配调用 ID
和工具名，同一事实发生矛盾时停止续接。

## 规则＋本地 Laya

实验模式复用 Stage 的本地结构化问题合同。默认每两次执行最多判别一次，每任务最多四个
批次；低确定性或完整输入超出容量时选择接管模型。降回常用模型需要连续两次明确支持。

权重必须提前下载、核对 revision 并加载。任务运行时不会隐式下载，也不会在本地进程故障
时改用云端 Judge。当前 `aac6fef/laya-multilingual-mlx` 固定 revision 的响应速度可用，但
判别质量尚未达到日常使用门槛，因此设置页持续显示实验状态。

## 预算与轨迹

付费 Task Judge 派发前保护一次必要执行调用。候选模型互斥，不把整个模型池费用相加。
后续 Stage 只为实际选中的执行模型预留；接管预算不足时停止，不静默降档。AFP 和现金继续
分账，本地 Judge 记录 forward 数、冷启动和等待时间，不伪造 API 费用。

每次路由轨迹至少记录实际模型、推理等级、调用用途、初始 Task 选模、排除原因、证据 ID、
保持前后状态、切换或恢复原因、规则版本、本次费用和累计费用。旧记录缺少字段时仍可显示。

## 已知限制

- DSH、Codex、Hermes 的标准模型接口已通过正常工具续接。DSH 原生事件可提供可信工具结果；
  Hermes 插件与 Codex CLI 适配器现已完成无付费重复失败换模验收。纯 Base URL 接入依旧没有
  退出状态，Codex 桌面端与其它执行模式尚未按此能力验收。参见
  [客户端工具证据接入](client-tool-evidence.md)。
- 本地 Laya 保持实验状态；本次有限验收不证明自然任务收益。
- 图片／影片审核、P6 子 Agent 共享预算和大规模收益对比不属于本版。
