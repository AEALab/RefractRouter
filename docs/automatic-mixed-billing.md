# 自动路由混合计费与 AFP 优先决策

## 状态与目标

本文件记录自动路由的混合计费决策合同。代码已提供可选的 `dshModelPool` v4
及 providerConfig v5、双单位节点分配和 DSH 配置入口；原有 v3／v4 单单位
配置按原合同运行。已在用户现有 DSH profile 完成有限真实接线：AFP
单节点任务与 AFP／CNY 混用的四节点 DAG 均完成并通过当次模型评审。此前
CNY 评审 JSON 无效、AFP 评审额度不足等失败仍保留在原始运行记录中。
这些结果证明对应功能路径可用，尚不能声称普遍质量或费用收益。

产品目标是先满足用户设定的质量、能力、数据域和预算门槛，再尽量减少新增现金
支出。用户已确定：在满足这些门槛时，默认优先使用已订阅的 Ark Agent Plan
AFP 路线。AFP 不产生本次调用的额外现金扣款，但会消耗有限订阅额度；账本必须
保留 AFP 用量，不能把它记作零资源消耗或按任意汇率折成 CNY。

## 模型与任务准入

每条模型路线按实际 provider、接口、版本、数据域和计费单位独立核验。模型出现在
DSH 目录，只证明宿主能发现它；被加入自动路由模型池、通过当前任务准入、成为
实际派发模型是三个不同状态。设置和路由轨迹应分别列出这三个状态及排除原因。
混合计费设置沿用旧 `roleOverrides.workers` 时，若其中只有 CNY 路线，即使 Ark
已启用也无法成为执行候选。设置页会提示用户将 AFP 路线加入执行池，或清空
显式执行池交由核心自动分配。

质量先验达到 `qualityMin` 只表示模型进入可尝试的候选集合，不等于本任务质量
不会下降。AFP 优先还须通过与可行现金候选相同口径的质量比较；若已有可信的
任务级反例或质量画像明显更低，不得因订阅制而选 AFP。不得绕过能力、历史兼容
或数据域门槛。仅有公开先验、缺少任务级对照时，在轨迹中标记证据级别，不能
显示为“已证明无质量损失”。

## 费用向量与偏好

对完整候选路线分别预测并保存 `{AFP, CNY}`。规划、执行、审核、判别、必要的
工具续接和预计接管调用按实际路线进入各自单位。USD 现金来源只有在冻结汇率、
日期和价格来源后才能换算为 CNY；AFP 始终不换算为 CNY 实付。

先排除任一单位超过对应任务额度或调用名额的路线。满足质量与预算的候选按以下
顺序选择：

1. 比较新增 CNY 支出；较低者优先。因此合格的 AFP 路线通常优于另需现金支出的
   路线，即使它消耗更多 AFP。
2. CNY 预计支出相同，再比较 AFP 消耗；较低者优先。
3. 两种支出相同，再比较经过验证的等待时间；仍不可区分时保留确定性模型池顺序。

这是用户选择的“订阅优先、现金其次”的词典序偏好，不是把两种单位求和得出的
客观总成本。展示时要同时列出各路线两种额度和选择规则。例如：

| 路线 | AFP | CNY | 按本偏好 |
|---|---:|---:|---|
| 直接执行 | 12 | 0.01 | 优先，新增现金较少 |
| 三节点 DAG | 8 | 0.06 | 保留为候选 |

如果 AFP 额度不足，第一条路线不可行；若第二条仍在现金额度内，才可选择第二条。
规划调用若在比较前已经派发，属于两条候选共同承担的已结算成本，不得为其中
一条重复计入差额，但仍须进入任务总账和授权上限。

## 预留、结算与失败

每次调用按自身单位原子预留，回执按实际模型、价格时段、用量及单位结算。
账本支持跨单位必要调用路径的原子预留；每笔已知请求按实际单位预留并结算。
混合计费直答现在会在执行前检查最终评审的保守输入上界；不足时零调用预检
直接阻断。该上界取当前选中执行模型的输出容量，可能高于实际花费。未来审核
调用的动态输入额度尚未锁定为跨调用保护额；生成过程超出预测包络或并发共享
预算时仍需进一步验证。未派发的预留释放；用量未知的已派发调用保留待核对额度并停止
后续受管调用。任务最大调用数和取消状态由两本账共享。

轨迹分别显示 AFP、CNY 的预计值、保护额、已结算值及待核对额。历史单单位记录
保持原状，不追改为混合计费。旧版自动路由配置继续按原单单位合同运行；新版配置
和协议须显式升版，缺少任一单位预算、价格或宿主接口时在零调用预检中阻断。

## 上线验收

先完成同单位回归，再覆盖 AFP 执行＋CNY 审核、CNY 规划＋AFP 节点、同一 DAG
内 AFP／CNY 节点混用、预算不足、不同价格时段、未知用量、并发预留，以及
AFP 候选质量不合格而选 CNY 的反例。用无网络模型验证合同；真实调用只做有限
接线验收并分别报告两种实际用量，不用增加拆分比例作为通过条件。

本机有限验收中，`ark/glm-5.3` 直接回答并经同路线独立评审通过：执行
7.49295 AFP，评审 4.05045 AFP。OpenRouter Jev 的拆分前判别另记
0.0001580969124 CNY；该调用在 Router 主模型账本之外，展示时按调用 ID
去重，并提供两种单位的已知合计，不能把主账本的 0 CNY 当作全任务 0 CNY。
此结果仅证明单节点接线及记账，不证明多节点 DAG、质量无损或普遍节省费用。

随后使用三项独立事故分析及最终汇总，在 DSH 中临时选择“始终拆分”，真实
生成三个并列分析节点和一个汇总节点。A、C 与汇总由 DeepSeek 官方
`deepseek-flash` 执行，B 由 Ark `glm-5.3` 执行；最终模型评审给出 93 分并通过。
生产账本为 12.83265 AFP 与 0.06713856 CNY，评审为 6.3774 AFP，
合计 19.21005 AFP 与 0.06713856 CNY。证据保存在
`.refractagent/runs/20261005T122516Z-facabfc3b18b/`。本题未使用拆分前 Jev
判别；其 CNY 金额来自 DeepSeek 执行节点。

当时单任务生产上限为 50 AFP，规划调用后仅余约 45.40 AFP。四个节点都选
`glm-5.3` 的冻结预测约需 162.03 AFP，因此分配器在独立现金上限内选择
混合路线。这说明现金调用是预算准入的结果，不是 AFP 优先规则失效。随后将
本机生产上限调整为 200 AFP，并恢复原有“自动判断”模式。使用同一冻结计划
与模型画像做零调用重算时，四个节点均选 `glm-5.3`，预测 162.03 AFP、
0 CNY；该重算不是新配置下的真实任务结果。用户已授权的累计额度与单任务额度
须继续分别核对，AFP 预测也不能视为已实际消耗。
