# 自动路由的最终审核与一次纠正

## 适用范围

本功能属于自动路由的 DAG 研究入口。标准模型接口与规划路由继续交由宿主 Agent
推进任务、执行工具、管理权限与上下文；本变更不向标准入口增加内部 Agent 循环。

`maxFinalRevisions` 默认为 `0`，保持旧配置行为。显式设为 `1` 后，最终正文质量不合格
可以由原最终执行模型纠正一次，并须通过复审才交付。规划、已完成节点和工具不重做。
非法审核回执、认证、传输、未知用量或证据写入失败停止，不能借纠正触发自动重发。

## 审核证据

新版闭环使用 `proposal-constraints-v9`。核心保存完整任务、候选、宿主工具证据与哈希，
把原文分页为有限编号。Judge 选择 `answer_ref` 和 `source_refs`，不重复抄写长引用。
核心核对编号、判定、逐句覆盖与来源类型后恢复展示文字。未知编号、缺少判定、
事实通过却无来源、前后判定矛盾都会阻断；编号存在不证明来源语义支持结论。

`source-state` 与 `time-causality` 审核整份候选。两项的 `answer_ref=null` 表示
整份候选范围，由核心绑定候选哈希，不代表无法判断；判定仍须明确填写。
逐句项必须使用固定引用编号，事实通过仍须选择独立来源。仅当规范字段完整时删除
已观察到的多余空别名 `check-id:null`，记录原始回执与零调用规范化；不补全任何缺失判定。

分页不会截断原始材料。JSON 字符串的解码视图绑定实际输入；候选正文及其中的
指令不能成为支持自身事实的独立来源。旧引用合同与历史记录保持原样读取。

审核范围包括正文、建议、恢复步骤、实现状态和时间因果。无工具调用的自我说明
不能证明系统历史上未经测试；“可能”或“风险”不能使错误前提与错误因果合法。

## 可信校验与语义审核

可选 Python `final_validator` 是接入方或实验系统提供的确定性校验器。它可以返回
`deterministic-answer-fields-v1` 回执，列出已检查的 `answers` 字段和当前候选哈希。
回执不能来自候选或模型声明，不传隐藏标准答案；哈希、范围、字段或结果不合法时停止。

Judge 不用未经验证的心算推翻这些已确认值，仍检查解释是否一致，以及正文、建议、
其他计算与证据是否正确。回执只确认列出的字段，不确认工具成功、语义质量或整体通过。
没有可信回执时继续按原任务审核。本功能不替 Agent 调用工具来制造校验结果。

## 额度、取消与记录

纠正派发前，Python 原子保护纠正调用与必要复审的费用和调用名额。复审先保护明确
输入包络，实际派发前绑定真实消息。未派发保护及时释放，已派发且用量未知的预留保留。
取消后迟到响应不能推进任务；公开参考估值、现金费用与待核对预留分开记录。

审计保留原候选、首次判定、纠正候选、复审、费用与状态变化。路由轨迹展示阶段、
接受或丢弃、原因、保护额度与实际模型；不公开隐藏标准答案或完整私有上下文。

## 验收原则

离线测试验证状态、预算与引用合同；真实成对案例验证是否误放行；完整自然任务验证
规划、执行、审核与交付。三者分别报告。真实题目的材料和成功判据保持冻结，失败
记录不覆盖，不通过降门槛、放行未审定正文或反复重试制造成功。
