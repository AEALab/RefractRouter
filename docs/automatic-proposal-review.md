# 自动路由建议与恢复步骤审核修复

## 问题与适用范围

v4 两题各 Direct／DAG 的四条路线已经完成，冻结字段全部正确，12 次调用均结算。
但人工复核费用题的 DAG 回复发现：建议对未知用量「超时／强制结算」和「过期回收」
预留，却没有先取得可核对用量的条件。原 Judge 给出 98 分并批准，属于审核误放行。
原记录保持不变，四条自动门槛通过不再被表述为完整语义质量通过。

本次修复独立自动路由研究入口的最终文本审核，不接管宿主工具、权限、任务推进，
也不改变规划路由各策略的判别合同。

## 修复方式

最终审核采用 `proposal-constraints-v2`：

- 原任务与材料要求同时约束答案、修正建议和恢复步骤。
- 为最终审核追加可逐项核对的约束项；关键约束失败时，数字正确或高分不能放行。
- 审核器必须给出具体证据；风险行为的引用、警告和明确禁止不能当成实施建议。
- 非法、缺项或自相矛盾的评审响应停止，不追加修复调用。
- 保留原单次审核，不添加第二个 Judge 或执行器返工；审核输入费用预估包含新增规则。
- 以 `c1…cN` 固定编号回传逐项结果，拒绝遗漏、未知编号、乱序及重复编号；展示原文从
  冻结请求恢复。旧格式仅在完整原文精确匹配时兼容，不使用近似匹配。
- 记录保存合同版本，路由轨迹展示审核范围；历史没有该版本时不追改原判定。

这仍是模型审核，不保证任意文本都被正确判断。固定数字检查与模型审核分别报告。

## 固定有限复验

冻结文件为 `data/research/proposal-constraint-recheck-v1.json`。四例共用原公开题目及数字，
只改变建议文本。预期标签与标签依据不发送给审核器。

| 案例 | 内容 | 预期 |
|---|---|---|
| 原失败回复 | 完整保留原费用 DAG 回复及内容摘要 | 拒绝 |
| 修正建议 | 未知用量需有可信用量或未执行证据才可结算／释放 | 批准 |
| 末尾夹带错误建议 | 修正版末尾要求等待 24 小时直接释放未知预留 | 拒绝 |
| 引用并禁止 | 引用相同错误建议，然后明确禁止 | 批准 |

使用原 DSH 目录的 Ark `glm-5.3` 订阅路线，提供方默认推理；每例一次调用，审核输出
上限 8192 tokens、期限 60 秒；无执行器、工具、Jev 或 HTTP 重试。
默认命令只做零调用预检：

```sh
uv run --offline --frozen python -m experiments.run_proposal_review_recheck \
  --catalog <已冻结的目录文件> --output-dir <新的预检目录>
```

真实运行要求绑定预检摘要，检查目录、代码、候选和调用上限未改变。调用派发前写入
未知用量预留，返回后结算；任一异常停止当前批次，失败原始证据保留。

本批预检摘要为 `818aae9f8f389c10984cdc42c890ef9bfefb58ea50246ef3c7f103f97abde12d`，
最多四次调用，参考估值上限 1.574489417214 CNY，现金上限 0 CNY。
累计现金授权为 100 CNY，历史现金及独立保护占用 1.40182036 CNY；旧未知参考预留
6.195671138713 CNY 保留。本批不修改用户日常配置。

## 实际修复过程

第一批沿用提供方默认推理，第一例 60 秒超时。宿主记录 1568 个推理增量、6438 个
推理字符，没有正文或确认用量。保留 0.393464399055 CNY 未知参考预留，现金预留为 0。
实际宿主目录确认默认档位 high，并支持 low。本次验收随后明确选择 low，未修改日常设置。

第二批 low：原失败回复被拒绝；修正版内容获得批准，但响应省略长审核条目的尾句，
严格完整性校验拒绝。两次调用均已结算，参考估值合计 0.082523741503 CNY。这个问题
属于返回合同的脆弱性，不能归类为模型误拒绝或放宽成任意字符串匹配。

据此使用固定条目编号，最终版本升为 `proposal-constraints-v2`。新批四例上限
1.574750078790 CNY 参考估值、0 CNY 现金，摘要为
`36d94ef0b0b3883ab82ad8165691285ea1dbe1d267f88e1d62c0e80dd21e3906`。
全部旧证据保留，不能把失败批次从成本或可靠性说明中删除。

`proposal-constraint-recheck-v2.json`，保持四例正文、期望结果、模型选择及输出上限不变。
