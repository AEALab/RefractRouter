# DAG 多任务冻结对照与费用预检

[Issue #32](https://github.com/AEALab/RefractRouter/issues/32) 要求区分拆分、调度及路由收益。
[data/benchmarks/dag-routing-v1.json](../data/benchmarks/dag-routing-v1.json) 冻结了任务、
人工 DAG、清单哈希、拆分、重复次数、六组方法、阈值及分析方式。已完成离线模拟，并执行了首轮真实调用；该轮在第一个节点的 JSON 格式契约失败后停止。
已确认生产记账为 0.0275 AFP、评审为 0，仍不存在真实最终质量或路由收益结论。

## 任务与数据拆分

任务完全使用请求内给定材料，涵盖方案比较、资金约束分析和简短改写三个任务族。
每族有 2 个校准任务和 1 个留出测试任务，共 6 个校准任务、3 个测试任务。
比较任务的独立分析分支可并行，资金约束分析包含必要依赖，改写任务只有一个节点。
具体题目、事实、验收条件和各节点指令均直接保存在协议中。

这是固定人工 DAG 的实验，隔离调度和模型分配的效果，不测自动规划器的拆分质量。
自动规划能力及对新任务的结构适应性仍需另一套授权验证。

校准任务重复 2 次：先让三个候选模型分别独立执行整个 DAG，并获得最终评审。
随后以固定参考模型该次运行的上游产物为上下文，独立探测每个节点的全部三个候选模型，
并逐项独立评审。各候选在同一探测上下文中消费完全相同的材料；该条件预测仍不能代替
下游使用实际混合模型产物的组合验证。

分层 profile 仅使用校准探测；候选单模型也仅根据本任务族的校准结果选定，进入测试后
不再修改。另存未经过约束筛选的最高平均质量单模型为质量基准；综合单模型须通过全部
校准验收且平均质量达到底线，再按质量、费用及模型 ID 排序。无合格模型则停止实验。

## 六组对照

每个测试任务重复 3 次，共 54 次测试运行；加上 36 次整图校准，共 90 次整任务运行。

| 方法 | 内容 | 用途 |
|---|---|---|
| `direct-strong` | 参考强模型单次完成原始任务 | 不拆分基准 |
| `dag-strong-serial` | 相同 DAG，全部用参考模型，串行 | 与不拆分组比较拆分效果 |
| `dag-strong-parallel` | 相同 DAG/模型，有界并发 | 隔离并发调度效果 |
| `dag-calibrated-single` | 按任务族校准后冻结的单模型，有界并发 | 单模型选择基准 |
| `dag-node-a` | 分层 profile，A 约束式，有界并发 | 节点路由效果 |
| `dag-node-b` | 分层 profile，B 加权式，有界并发 | 与 A 及单模型比较 |

所有组共用最终评审、验收要求和 provider 边界。串行组只把全局并发度改为 1，仍保留
provider 并发上限与启动间隔；并行组最大并发 2，`ark-plan` 上限 2、启动间隔 100 毫秒。
这些是单次 DAG 节点调度限制；校准探测、评审和不同任务之间不提供账户级限流。
协议按固定顺序执行，仍可能受到服务随时间变化的影响，不是随机交叉试验。

三候选和独立评审模型绑定至冻结 AFP 清单，使用 Agent Plan `/api/plan/v3`，零重试。
真实调用遇第一个不可用响应、契约错误、预算/时间不足或无可行路线便停止；有效但
质量不足的评审结果会被保留，用于排除候选或判定未达标，不当作传输错误重试。

## 预先固定的验收

选模要求节点质量代理至少 80、预测节点费用不超过 100 AFP、任务截止时间 300 秒；
B 权重为质量 0.5、成本 0.25、时延 0.25。最终收益判断还要求：

- 配对组的最终答案均通过语义验收，最终质量不低于 80。
- 候选相对基准的平均质量损失不超过 3 分。
- 成本至少降低 10%，时延比不超过 1。

分析按相同任务 ID 与重复编号配对，并按任务聚类重采样 2,000 次，固定种子 32，
报告 95% 区间。质量差下界、成本节省下界及时延比上界均须达到对应条件。
六组对照分别报告，不合并成一个总胜率。缺失配对不得报告成功。
只有 3 个独立测试任务，结果最多是探索性信号，不能证明跨任务泛化；模拟结果的
`exploratory_signal` 恒为 null，不用模拟评分证明收益。

每次部署成本包含节点调用和运行时必需的最终评审。校准、独立探测及其评审费用另列，
总实验费用全部计入双预算。这里没有模型规划调用，也没有外层 DSH 助手调用。

## 对称单模型基线与新留出集

增加 `dag-single-a` 和 `dag-single-b`。两者只允许同一 DAG 的全部节点使用同一模型，

## 独立样本采集协议 v5

`dag-routing-v5.json` 使用 `dag-routing-study-v3`，将停止范围从整批缩到独立样本。
每个 DAG 有独立的停止状态，账本按剩余总包络准入；契约失败阻止该 DAG 下游，
结算在途调用并保留失败记录后继续其他样本。认证、未知用量、账本、证据写入或
未分类程序异常停止整批。没有重试、输出修复或事后修改历史失败。

六种显式交接、36 次整图校准、84 次节点探针和 72 次留出结果最多使用 540 次调用。
探针消费历史 v3 **校准任务**中预先冻结的参考上游原文字段，并绑定来源协议与产物哈希；
不同候选消费同一上下文。新校准整图失败不再阻塞其他候选的探针，也不会用新留出
结果生成校准输入。旧 v4 的三个留出任务尚未调用，本轮继续使用其原材料和阈值。

原有严格分层排除规则保留：契约/语义失败或独立评分不可用会排除对应模型分层。
契约拒绝的零分是显式确定性拒绝标记，整层不会进入路由；缺失评审仍为 `null`。
如全部候选不可用，记录无可行路线，继续其他控制组，不补造 profile 或强行降级。

全部计划样本分别记录成功、执行失败、评审不可用和无可行路线；交付率的分母固定为
每组九次运行。质量、成本、时延的条件比较仅使用两组共同评分样本，单列全量用量
和失败结果，避免用失败导致的低成本冒充节省。正收益仍要求对应组全部交付通过及
冻结区间门槛；完整收集到失败或负结果也属于完成实验，不要求必须发现收益。

执行入口仍为 `experiments/run_dag_study.py`，传入 v5 协议。旧协议及原始报告保持原样；
`dag-handoff-v2.json` 只更新当前实现的独立交接回归指纹，真实六种排列包含在 v5 中。

## 用量完整性与校准复用 v6

v5 虽采集了 72 个留出结果，但审计发现单模型 B 一次响应包含未闭合片段、空结束原因
及零 token 记录。旧解析器默认将缺失用量补零，无法由旧归档区分缺失与原端显式零；
它被误标为 billed，因而没有触发冻结的未知用量停止规则。原始证据不改写，新增
[计量审计](../reports/dag-decomposition/issue-32-independent-samples-20260908/usage-audit.json)
明确 531 次用量已确认、一次未确认及对应预留；v5 的比较仅保留为带限制的描述。

修复后，HTTP 响应记录 `usage_available` 与 `raw_usage`。必要计数字段缺失、无效或非空
文本却为零 token 时，不释放预留，不将其当作免费调用，停止整批并保留已归档响应。
正常返回也必须明确 `finish_reason=stop`；其他结束状态在已知用量结算后按无效输出
处理。旧 API 响应中缺失字段的信息无法凭空补回，修复不会追改历史账本。

v6 保持相同阈值、模型和选模算法，换用三个新的留出材料；只复用 v5 的校准部分，
因为其中 36 次整图校准与 84 条探针相关调用均有正的必要用量和正常结束原因。
复用前验证来源索引、逐项产物哈希、任务/重复/约束/模型清单一致性，重新构建的
profile 候选和排除项也必须与原 profile 完全相同。不复用 v5 留出结果，不重新采集
已完整的校准；新增调用上限为 252（六种交接 + 72 次留出结果），新一轮用量单独记账。


## v6 完成结果与验收边界

[用量修复后的真实验证](../reports/dag-decomposition/issue-32-usage-verified-20260908/README.md)
已完成 252 次新调用、六种交接及 72/72 次留出对照，全部交付通过；必要用量逐次核对，
没有未知项，117 条上游输入边与真实父节点产物一致。复用校准的八个可用 profile 条目
及一个排除项完全保持原样，未将已观察留出数据用于调参。

节点 A 相对同一 DAG 的单模型 A，配对平均成本节省 17.98%、质量差 -0.89 分、
时延增加 0.26%；节点 B 相对单模型 B，成本节省 6.21%、质量差 +0.56 分、
时延增加 13.92%。两者及其他预设比较均未达到冻结的联合区间门槛，不能宣布综合收益。

第 4 项在三类能力/风险组合及一个输入预算区间内验收；第 6 项的真实实验及证据采集
验收完成。此前失败状态属于历史轮次，不再代表最新进度；原始失败记录仍保留。
这里的单模型对照是整图统一分配，固定人工 DAG 也不验证自动规划器质量；只有三个
独立留出任务，扩大任务、输入范围或比较优化后的单次调用路由需另行冻结协议。
当前代码及报告尚未提交或发布。

## 有界节点恢复与后续实验

核心已新增显式 `maxNodeFallbacks`，机制和证据字段见
[节点失败后切换模型](text-task-routing.md#节点失败后切换模型)。历史 v1-v6 冻结实验的
零回退规则及真实结果不变；当前核心已经变化，直接加载旧冻结协议应被指纹校验拒绝，
复现旧执行需使用对应报告中的调用前源码归档。离线回归只在临时副本中绑定当前实现，
不会覆盖原协议或绕过生产加载校验。

新恢复实验需至少区分三种规则：不恢复、只恢复失败节点、全任务切换模型后重跑。
各组预先固定最大尝试次数、候选与停止规则，保留全量调用、失败和成功结果；整任务
重跑仍需计入被丢弃的成功分支成本。比较双方应共享授权调用包络、质量标准和最终
评审方式，同时报告实际使用资源。现有六种故障注入仅验收机制，不替代这种真实对照。
