# node-as-tool 当日先导验证

## 目标与范围

回答：需要多个专业职责协助的候选任务中，按需调用专家，相对一次性回答和完整 DAG，
是否出现可核对的事实改进、总费用下降或耗时变化。暂不开发自动／规划模式选择器。

三条路线固定同一 `deepseek-v4-flash`，避免把不同模型的能力差误记成执行方式收益。
这是低风险开发先导，不能推断所有模型、真实业务或正式留出的表现。
任务在执行前按材料分析、约束核对与计算等职责选择，不按路线胜负挑题，
也不预设任务必须拆分。没有使用专家或没有拆图时照实记录。

## 冻结任务和交付

`data/node-tool-pilot-v1/tasks.json` 包含 3 个构造开发任务：

- 采购：报价版本、税、折扣、运费、保修、交期及证书资格同时约束。
- 发布：更新后的依赖、工时、两槽并发、发布窗口及尚未发生的批准。
- 流水与代码：事件去重、载荷冲突、退款余额、pending 与错误代码诊断。

所有路线只收到同一个 `execution_payload` 公共投影；参考答案、结构标签和审查记录不进入执行消息。
模型无文件、命令、网络检索或其他宿主工具；node-as-tool 仅开放文本专家工具。
引用参考位于独立 `references.json`，只供运行后事实检查。自动检查能发现关键字段错误，
不能证明正文语义或参考材料已由独立真人认可。

## 三路线

| 路线 | 执行与记账 |
|---|---|
| one-shot | 一个模型请求直接交付 |
| node-as-tool | DSH 原生主循环按需调用专家；最多 4 次主请求及 3 次专家请求，全部进入父账本 |
| DAG | 既有 Python 紧凑规划器和节点执行器；实时生成最多 4 节点，最多两节点并行；规划费用及等待计入 |

最终输出统一 `answer/findings`。三条路线的主请求、专家、规划器和 DAG 节点均使用模型目录的
完整 **384000 output tokens** 容量，包含思考和最终正文。取消研究自设的 8192／2048／1200
小额度；不通过关闭思考或换模型来规避截断。输入预检按上下文窗口与实际请求计算，
研究保守输入界限为 600000 UTF-8 字节（专家所需材料界限为 32768），输出和输入总和
仍小于已登记的 1024000 上下文窗口。规划账本按实际传给提供方的完整输出容量预留，
不能沿用历史文本协议隐藏的 8192 预留。
专家只显式接收所需文本，不宣称所有路线只有一个上下文或消除了交接损失。
不同执行方式还改变提示与上下文投影，比较的是整体执行方式，不作纯交接损失的因果归因。

三路线的实际 HTTP 请求均须显式携带 `temperature=0`，包括每次规划、工作、最终交付、
主循环及专家调用；`top_p` 与思考参数均保持提供方默认。派发前核对序列化请求，
不能只检查模型配置或 Chat Completions 的默认值，因为 Responses 路径会重新构造请求正文。
Python DAG 保存逐调用原始请求、原始 JSON 响应及关联 ID；并发节点使用线程局部绑定，
避免把先完成的响应错误地关联给另一个节点。DSH 保存对应的原始请求与 SSE 响应。

## 公平性和费用冻结

先用 2 个预先定义的 one-shot 提示候选，3 题各重复 3 次，共 18 次调用。
按关键事实通过数、失败检查数、费用与稳定字典序选择基线提示；不使用后续三路线结果调参。
这个有界开发搜索不等于独立语义审查后的最优提示。三路线再各题重复 3 次，形成 27 个样本。
路线顺序预注册交错，重复不当作独立任务样本。

人类已批准的累计上限仍为 **135 次真实模型请求、286 AFP**，包含全部主请求、专家与 DAG
规划及原批次的失败调用。模型完整容量下，所有未来调用都耗尽输出的费用总和远高于额度；
这只是理论全耗尽总和，不是准许支出。Python 在每次实际派发前预留本次完整输出的最坏费用，
结算后释放差额并继续；不能把模型输出额度压低到小数值以凑齐理论整批总和。
单任务可用预算取理论任务上界与累计剩余额度的较小值，仍由共享账本逐调用保证不超支。
次数剩余不足以覆盖下个完整个案时，不派发该个案，不偷偷扩大 135 次授权。
AFP 为 Ark Agent Plan 套餐用量，不是人民币实付；本批不调用额外付费 Judge。
来源：[官方 AFP 抵扣规则](https://www.volcengine.com/docs/82379/2516283?lang=zh)，核对日 2026-10-29。
只用 `/api/plan/v3`，底层重试、节点模型回退和规划修复均为 0。

用户已批准本先导上限 286 AFP，并明确要求取消造成实验中断的低输出限制；修订继续沿用该累计
授权，不按新目录重新获得预算。预检和演练不读取实际凭证值、不调用真实模型。
真实执行只通过 `CODEX_ARK_API_KEY` 引用取得凭证，不写入产物或命令行。
拒绝复用证据目录；冻结任务、核心、适配器和定价摘要改变时必须生成新协议。
每样本核对源码未变，且实际请求在派发前检查输入、输出、次数及费用包络。
长度不是整批停止条件。SDK 返回错误时先处理真实用量回执，不能因为 `finish:error`
跳过结算而人为制造“未知用量”。完整容量下仍截断的个案保留为未完成运行，不冒充事实错误，
已结算时继续独立样本。无回执、认证、未知用量、
账本或证据写入异常停止整批，保留预留，不自动重试。

## 当天交付与边界

交付原始模型输出、实际工具／DAG 轨迹、用量、费用、任务时间、逐任务事实检查、
翻转矩阵和完整／缺失配对数。研究入口不设置人工总超时或单请求短超时，
不限时语义贯通调度、HTTP、DSH 主循环与专家层；人工取消、模型物理容量、累计费用与次数仍有效。
模型／规划执行计时与进程冷启动外层耗时分别记录，避免把宿主启动误当作模型速度。

没有独立真人语义双审的结果保持 pending；任何已支持的关键事实错误为 fail。
不因机械字段通过而宣称整体质量通过；收益判定保留 `Insufficient-evidence`。
若出现事实改善、过量委派、格式失败、无专家触发或较高费用，均作为有原始证据的先导观察发布。
后续正式留出和模型分配消融需另行冻结，不在这一天先导里扩张。

## 复现入口

默认零模型调用预检：

```bash
uv run python experiments/run_node_tool_study.py --output-dir reports/新的预检目录
```

演练使用 `--frozen`、`--dsh-node-modules`、`--python` 和 `--rehearse`；
真实执行另须 `--execute-paid-run`、精确的 `--approved-protocol-sha256` 与 `--approved-afp 286`。
修订预检传入 `--prior-result reports/node-tool-pilot-20261029-live-01/summary.json`，
冻结原始证据哈希并累计保留那次真实请求和 0.63 AFP 未知用量预留；不得混入新处理组或抹去记录。
接续参数一致的已完成样本，使用 `--resume-samples` 指向已停止批次
（`--resume-optimization` 是保留的旧参数名）；
同时把它列入 `--prior-result`。只允许材料、模型、输出容量、提示及其他执行参数一致、
已经完整结算的样本，逐条绑定原始摘要、个案和实际请求采样证据的哈希；不重放请求。
主判据失败或 JSON 格式错误的已完成交付也必须接续，不能只保留成功答案。
默认产品配置、模型、思考等级、日常额度和标准模型 API 不因本研究发生变化。

## 采样控制修订

`live-03` 的 Native 实际请求为 `temperature=0`，但 Python DAG 的 Responses 请求未显式携带
温度。旧客户端虽然在 Chat Completions 默认正文中设置了零温度，随后重建 Responses 正文时
没有保留这个默认值。因此旧 DAG 与 Native 的差异有采样混杂，不能用来归因路线收益。

修订协议只接续全部 18 个基线开发和 8 个 Native 比较样本，包括原主判据失败的样本；
5 个旧 DAG 样本仅保留为诊断，费用和请求次数照常累计，全部 9 个 DAG 比较重新采集。
旧证据不重写，原来的阶段观察补充醒目标注。

接续后不声称所有配对仍保持最初的交错时间顺序。在新预检时，按来源冻结 5 组
三路线均重新采集的任务—轮次配对，作为时序稳健性补充：发布和流水第 2 轮，全部任务第 3 轮。
这不是按新结果挑选子集；主分析仍保留完整 9 组。流式／非流式适配器、职责提示和上下文
投影的差异仍须披露。本先导比较当前整体实现，不能解释为单一机制的因果证明。

## 长度截断修复验收

旧预检与 `live-01` 原始证据保持原样。那次错误只能证明小输出额度下未完成，不能据此判断模型
或 node-as-tool 质量。官方接口把思考计入输出额度；本地 SDK 把提供方的 `length` 原因映射为
`PI_AI_ERROR`，同时仍产生用量事件。接入层以前在错误路径直接取消，遗漏了结算，属于实现缺陷。

修订必须验证：大于 8192 的配置实际进入请求和费用预留；错误回执带有效用量时实际结算；
SDK 在连接失败时附带的默认零用量不能伪装成已知账单；失败调用和历史预留计入同一累计授权；
原始请求与 SSE 响应落盘且不包含认证头或凭证值。归档不另发请求，不重放原调用。
