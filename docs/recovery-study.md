# 三组恢复对照

本实验承接 [Issue #38](https://github.com/AEALab/RefractRouter/issues/38)。
Python 实验入口已实现；真实模型采集尚未执行，Issue 保持开放。
固定人工 DAG 只支持恢复机制的探索性比较，不能证明自动规划收益或线上可靠性。

## 冻结范围

协议位于 `data/benchmarks/recovery-study-v1.json`。三个新编写的封闭材料任务分别是
归档系统、内部翻译和排班工具选型，每个任务重复两次，比较三组，共 18 个计划样本。
这些场景没有参与既有校准或真实留出测试，但也不是随机抽取的线上需求。
任务文字、验收条目和人工 DAG 一起冻结，不从自然语言推断额外长度上限。

复用 #32 已核验的开发集 profile，不混入历史留出评分。开发集曾排除 `cheap` 的
`synthesis / medium / medium` 分层，原因是 `known-contract-rejection`。
因此所有组初始都使用 `mid`（MiniMax M3），唯一替换候选是 `strong`
（DeepSeek V4 Pro），最多切换一次；不能为增加故障触发而放宽质量准入。
Kimi K3 负责独立最终评审，与生产候选不同。

| 实验组 | 出错后的处理 | 成本与产物 |
| --- | --- | --- |
| `no-recovery` | 停止当前 DAG 派发，等待在途结算 | 保留全部已用费用及失败原文 |
| `local-node-switch` | 按冻结次序替换失败节点 | 复用成功节点，失败节点上游字段及请求不变；切换后为异构路线 |
| `whole-dag-switch` | 结算当前尝试后，用下一个模型重跑同一 DAG | 每次尝试全图单模型；丢弃分支的费用仍保留 |

三组的节点质量代理下限及最终评审下限均为 80 分；最终评审还必须 `passed=true`。
每个样本生产费用上限为 100 AFP，包含全部尝试；总截止为 300 秒，包含最终评审。
节点并发及 Ark 提供方并发均为 2，生产请求最小派发间隔为 100 毫秒。
整图重跑保留之前的派发时间，不重新获得预算、调用次数或截止时间。
最终评审在全部节点结算后单独执行；生产请求的间隔规则不覆盖独立评审调用。

## 失败及停止规则

只有用量完整结算的空输出、非正常结束或节点 JSON 契约错误可以触发换模型。
最终语义评分不达标、长度要求、评审格式错误、容量、预算和截止失败均不触发换模型。
局部切换继续使用已有 `NodeRecovery` 的质量、容量、剩余费用与调度检查；
整图重跑也重新检查剩余资源与整个 DAG 的单模型可行性。下一候选不可行就结束样本，
不会增加临时模型或调整协议。

错误分成两个边界：是否允许同任务换模型，以及是否允许继续其他独立样本。
已结算的结果、评审、容量或截止失败可结束样本后继续；未知用量、认证或其他基础设施、
账本、证据写入异常停止整批。取消不触发模型切换。
所有组共享同一个 `TaskCallBudget`；只有明确分类且完全结算的失败才能恢复下一次派发。
未知用量的预留不能退款，也不能当作实际零费用。

## 零调用预检与验收

```bash
uv run python experiments/run_recovery_study.py --output-dir /tmp/recovery-preflight-new
uv run python experiments/validate_recovery_study.py --output-dir /tmp/recovery-faults-new
uv run python experiments/run_recovery_study.py --demo --output-dir /tmp/recovery-demo-new
uv run pytest
```

每个命令必须使用全新输出目录。预检不创建网络客户端；确定性故障验收禁止网络。
`--demo` 的费用和分数全部是模拟值，不构成真实恢复收益证据。
协议绑定核心实现、清单和 profile 指纹；核心变更后须审阅并建立新的冻结快照，
不能继续使用已经执行的旧协议。

当前真实运行的完整保守包络为最多 108 次调用：生产 90 次、独立最终评审 18 次。
生产上限 **1000.2432 AFP**、评审上限 **737.28 AFP**，合计 **1737.5232 AFP**。
按冻结输入与输出上限、不计缓存折扣估算，实际用量通常低于上限，但此处不作预测。
输入超限在请求前停止；预留用量被提供方实际用量突破时停止整批。
所有预留记录均占调用次数上限，包括派发前取消。

真实执行还要求 `--execute-paid-run`、已获准的 `--approved-protocol-sha256`、
`--max-production-cost` 和 `--max-evaluation-cost`，且双预算覆盖完整包络。
运行器实际仍以冻结包络为硬上限，使用 Ark Agent Plan `/api/plan/v3`、底层零重试。
现有 #32 授权不自动扩展为本协议的新增调用授权。

## 证据与解释

输出保存协议、清单、profile、预检、逐次请求与响应、原始输出、失败类型、模型分配、
派发与结束时序、逐次结算、最终独立评审，以及文件 SHA-256 索引。
每次预留后立即写入状态；重跑前等待在途请求结算。

汇总以全部计划样本为交付率分母，单列未执行数、已结算费用与未知用量预留。
`total_cost` 是累计账本值，包含未知用量预留；中途停止的总额不能当作完整采集成本。
恢复触发次数按结构错误、空输出或非正常结束的节点尝试统计，不是成功恢复次数。
若真实触发为零，只能说明本次样本未观察到可恢复故障，不能估计恢复收益。

质量、成本和时延差值使用相同的已评分任务与重复配对集合；缺失评分不填零。
同时报告排除的配对数，以揭示仅比较成功产物的选择偏差。
区间按独立任务聚类，以种子 38 重采样 2000 次；少于两个已配对任务不生成区间。
三个场景及两次重复只提供探索性描述，不预设显著性或必须取得正收益。
真实错误是自然出现的，各组不保证遭遇完全相同的故障；模拟注入另行解释。
