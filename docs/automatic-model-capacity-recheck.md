# 自动路由模型容量复验

## 目的与边界

用户要求取消执行模型的 8192 tokens 额外上限，再运行原六题的 Direct／DAG 对照。
「不额外限制」仍受模型输出容量、输入与输出共用的上下文窗口、期限和费用预算约束。
不向 API 发送无限数值，也不取消预算、次数、传输期限或未知用量停止规则。

日常 DSH 自动路由已设置 `liveExecution.maxOutputTokens: unlimited`；设置卡片的
「无限制（依模型窗口、Provider 上限与费用预算决定）」已核对为选中。
Ark Flash 的日常 `low`、现金生产 5 CNY／评价 1 CNY、其他模型、凭证和会话保留。

## 新批次合同

保留 `automatic-applicability-v3.json` 原文件与旧结果。新批次的预检内形成
`automatic-applicability-model-capacity-v1`，使用原任务、材料来源、答案标准及顺序。

- 六题各运行 Direct 和 DAG，计划 12 条路线，最多 60 次远程调用。
- 每题最多 5 分钟，规划最多 90 秒；零 HTTP 重试、零回退、零规划修复、零 Jev、无工具或委派。
- 实验快照中的 Ark Flash 恢复 `high`，隔离输出上限变化；不写回日常 `low`。
- 执行模型使用目录容量。规划独立保持 8192 上限；最终评审仍按该模型及实际请求容量处理。
- 每次派发仍先按实际输入和输出上界原子预留，不能在预算不足时先调用再结算。
- 现金与参考估值各硬限 88.4736 CNY；参考估值包含按量费用，两者不可相加。
- 历史现金及独立 Jev 保护额度扣除后，累计 100 CNY 授权余额为 98.59817964 CNY。

目录容量来自已安装的 DSH 适配器；不是本批次重新核验的提供方实际最大值。
若提供方拒绝该容量，记录接口失败，不把配置声明视为真实调用验收。

必要预留不足就停止。因此计划 12 条不代表保证全部可在硬预算内完成。

## 可复现检查

实验宿主只读取原 profile，目录操作显式选择 `model-capacity` 和实验 Flash `high`。
Python 冻结目录、运行库、源码、构建桥接、原始材料及历史账本；执行绑定预检摘要，
使用新输出目录。原 8192 模式默认合同继续保留。

新增无网络检查验证：新目录与旧目录不混用、预算耗尽停止、目录容量真实进入执行调用、
Direct／DAG 调用胶水，以及历史材料和旧协议不被修改。

## 结果

2026-10-08，新批次 `native-capacity-live-01` 执行 5／12 条路线后停止。
11 次远程调用中 10 次确认结算，1 次用量未知。剩余 7 条未派发，不计为模型失败。
已执行路线中 1 条同时通过固定事实检查与模型最终评审；不宣称完整质量验收通过。

|---|---|---:|---:|---|
| 独立上线审查 | DAG | 1 | 7.727 | 规划含非法 `analysis` 节点，阻断 |
| 取消与预留 | DAG | 1 | 10.509 | 规划含非法 `analysis` 节点，阻断 |
| 费用与工具证据 | Direct | 2 | 223.011 | 模型评审 95／通过，但固定事实两项错误，品质不通过 |

两条 Direct 执行分别使用 11953、11678 输出 tokens，超过原 8192 上限，均生成完整正文，
没有 `length` 截断。此前 high 无正文的输入包络题此次通过，说明额外输出上限确实会
阻碍这条路线；不据此声称 high 总是必要，也不把放宽容量等同于答案质量修复。

费用与工具证据题应合计参考费用 0.08＋0.03＝0.11 CNY，现金占用 0.03＋0.20＝0.23 CNY；
模型输出 0.08／0.20，最终模型评审仍误判通过。费用核对表应合计订阅与现金参考估值
0.0036＋0.0144＝0.018 CNY，最终回复仍遗漏现金部分。固定事实门槛没有被放宽。

### 验证与结论

完整 `uv run pytest`：1817 项通过，包含插件契约测试；TypeScript 类型检查、
插件构建及实验宿主类型检查通过。第一次完整测试的 13 项本地 HTTP 监听检查受到
沙箱权限阻挡，允许本地监听后完整重跑通过。DSH 原 profile 界面已确认无限制选项选中，
与修改前解析比较只有请求的 `liveExecution.maxOutputTokens` 一项变化；凭证摘要一致。

取消执行输出额外限制解除部分 high 截断，仍未解决非法规划、费用事实遗漏和
整任务期限内无法完成评审的问题。新批次还使用了已修复的桥接／规划实现，
不能把与历史批次的所有差异都归因于输出容量。后续应针对这三类问题修复，
不靠扩大题集、降低品质门槛或连续重发未知用量调用完成验收。
