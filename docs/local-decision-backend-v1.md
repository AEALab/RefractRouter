# 本地结构化判别后端合同

## 目标与现状

Task、Stage、Advisor、Escalation 与自动路由拆分判别共用一个本地 Judge 进程。
`local-decision-backends-v1` 把后端身份、可执行操作、问题类型和本地权重部署信息
集中在 Python 核心。当前只登记 `laya-mlx`；这份目录表示接口已接通，**不表示某一
权重在某一策略上通过质量验收**。现有 Laya 配置、权重目录与 revision 保持兼容。

不接受配置中的任意 Python 模块名或动态导入路径。新后端须在核心代码中明确登记、
实现并经过审查；未登记 ID 在配置编译或本地派发前拒绝。Jev 云端服务不属于此合同。

## 后端接口

每个后端登记：

| 字段 | 用途 |
| --- | --- |
| `id` | 稳定后端 ID；进入配置、状态键与轨迹 |
| `operations` | 明确支持的任务判别、阶段判断、审核、升级和拆分场景 |
| `questionTypes` | 已实现的 `choice`、`score`、`noul` 等问题形式 |
| `artifact_files`、`manifest_name` | 本地权重完整性与固定 revision 核对 |
| `dependency_module`、`allowed_sources` | 本地依赖和明确下载来源 |
| `factory` | 核心登记的本地加载器；配置不能提供代码路径 |

加载器返回具有相应判别方法的对象。工作进程只按已登记操作调用方法；各方法继续返回
`payload`、实际模型、冷启动、延迟和用量。Python 策略仍负责问题版本、结果校验、
预算、候选资格与最终路由；后端不得自行执行工具或选择未经策略准入的模型。
常驻实例键包含后端 ID、模型来源、权重 revision、目录、装置、精度与方法，避免不同权重
误用同一已加载实例。

DSH 可通过 `local-backends` 查询目录，再根据 `operations` 展示已接通选项。
插件只传递后端 ID 与本地模型配置，不在 TypeScript 中维护另一套后端能力或质量规则。
目前设置页仍以 Laya 为唯一现成选项；新后端完成后才在界面开放相应选择。

## 接入更强本地模型的步骤

1. 冻结模型来源、权重 revision、运行时版本、实际 tokenizer 容量和本机资源要求。
2. 在核心登记后端 ID、支持的操作与权重清单，并提供本地加载器。若不是权重目录形式，
   先为该部署形态补充明确的就绪、取消和恢复合同，不套用 MLX 文件检查。
3. 对每个要开放的策略实现独立问题模板与结构化响应映射；不假定不同模型的分数可比较。
4. 使用固定题集验证判别质量、误放行、无法判断、中文／英文、冷暖延迟与容量处理。
   未通过的策略只可保持实验状态，不能因为后端支持该操作就默认启用。
5. 在 DSH 设置中提供已登记后端的选择与状态说明；回归旧 Laya 配置、轨迹、取消、
   未知用量和工具续接。真实付费实验仍按单独冻结范围授权。

自动路由当前 Laya 拆分题集只有 7／18 正确；见[原始验收](../reports/decomposition-local-20260930/README.md)。
更强权重接入后须重新验收本场景，不能沿用 Laya 的质量结论或调整门槛代替验证。
