# 审核、返工与接管的完整费用审计

对应 [W07 / #208](https://github.com/AEALab/RefractRouter/issues/208)。Advisor 与 Escalation
分别比较相同执行模型、相同首请求的无审核路线，沿用已有严格状态机。
本包提供离线审计、确定性约束检查、冻结的条件触发研究候选及可重放证据；
没有改变现有产品审核次数、默认值、工具执行或模型选择。

## 先把费用算完整

`review-benefit-audit-v1` 读取 #203 的 `task-result-v1` 和原逐调用账本，复用
`whole-task-cost-observation-v1` 核对逐调用金额与总账。

完整费用包含全部执行、返工、接管、压缩和审核尝试，包括失败和被丢弃的候选。
`execution`、`review`、`other-managed` 是互斥的费用分区。
`discardedExecutionSubset` 是执行分区的子集，不能再次加进总费用。
没有派发的预留不是已消费；已派发但用量未知仍保留保护金额。
任一侧用量未核清或费用维度不同，配对节省比例保持未知。

现金计价与订阅参考估值分开，CNY、USD、AFP 不直接相加。
这些记录仍不能证明供应商实际扣款；实际扣减须另行对账。
主要配对先检查首个执行的 provider、实际模型、输入摘要、思考和输出合同相同。
项目来源独立、宿主/工具快照相同及完整实验设计仍由 #210 冻结并核验，
单个费用配对不自行签发来源独立性或发布资格。

## 分清模型判断与独立验收

每个裁定绑定候选 ID、全文 SHA-256、评分规则 SHA-256、范围和原始裁定记录摘要，
并须在独立评估通道中有匹配的活动事件。重复、冲突、错绑、部分字段通过或模型多数票
不能作为完整金标。导入方仍须保证裁定来源可信；摘要本身不认证人类或证明语义正确。

最终答案使用 `complete-delivery-and-requirements`，工具候选使用
`candidate-next-action`，正常工具探索不会因尚未完成全文而被判错。
模型自报 APPROVE、PROCEED 或用户反馈均不能替代独立验收。
材料缺失或裁定未决时保留 UNKNOWN，不当作正确交付。

| 指标 | 口径 |
| --- | --- |
| 漏放 `falseAllowed` | 独立判定错误的候选实际被 Router 放行；包含未达接管阈值的 STALL。 |
| 误干预 `unnecessaryInterventions` | 独立判定正确的候选被丢弃，且实际触发对应返工或接管。 |
| 已知失败的修复尝试 | 被干预的具体候选确实为 FAIL，实际生成对应替代候选。 |
| 修复成功 `repairedKnownFailure` | 对应替代候选完整通过，整任务最终候选也通过；不拼接别轮的错误与干预。 |
| 审核无有效判词 | 记录实际审核调用，即使解析失败、取消或没有生成有效 decision。费用仍计入。 |
| 完整质量 `quality` | Router 选中的最终 stop 候选及任务结束状态满足要求，再采用其独立全文裁定。 |

返工/接管按同一宿主请求、具体 Judge 之后的首个对应执行建立 `repairEpisodes`。
若替代候选仍为工具步骤，或历史缺少足够关联信息，就报告结果/归属未知；
不能把其他请求后来答对推断为本次干预成功。
`routerFinalSelected` 与独立验收、客户端实际收到内容是不同记录。
审计保留 `transportDelivery: unknown`，不靠 release 推定用户已看到答案。

所有冻结任务都进入实验分母，失败、未知和超时不能被剔除后再计算节省。
审计输出只给出原始逐调用及任务时间；本地重放或小样本不报告 P95。
最终审核无法撤回宿主已经执行的动作；工具过程审核和最终审核的边界必须分别观察。

## 确定性检查与条件触发

`mechanical-delivery-check-v1` 复用既有 Unicode 码点/UTF-8 长度检查，
并检查明确要求的 JSON object；重复键、非有限数值、数组和非法 JSON 均拒绝。
这些机械检查不会重写原文，也不会输出“整题正确”：通过后语义仍为 UNKNOWN。
没有请求机械约束时，不把“没有失败”当作完整机械通过。

`review-trigger-research-v1` 仅供研究调用，尚未接入产品路径。
它冻结用途、精确评审身份、资格材料摘要、开发样本身份、允许类别、频率和次数；
不接受留出样本、答案、评分或未知字段进入触发配置。
输入的资格材料必须与冻结摘要及用途/后端完全一致，缺资格即停止该研究配置。
资格文件由受信研究导入方提供，不能用自填的 qualified 字段冒充独立校准。

- strict 模式每次要求审核，达到次数上限即停止，不静默跳过。
- conditional-research 只在明确类别、机械检查通过、已有审核且符合冻结频率时
  输出 `unreviewed`；这不是批准，`approved` 和 `productionEnabled` 始终为 false。
- 首次审核、返工复审、未知类别或未请求机械检查仍要求审核；配额耗尽停止。
- 机械检查失败可以产生研究用 block，不增加语义调用，也不自行执行返工或工具。

当前没有新增真实评审后端取得这条触发路线的资格，条件触发继续保留为研究候选。
现有产品严格审核继续沿用原合同；不能为了降低费用把审核故障改成批准。

## 零调用重放

```bash
uv run python experiments/replay_review_benefit.py \
  --source data/review-benefit-v1/cases.json \
  --output-dir /private/tmp/refractrouter-review-benefit-新目录
```

入口无付费开关；使用真实 Python 核心状态机、固定回执和本地构造标签，
不调用真实模型，不加载本地判别模型，也不执行宿主工具。
来源及源码摘要、实际 Git 版本和工作区是否干净都会保存；不覆盖旧目录。
研究重放依赖匹配的源码环境，不是新的标准模型 API 或任意 Agent 兼容证明。

12 组构造配对覆盖：批准正确/错误、返工与复审、未知和无效判词、单次接管、
误接管、工具候选丢弃、跨轮错误归因及 STALL 的实际放行。
独立审查发现的两项归因反例已加入正式回归。
标签只在固定执行脚本结束后进入独立评估通道，不作为路由回退条件。

以下数值来自构造回执的模拟标价，真实研究支出为 0，真实独立任务数为 0：

| 模拟路线 | 配对数 | 最终 PASS / FAIL / UNKNOWN | 漏放候选 | 误干预候选 | 修复任务 | 无审核模拟费用 | 审核路线模拟费用 |
| --- | ---: | --- | ---: | ---: | ---: | ---: | ---: |
| Advisor | 5 | 2 / 1 / 2 | 1 | 0 | 1 | 0.00070 | 0.00252 |
| Escalation | 7 | 5 / 1 / 1 | 3 | 2 | 3 | 0.00126 | 0.00658 |

模拟费用单位为 CNY，不能计入真实现金账本；这些构造错误也不能估计真实模型的错误率。
逐调用 10 ms 是固定夹具值，任务墙钟是本地重放耗时，未观测真实模型时延。
UNKNOWN 可能是证据不足、审核故障或没有最终答案，逐题原始状态保留。

## 阶段结论

现在可以一致地检查审核有没有漏记费用、漏放错误或误把干预算成修复。
真实审核净收益仍未证明，触发变更继续保持实验状态。
#210 应在相同执行模型、工具和交付要求下分别比较两策略，计入全部在线审核，
独立研究评分另列并报告项目总支出；明确质量回退即停止该配置扩量。
没有合格评审或净收益证据时，不启用条件审核，也不借免费完美审核替代真实路线。
