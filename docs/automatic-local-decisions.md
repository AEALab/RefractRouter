# 自动路由的本地有限选项判别

状态：首批拆分前判别已接入自动路由；固定权重的专项质量验收未达标，继续标为实验。本文承接自动路由现状核对及
用户关于将本地 Laya-MLX 等结构化判别模型用于拆分和快速有限回答场景的要求。

关联 [Issue #113](https://github.com/AEALab/RefractRouter/issues/113) 的执行接入工作；
不改变该 Issue 独立研究验收依赖 #112 的要求。

## 定位与职责

把本地结构化判别作为 Python Router 的可选能力，用于回答边界清楚、选项有限的问题。
当前实现优先复用 Laya-MLX，后续后端通过独立适配器接入。Laya 与 Jev 的接口设计相近，
不据此认定权重、分数、性能或质量相同，也不需要接入 Jev 云端。
后端注册与替换要求见[本地结构化判别后端合同](local-decision-backend-v1.md)。

Router 仍按数据域与能力准入、可接受质量、总模型费用、等待时间的顺序决策。
本地判别提供语义证据；确定性规则负责资格、费用、预算与派发。
任务内容和工具正文都是待判断材料，不能更改问题定义或指示 Router 绕过规则。

具体 DAG 的节点描述由规划模型生成，图合法性、依赖和费用由 Python 核验。
工具执行、权限、上下文管理和任务推进继续属于宿主。显式 DAG 工作属于独立研究入口，
不因增加本地判别而进入标准模型 Base URL 的原生 Agent 循环。

## 使用场景与交付顺序

| 场景 | 有限选项示例 | Python 如何使用 | 优先级 |
| --- | --- | --- | --- |
| 拆分前的结构判断 | 可分离／强依赖／不明确 | 决定是否值得进一步支付规划调用 | 首批 |
| 已有子任务的依赖判断 | 依赖指定上游／可独立／不明确 | 为候选图检查提供线索，不直接删除依赖 | 后续 |
| 执行类型识别 | 读取／抽取／计算／生成／混合／不明确 | 在合格候选中辅助选模，不执行或授权工具 | 后续 |
| 候选模型适合度 | 适合／不适合／证据不足 | 复用候选资格和成本规则，按具体任务验收 | 后续 |
| 有界异常分流 | 正常探索／疑似任务困难／不明确 | 结合可信状态决定维持路线或进入已有恢复流程 | 后续 |

每个场景使用自己的版本化问题和验收条件。不能因为某一场景通过，就将本地后端标为
通用合格评审器。数据域授权、已确认的工具退出状态和硬预算不能由本地模型覆盖。
本版不以结构化 Judge 替代 #112 要求的本地任务执行器或独立质量评审。

## 首批：拆分前判别合同

已新增 `decomposition-decision-v1`，先只回答任务结构问题。当前固定版本在同一个
Laya 推论批次中询问两个 `Noul` 问题：后一步是否必须读取前一步的实际结果；是否有
至少两项实质工作可独立开始。Python 根据这两个原始分数与门槛组合下列结果：

> 用户要求中是否有可分别完成的实质工作，还是主要工作必须依赖前一步的结果？

| 选项 | 含义 |
| --- | --- |
| `SEPARABLE` | 存在可分别处理的实质工作，之后可能需要汇总 |
| `COUPLED` | 工作紧密相关，主要步骤依赖前一步的结果 |
| `UNKNOWN` | 上下文、材料或要求不足以可靠区分 |

选项不包含“更便宜”“保证质量”或“必须拆分”。这些结论需要实际模型资格、容量、
调用包络和成本资料，不能由一项语义分类推出。短输入也可能可分离，长输入也可能强依赖；
“分别”“比较”等词只作为输入线索，不单独决定 DAG。

请求至少包含：任务身份、合同版本、问题与选项、实际用户要求、必要材料引用及完整性、
宿主提供的相关约束、输入摘要、后端及权重 revision、期限和容量限制。
保留影响解释的系统或开发者约束；不把全部技能目录和无关历史直接拼入模型输入。
附件内容不可见或任务依赖的历史未提供时，完整性必须明确标记。

响应保存两个原始 `Noul` 分数、组合结果、后端实际版本、容量检查结果、实际 forward 次数、
排队及推论时间。低于按场景确定的门槛时，Python 得出有效结果 `UNKNOWN`，并保留原始答案。
原始分数及组合分数不得标为正确率或任务成功率。
当前产品初值为 0.65，低于门槛统一归为 `UNKNOWN`；该值必须在有限开发案例后重新冻结，
不直接复制 Stage 的 0.8／0.9，也不事后降低以提高通过率。

## 与两级选择器的协作

1. 先处理配置、数据域、容量与预算等硬条件，以及显式 `dagMode`。
   已明确指定直答或研究强制拆分时，不增加这次可选判别。
2. 已启用“规则＋本地判别”且使用自动策略时，宿主在预检前提交一次本地任务级判别；
   强制直答或强制 DAG 不增加判别。预检与真实执行复用同一结果及输入摘要。
3. Python 将判别作为带来源和不确定性的结构信号，结合真实候选的价格、能力与容量，
   决定是否调用 planner。`SEPARABLE` 不自动触发拆分，也不保证能并行执行。
4. 当前真实自动路由入口仍使用既有复杂度门控；本地结果只影响是否进入 DAG 路线。
   候选图的完整费用、依赖与时延比较尚未接入该入口，不能把当前拆分判断解释为
   已证明有净收益。
5. 后续接入完整两级选择器时，再核验候选图的并行机会、规划与合流开销、费用和
   端到端时间；涉及数据隔离的硬条件继续优先处理。

`RouteFeatures` 已增加带来源的离散结构证据，未把分类分数填成所谓“独立度概率”
或“并行比例”。当前规则映射为：`SEPARABLE` 增加规划探测信号；`COUPLED` 增加结构阻断；
`UNKNOWN` 保留原规则。完整 DAG 的依赖密度和关键路径仍应从验证后的图计算。

## 无法判断和故障

- 正常返回 `UNKNOWN`、必要输入缺失或超容量：记录原因，退回现有规则；只有原本合法且
  能承接任务的直答路线才可作为默认。不能将“未知”自动当成高效模型足够或必须拆分。
- 显式启用但本地模型未就绪：在付费调用前提示加载或由用户改为规则模式。
- 超时、进程崩溃、取消和无效响应：停止该次受影响流程，保留错误；不自动重发、转云或
  将迟到结果用于推进状态。
- 模型未下载时不隐式下载；实际 tokenizer 校验任务、问题与选项的总长度，不依赖截断。
- 不为取得本地容量而增加隐藏的生成式摘要调用。

## 延迟与状态

首批每个任务最多一次本地判别批次，同一批次不依赖前一道答案再问下一道。
默认不在每个 DAG 节点前重复判别；后续若增加节点场景，需独立的次数和期限限制。

复用 `LocalJudgeProcess` 常驻服务，新增拆分操作和独立适配方法；同一实例串行推论，
排队时间纳入任务与判别期限。同一次 DSH 请求的预检与真实执行共用结果及输入摘要，
不重复推论。跨请求持久缓存尚未实现，新请求仍可能重新判别。

记录整个决策边界的耗时：输入准备、tokenizer、排队、实际推论和结果校验；分别报告
冷启动与暖机 P50/P95、有效判别覆盖率及总调用链等待。
已有 Stage 短案例延迟仅作参考，不作为新场景的速度承诺。
本地推论记录无 API 费用、次数、耗时与可获得的资源指标，不把硬件使用成本视为零。

## 设置与轨迹

自动路由自己的设置已提供“规则”和“规则＋本地判别”选择，后者标为实验。
显示本地模型、revision、就绪状态和本次启用的具体场景，不修改规划路由各策略设置。

每次轨迹显示是否使用本地判别、跳过或失败原因、有效答案、两个原始分数、
模型版本、排队／推论耗时，以及 Python 最终选择直答还是进入 DAG。
例如：“本地判别为强依赖；只有弱词法规则要求拆分，因此选择直答。”
原因由答案、核验结果和规则组成，不伪造本地模型生成的解释。

## 有限验收与完成标准

先用确定性结果验证合同、同请求复用、超容量、取消及迟到结果，并覆盖所有可能分支。
再使用固定本地权重执行独立的结构判断题集，包含中文、英文、混合语言、短任务负对照、
长但强依赖任务、可并行分支、依赖附件或历史的任务，以及材料中的指令干扰。

分别记录误建议规划、漏掉可分离任务、无法判断、硬边界违规、有效覆盖和端到端额外等待。
只选一个场景完成有限验收，再决定是否扩大用途；不通过则保留该场景实验状态，
不反复增加样本、降低门槛或把其他策略的通过结果当作替代。
真实云端规划／执行验收按新冻结包络核价，本地推论验收不等同于云端付费范围授权。
