## 已证实的问题与修复边界

1. 两个规划使用 `cost-calc`、`case-eval` 等带连字符的 ID；核心只接受
   `[a-z][a-z0-9_]*`，原提示没有明确说明。这是可修复的合同提示缺口。
   本批结束后已补充格式和父节点引用说明，校验规则未放宽；修复不混入本批结果。
2. 一次规划使用 `analysis` 类型，虽原提示已列举合法类型，模型仍违反合同。
   需要进一步验证该路线支持的结构化约束，不能悄悄把未知类型映射为可执行节点。
3. 八条执行消耗输出上限后没有可交付正文。终止用量确实可核对，
   但不能据此认定所有 token 都属于推理、故障由高推理等级造成，或模型一般能力不合格。
   当前自动路由目录编译记录 `reasoning_effort=default`，宿主目录声明默认 `high`；
   尚未进行显式不同推理参数的因果对照，不通过扩大输出或期限掩盖问题。
4. 费用面板 Direct 的模型评审给出 96 分并通过，但 `knownReferenceCny` 为 0.0036，
   按冻结源码 `reference_cost_cny` 的定义应合计订阅与现金已结算估值：
   0.0036 + 0.0144 = 0.018。固定事实检查判失败，没有把高分当作正确证明。
   后续题目和评审说明可明确这个字段定义，须以新版本记录，不能追改本批标签。
