# v4 两级自动路由选择器

本阶段为 [RefractAgent v4 配置合同](refractagent-v4-config.md)增加 Python 自动路由求解器，
并接入真实执行中的规划后路线比较。选择计算本身零额外模型调用；进入 DAG 探测时的
planner 仍是实际调用并照常计费。它实现 Issue #116 的 direct-or-DAG 估算切片，
不改变 DSH 插件职责，也不把估算结果描述为已经验证的生产收益。

## 两级判定

第一级 `first_level_gate` 判断是否值得支付一次 planner 调用。固定特征只表达调用前可见的
结构信号：子任务独立度、可并行工作比例、敏感与公开材料是否混合、合法模型价差、直接路线
是否已经低成本、依赖密度和汇合风险。门控输出保存策略版本、阈值、命中信号和阻断原因；
这些阈值是可审计规则，不是校准概率。

默认直接回答。只有安全放置、合法模型价差或可并行工作表明 DAG 可能有净收益时，才允许调用
planner。高依赖密度或高汇合风险会阻断一般成本、并行信号；安全隔离需求仍可进入第二级，
因为安全可行性不能被费用或结构风险抵消。`dagMode: never` 始终跳过 planner，`force` 仅用于
研究对照。

第二级 `choose_route` 在 planner 已形成候选图后比较完整的 direct 与 DAG 路线。此时 planner
是两条已实现流水线的共同探测开销：DAG 记录为 `planner`，回退 direct 记录为
`planner_probe`。第一级门控负责让简单任务在探测前直接回答，避免支付这笔开销。

第二级比较遵循：

- 先按模型职责、敏感材料放置、上下文和输出容量、`qualityMin` 硬门槛过滤候选，并按原因
  记录排除计数；
- direct 计入 worker 与最终 judge；
- DAG 计入 planner、每个 worker、最终 judge、工具续接和有界备用尝试；备用尝试在调用前按
  当前候选的同一 envelope 保守计数，实际异构切换费用由后续运行账本回填；
- direct 与 DAG 的 judge 分别接收独立估算，避免把两条路线不同的汇总上下文错误视为相同；
- 重复上下文由每次调用的 `CallEnvelope` 显式传入，不从节点名称推断；
- DAG 时延使用共享列表调度器计算关键路径，不把节点时延简单相加；
- 优先比较含风险余量的总边际成本，成本在容差内相同时再比较时延；
- 任一必要职责没有合法候选时返回 `infeasible`，不派发调用。

调用方可以提供更精确的 planner 或 judge 估算，但不能把其所见输入从敏感等级降为公开等级；
这种输入在求解前直接失败，不允许通过便宜的外部模型绕过安全放置。
研究用 `force` 在 DAG 缺失或不可行时返回 `infeasible`，不会静默退回 direct 而污染对照组。

## 费用与预测语义

`CallEnvelope` 是调用前估算，不是实际账单。每项估算记录单次输入、缓存输入、输出、续接次数、
备用调用次数和可选时延。模型有路由预测时使用其声明值；缺少时延预测时必须由调用方显式提供，
不得用常数静默补齐。

结果同时保留：

- `marginal_cost`：求解器用于比较的边际成本；
- `actual_cloud_cost`：按声明价格估算的真实云端支出；
- `cost_with_risk_margin`：仅用于 DAG 准入的边际成本与风险余量之和。

`simulated-local` 的边际成本仍可按研究合同记为零，但其声明云端价格进入
`actual_cloud_cost`。两者不得混用，也不能把零边际成本解释为物理本地执行。

## 审计结果

选择器返回可直接写入运行证据的结构化记录，包括策略版本、目标、状态、路线、原因、各职责被
排除的候选数、模型分配、每次调用估算、总费用，以及 DAG 的关键路径。当前模块只负责确定性
求解，不读取测试答案、不调用 provider，也不执行节点。

## 真实执行接线

v4 自动策略在预检时使用 `live_execution.complexity_gate` 决定是否支付规划调用。
`dagMode: never` 在预检直接采用整任务执行；`force` 保持研究用强制 DAG。
普通自动模式只有任务明确要求分别或独立处理时，结构规则才建议支付规划调用；
Jev 判别为 `SEPARABLE` 也可建议规划。任务文字较长、存在工具调用、验收条件、
严格输出格式或多份材料，本身都不证明工作可独立拆分。若 Jev 判断为 `SINGLE`
或 `COUPLED`，则直接执行；工具权限与最终审核仍独立检查。
普通 `auto` 若进入规划，真实 planner 产生图后，再用 `compare_executable_routes`
比较两个已完成能力、容量、数据域及质量准入的执行候选。决定为 direct 时，
运行记录标为 `direct-after-probe`，只派发整任务执行器；规划调用作为已发生费用仍入账。
决定为 DAG 时继续原节点调度。该步骤不调用额外 Judge，也不执行候选图的节点作为探测。

这项比较使用本次编译的模型／推理档位画像、实际已结算的 planner 费用、同一最终审核
输入包络、宿主工具续接的有界保守额度及共享调度器的 worker 时间预测。
费用按当前账本单位比较；执行和工具额度从生产账本检查，最终审核额度从评审账本
单独检查。预测没有不同 Judge 的效果校准，也不跨 AFP 与现金换算。
无法预先界定工具调用次数或启用未验收的选择性上下文时，记录 `unavailable` 并保留
已通过准入的 DAG。整任务输入超过容量时，标明 direct 不可行，不阻断合法 DAG。
比较结果保存候选分配、排除原因、各项费用估算和选择原因，并由 DSH 显示。
规划后选路把已结算的 planner 费用视为两条当前可执行路线的共同费用；另外保存
`dag_net_estimated_savings_vs_unprobed_direct`，用未支付 planner 的原始 direct 路线
作基线，检查 DAG 的预计节省能否抵消探测开销。AFP 与 CNY 混用时分别保存两个单位的
预测差额，不将订阅点数当现金相加。该字段仍是预测，不能据此宣称实际节省或质量等同。
真实运行从既有调用账本被动记录被选路线的预计费用、实际结算、待核对预留、
模型评审及宿主工具回执检查结果，
无需用户点击或额外模型调用。观察库按路线和计费单位给出已完成、无待核对运行的
预测／实际费用比 P90；自身模型评审仅是质量线索，未执行路线没有实测反事实。
因此这批记录可用于发现费用预测偏差，尚不能单凭它证明 DAG 比 direct 更省钱。
若规划器返回的候选计划只有一个节点，即使该候选的预测费用优于通用 direct 模板，
运行记录仍将实际路线归为 `direct`，并标明选中的是「规划器单节点候选」。已发生的
规划调用继续计费；单节点不会计入多节点拆分覆盖。审计同时保存规划器节点数、
最终选中节点数和是否形成多节点拆分，避免把一次规划调用误计为 DAG 执行。

当前 v4 live 仍要求 `synthetic` 数据模式，只接受 USD／CNY 模型池，并要求规划修复、
动态再拆和节点回退均为零。执行路线的用户声明质量和时延是预测，未通过独立留出样本
校准；因此只能声称路由选择与账本功能已接线，不能声称真实任务质量或净收益已经验证。

已纳入[本地有限选项判别](automatic-local-decisions.md)：复用 Laya 常驻服务，
先实现拆分前的结构判断。DSH 在预检前取得一次结果，预检和真实执行绑定同一输入摘要；
Python 将离散证据与请求结构规则合并。该能力仍为实验状态，不能以已有 Stage 的功能或耗时
验收替代新场景质量验收。本地固定权重的多用途结果见
[专项验收](../reports/local-jev-multiscenario-20260930/README.md)。

运行期安全合同的完整覆盖核对、预测与实际账本对照、预测误差校准及
独立留出实验仍需逐项交付。DSH 插件只传递配置和展示结果，
不在 TypeScript 中复制路由、评分或预算逻辑。
