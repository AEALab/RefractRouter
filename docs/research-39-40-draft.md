## 验证问题

- [#39](https://github.com/AEALab/RefractRouter/issues/39)：固定人工 DAG，比较节点 A/B 与同图单模型 A/B，
  分开观察能力类型、输入规模和风险条件。质量基准、强模型串并行与整任务 A/B 是辅助对照。
- [#40](https://github.com/AEALab/RefractRouter/issues/40)：区分人工、每次自动规划、缓存自动计划和整任务 A/B；
  冻结交付条件，规划语义与最终交付分别评分，缓存规划也计入设置成本。

两项研究使用不同任务 ID 和随机种子，均划分开发、校准和测试材料。
每格包含 1 个开发、3 个校准、3 个测试参数抽样，测试重复两次。
#39 有 8 格、24 个测试抽样；#40 有 7 格、21 个测试抽样。
每次重复不是新独立任务。

## 当前材料的局限

材料由固定模板生成，包含来源编号、价格、数量、风险限制和可复算费用。
长输入包含 90 条费用记录，并检查实际消息大小，不能只修改输入容量标签。
人工串行任务要求根据费用计算预算缺口，确保依赖对应真实用户要求。
规划草案包含并行、必要串行、强耦合、短任务、过度拆分、汇总瓶颈和交接遗漏条件。

**随机种子独立不等于任务类型独立。** 当前只有费用风险比较与短句改写两个模板族，
校准与测试共享模板。正文哈希及来源 ID 去重只能排除完全重复，不能完成语义近重复审查。
预检因此固定输出 `independent_task_transfer_verified=false` 和 `live_execution_ready=false`。
这些材料适合检验研究流程，不能据此关闭 #39 或 #40，也不代表团队真实任务分布。

当前样本数规划假设任务级质量差标准差为 10，目标均值半宽为 5；
两个主比较使用 Bonferroni 校正，正态近似要求至少 21 个独立任务。
这只是样本量规划假设，不能把当前模板变体当成已经满足独立任务要求，
也不保证实际区间精度。每格三个抽样不足以作精确分层或尾延迟判断。

uv run python -m experiments.preflight_research_studies \

入口没有付费执行选项，也不创建模型客户端。历史协议和原始报告不修改。

## 统计入口

`research_analysis.compare_research` 接收预检计划和显式观测记录：

- 所有计划运行进入交付分母；未运行或缺失记录不能被删除。
- 未知费用不补零；报告已知小计，完整费用和首次使用费用保持未知。
- 质量、费用与真实墙钟时间差使用相同配对集合；已有有效评分的质量失败仍纳入。
- 先对同一任务的配对重复求均值，再按任务重采样，输出 97.5% 区间。
- 单独输入校准、搜索及缓存设置费；缺少设置费时不声称首次使用成本已知。
- 拒绝重复记录、变更分层、非有限指标和无合格评分的成功交付声明。

该入口不执行模型、不推断人工复核通过，也不自动声称收益成立。
共同配对统计必须连同全计划交付率和全部失败费用阅读；条件于可评分样本的差值不能替代端到端结论。

## 距离真实实验仍缺什么

1. 明确目标真实任务分布，补充独立来源及人工近重复审查；保持开发、校准与新留出材料隔离。
2. 开发执行器已接入共享账本、独立节点探测、整任务 A/B 校准、自动规划归档与语义评审、
   缓存设置费及失败隔离，并通过无网络演练。仍需正式实验矩阵编排、实际异构交接、
   质量与并发对照、成本分类和证据驱动的完整验收；开发演练不能替代这些步骤。
3. 在最终消息契约确定后重新计算调用与费用包络，冻结实现及协议，再取得明确付费授权。
4. 执行真实实验并审计全部失败分母；#40 按冻结抽样规则取得真实成员的人工复核，不能由模型替代签署。
5. 对完整证据作范围受限的结论，再回填 #1、#22、#8；不替代既有 v0.1 结果。

此前 #32 或 #38 的授权不自动成为这两项新研究的付费授权。
用户随后已明确授权本次真实调用并免逐项预算确认；执行仍保留本地调用包络、Ark 限制、
零重试和完整记账。已完成的 48 次真实调用共消耗 52.3174 AFP，
见[真实先导及缺陷修复](../reports/dag-decomposition/research-live-pilot-v1-actual/README.md)。

## 开发执行演练

```bash
uv run python -m experiments.rehearse_research_execution \
  --output-dir /tmp/research-development-new
```

该入口强制禁用网络，用三份草案校准材料作为开发夹具，另用一份开发任务检验执行路径。
没有运行草案 test 材料；生成的 profile 为 `synthetic`，不能用于实测结论。
演练包含整任务校准、固定上下文的独立节点探测、节点 A 与同图单模型 A、
固定强模型人工计划及自动规划、一次计划设置和两次复用。
固定强模型对照不会标成节点 A/B 路由。

`ResearchSession` 可接入现有零重试客户端，但没有对外的正式付费 CLI。
所有调用共用一个 `TaskCallBudget`，累计费用和调用计数不因样本失败重置。
结构合法但语义评审失败的计划继续执行以观察错误传播；结构不合法的计划拒绝且不修复。
缓存设置失败后复用保留失败，不悄悄重新规划。未知用量、证据故障或缓存变更停止整批。

开发记录的 `deployment_cost` 暂含本次样本全部生产和评审费用；正式研究仍须拆分
部署必要评审与仅实验评审。节点探测、缓存设置各在 `probe_runs`、`plan_setups` 中另列，
必须与 `runs` 一起核对总账。正式付费准入和关闭判断不能直接使用开发结果。
