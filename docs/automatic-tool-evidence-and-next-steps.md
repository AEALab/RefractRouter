# 自动路由工具验收与后续工作

## 当前客户端范围

根据 2026-10-06 用户确认，当前产品支持与后续验收聚焦 **DSH、Codex**。
Hermes 暂缓，不作为本轮交付依赖；已有兼容代码与历史证据保留。

## 本次修复

关联 [Issue #178](https://github.com/AEALab/RefractRouter/issues/178)。旧运行中，用户要求
先用 Bash 执行 `printf 7`，模型没有调用工具却回答 7，最终 Judge 给出 95 分。
根因是评审输入只有任务、答案和验收条目，没有实际宿主工具记录。

新版采用两层检查：

1. Python 从当前用户任务与显式验收条目识别肯定式工具要求，核对本任务回执。
   没有对应工具回执时记录 `tool-requirement-failed`，停止最终评审；候选留在审计中。
2. 有回执时，将真实工具名称、参数、内容、结构化结果提供给最终 Judge，继续检查
   操作与结果是否满足原任务。调用一个无关工具不能证明任务完成。

第一层是保守的常见指令识别器，不是完整自然语言证明器。它跳过明确否定、可选、条件式
和引用示例；未识别的复杂表达仍由带工具证据的语义评审判断，不宣称所有表达均可确定识别。
只读取当前用户任务及其显式验收条目，不从宿主系统提示或引用材料创造工具要求。

## 结果语义与边界

| 证据 | 含义 | 验收处理 |
| --- | --- | --- |
| `completed` | 宿主确认命令正常退出 | 继续评审具体操作及结果 |
| `task-failed` | 命令实际执行并非零退出 | 交由 Judge 检查任务是否本来要求观察／报告失败，不当成成功 |
| `returned` | 宿主返回结果，未提供命令退出状态 | 只能证明收到回执，不能据此断言退出成功 |
| `denied` | 宿主权限拒绝或未派发 | 要求未完成，不补跑、不绕过审批 |
| `infrastructure-error` | 认证、传输或基础设施失败 | 不当成有效完成的操作 |
| `unclassified-error` | 宿主报告错误，缺少可信来源 | 不从正文推测成功 |
| `unconfirmed` | 无法确认结果 | 停止后续验收，不自动重发 |

工具执行、权限与错误回执归宿主。Router 不生成替代执行记录，不从候选正文或工具正文
解析“执行成功”作为可信状态，不新增工具调用或重试。

早期冻结合同采用 16 KiB 包络，按嵌套 JSON 序列化计算，预检和最终评审费用保护采用
同一上界。超过上界明确停止，不静默截断或增加摘要调用；旧合同与历史证据继续保持原样。
AFP／CNY 仍各自记账；未派发评审释放保护额度，已执行模型费用照常保留。
完整工具材料进入评审前重新检查资料域；安全审计只写调用身份、状态及证据哈希。

本次接线为 DSH 自动路由。核心合同不依赖 DSH 类型，但标准模型 API 不进入 DAG。
Codex 的工具证据须按其接入合同验证，不能把本次 DSH 通过扩展成 Codex 自动路由已验收。
Hermes 验收暂缓。旧运行与旧质量分数保持原样。

## 2026-10-09 长研究工具证据修复

用户的「关于中国通信服务在数字双碳方向上的战略调研」运行
`20261009T122140Z-09c47a8d2c39` 收到 11 条工具回执，完整嵌套证据为 65,759 字节。
旧 16,384 字节包络在最终审核派发前阻断任务，并非 Judge 已判定正文错误。
当次三条 `web_fetch` 回执为 `unclassified-error`，不能据此宣称全部检索成功。
当次执行费用、候选与失败记录保留；原运行未重新审核，不能改写为质量通过。

现行 `refractagent-providers-v6` 货币参考配置改为按实际完整审核请求检查容量：

- 保留全部工具名称、参数、正文、结构化回执及错误；不截断，不隐藏摘要，不补跑工具。
- 正文、任务、规则、工具材料和引用目录使用与实际派发一致的消息，全部计入保守输入计数。
- 输入须放入实际审核模型的上下文，并留出已配置审核输出容量。
- 模型调用账本按该完整消息预留费用，仍受独立审核预算和现金预算约束。
- 未确认工具结果仍优先停止；扩大可容纳证据不意味着工具成功或正文合格。
- 真正超出审核模型容量时显示实际计数与可用容量，明确审核未派发。
- DSH 失败说明透传核心给出的具体原因；轨迹展示证据字节数与完整审核容量检查。

旧版本配置保持原固定包络，避免追改冻结实验。新实现的合成回归覆盖超过本次事故规模的
11 条回执、三条读取错误、带／不带引用目录、实际容量不足、预算不足和未知工具结果。
合成审核通过只证明接线行为，不证明原研究答案的事实或引用正确。

## 建议的后续顺序

### 1. 收敛产品验收

完成本修复的离线反例、原 profile 真实工具续接与安装版本核对，记录 #178 已通过部分
及客户端边界；后续只补齐 Codex 对应接线。以这组明确验收项结束本轮，
不因为 Judge 偶然不满意而无限增加题集。

### 2. 优化简单任务的固定开销

已有算术样本总费用 11.56950 AFP，其中执行 7.4992 AFP、最终评审 4.0702 AFP。
首先从现有记录拆出上下文、规划、执行、评审的实际开销，检查哪些步骤对该类任务必要。
保留用户／宿主的原始约束，不用私自截断上下文换成本；只有明确无工具约束、无资料依赖
且命中已验证低风险规则的任务，才考虑省去额外规划／评审。完成条件：规则可解释、
确定性负例不漏过、安全及工具要求仍检查，并用少量固定真实样本核对实际节省。

### 3. 让“质量合格后优先 AFP”成为可理解的选模规则

当前混合路线还要求 AFP 质量先验不得低于可行现金模型的最高先验；这比用户设置的
`qualityMin` 更严格。例如 Ark Flash 先验 92.86 低于官方 Flash 94.69，会被排除，
即便都超过当前任务门槛 80。因此简单任务也可能持续选用 glm-5.3。

下一项应先明确产品配置：保持当前严格参照，或对已验收任务类型按可接受质量门槛准入，
再优先 AFP、再比较同单位成本和时延。不能仅调低阈值或把排行榜差值当成实际等质证明。
完成条件：每个排除原因和实际选模理由可见；固定的任务质量标准成立；现金备援和订阅
额度不足的行为明确。AFP 与 CNY 不相加、不捏造兑换比例。

### 4. 有限核对 DAG 的适用范围

继续承接 [#112](https://github.com/AEALab/RefractRouter/issues/112) 与
[#113](https://github.com/AEALab/RefractRouter/issues/113)：在以上产品问题收敛后，冻结一组
有独立子问题的代表性任务，与最优合法整任务路线对比。预先写明质量、费用、时间及停止
条件；若没有可复现净收益，就把 DAG 限定为研究或显式选择入口，不继续叠加学习复杂度。
P6 共享预算、本地训练和新增策略不作为本轮完成依赖。

## 自适应审核更新（2026-10-10）

Python 0.16.33 与 DSH 插件 0.33.21 针对当前
`refractagent-providers-v6` 人民币参考计价配置增加以下行为。历史运行记录不重算；
旧配置继续使用原审核触发和证据合同。

### 生产插件

- 生产包主入口通过 `entryMode: routing` 提供自动／规划模型、设置及运行记录；
  `/routing` 与旧 `/agent` 导出仍保留。DSH 仅从启用的包主入口发现前端，不能只启用子路径。
- `validation-tools` 提供研究验收工具，默认关闭；需要实验时可另行启用。
- 原 `refractagent`、`refractrouter-validation` ID 和旧导出仍可读取，模型 ID、会话、
  provider 和凭证不迁移。宿主的插件列表按模块路径展示，不支持插件自定义友好名称；
  因此使用明确的路径，并在设置卡片中给出中文用途说明。

### 自适应审核

预检先保留可能需要的审核路径，最终候选形成后，Python 根据实际证据决定是否派发。
仅注册工具、强制 Direct 或拆分 Judge 无法确定，不单独构成最终审核理由。
以下情况仍保留审核：DAG、明确材料及验收／输出合同、事实查证、依赖上下文的继续任务、
实际工具结果、候选引用来源或断言实现／验证状态，以及确定性检查发现的缺陷。
这些规则只决定是否增加审核，不将关键词当作事实错误或通过结论。

低风险 Direct 可以不调用最终 Judge；轨迹显示「跳过审核」，不能描述为已独立证明质量。
`always` 仍始终审核。封闭微型任务若出现预检未保护的新审核风险，停止交付；
不能事后扩展授权路径。未知工具结果、未知模型用量、数据域不准入仍优先阻断。
这项优化不改变节点选模、推理等级、额度和用户配置的 180 秒审核等待上限。

### 完整证据去重

`proposal-constraints-v11` 与 `review-evidence-references-v3` 使用结构引用：
原对象、数组、数值和文本都保留，文本完整分页并绑定原文哈希。同一来源原文只存一次，
每次出现的路径仍记录在 `origins`；候选与来源分别保存，不能用候选给自身事实作证。
对象、数组和文本采用不同标记，原材料即使含 `text_refs` 等同名字段也不会被误读。
原始请求和工具记录按既有隐私保存合同保留；没有删除历史、截断正文或增加摘要模型调用。

公开合成容量夹具的完整序列化输入由 239426 字节降为 104200 字节，减少约 56.48%。
所有原始工具值还原后相等。这只是该夹具的输入变化，不能据此宣称所有任务的费用、
等待时间或审核准确率同比改善。

### 审核失败与纠正

| 核心结果 | 后续行为 |
|---|---|
| 明确候选缺陷 | 仅在已配置最终纠正时，原执行模型纠正一次，再复审 |
| 有 `UNCERTAIN` 的证据检查 | 未审定停止，不用文字补造证据或轮换模型 |
| 通过判定但分数低于质量门槛 | 停止；没有明确缺陷时不盲目纠正 |
| 无效回执、认证／传输故障、未知用量 | 停止后续受管调用，保留费用与未知预留 |

纠正不重建 DAG、不重新执行已完成工具、不追加子 Agent。未通过复审的候选不交付。
自适应审核不会根据通过与否改选节点模型；强模型接管仍由独立策略及显式配置控制。
轨迹保存审核理由、实际工具数量、原始判定、故障类别、完整输入规模和合同版本。
