# 結構化 Judge 題型與驗收案例核對

## 判別原則

依照 [TypeSafe 問題類型說明](https://docs.typesafe.ai/primitives)：Choice 用於互斥且無順序的
動作，Score 用於有明確層級的連續評價，Noul 用於可定義清楚的是非條件。
同一次請求的多個問題各自讀取同一份狀態，不能假設第二個問題已看見第一個答案。
Router 必須保存原始答案、選項概率、規則版本與最後動作；選項概率不是候選的實際成功率。

| 場景 | 使用題型 | 核對結果與本次處理 |
| --- | --- | --- |
| 自動路由是否拆分 | 兩個 Noul：是否依賴前步結果、是否能獨立開始 | 題型合適。新設定名為 `noul-v1`，仍讀取歷史誤名 `choice-v2`；不改舊任務。 |
| Task 本地候選選擇 | Choice 含 `insufficient`；或逐候選 Score 加 Noul | Choice 合適於直接選路，但其概率只代表相對選擇確定性。本次在結果中獨立標記 `selectionProbability`。舊 Score 把「證據不足」放進有序等級，不符合連續尺度；新增 `ordinal-v2`，Score 只衡量已核對能力覆蓋，Noul 單獨判斷資訊缺口。舊問法保留供歷史配置讀取。 |
| Stage 混合判斷 | 進展 Choice、下一輪路線 Choice | 類別對應不同動作，題型可用。兩題雖同批返回，彼此獨立。舊規則要求兩題都過門檻，曾把八條原始選對高效路線的案例歸為不確定；本次未用同題調低門檻或改生產映射。 |
| Composite | Task 初選加可選 Stage 判斷 | 沿用各自合同，不能把兩種概率混作單一品質分數。 |
| Advisor | 四類 Choice，映射為批准、返工或未審定 | 類別對應控制動作；「證據矛盾可修正」與「資料不足無法判斷」仍需新題驗證邊界。 |
| Escalation | 四類 Choice，映射為放行、缺陷、停滯或無法判斷 | 題型符合動作分支；停滯類案例的工具回合有效性必須先驗證。 |

普通 LLM Judge 使用策略專屬的嚴格 JSON，不假裝返回 Jev 的 API 格式。
官方 Jev 固定題與 DSH 工具軌跡重放保存在獨立試驗記錄，尚未接入 DSH 在線規劃設定。

## 題集來源與有效性

舊版固定題和已付費原始回執保持原樣。審計發現
`escalation-judge-v1.json` 的六條停滯題標示 `finishReason=tool_calls`，
但候選沒有工具呼叫；這六條不可作為有效宿主工具回合的品質驗收。
舊版 Advisor、Escalation 的部分案例把「可信工具結果」寫在普通使用者文字中，
不能據此證明 Judge 會識別原生工具來源。不能事後刪除這些題並把剩餘命中率稱為
新的驗收結果。

新增 `escalation-judge-v2.json` 的 12 條與 `advisor-judge-v2.json` 的 9 條
**協議留出題**；需要可信工具事實的題目使用成對的工具呼叫、工具結果與事件。
`experiments/judge_case_audit.py` 先檢查回合形狀及來源，單元測試驗證新題集，
並明確記錄舊版六條不合格案例。逐題結果見
[題型與協議驗收報告](../reports/judge-question-audit-20261001/README.md)及
[三後端對照](../reports/judge-backend-comparison-20261001/README.md)。新題集中 Advisor 的
Laya、Jev、Ark 分別符合 3/9、9/9、9/9；Escalation 排除預先標記的一條含糊案例後，
分別符合 2/11、10/11、9/11。案例數與題面不同，不能與舊批次的 24 題成績直接比較。

[DSH 原生工具流程驗收](../reports/judge-tool-flow-20261001/README.md)另行保存四條
真實 Ark Judge 接線和同一批已歸檔輸入的 Jev、Laya 事後重放。四條成功接線均完成
預期的工具續接、返工或接管；Jev 原始 Choice 六題選對六題，但經現行 0.8 門檻映射後
僅三題得到預期動作；Laya 映射後為零題。重放沒有重新執行工具，也不證明 Jev 已在
產品路徑接線。這些結果不構成在已見案例上直接調低生產門檻的依據。

## 目前可下的結論

1. 題型與資料合同的修正已經過無網路測試；它證明接口一致，不證明判別品質改善。
2. `ordinal-v2` 和既有本地混合判別仍屬實驗；新用戶可明確選擇，舊配置不自動改問法。
3. 要改 Stage 門檻或正式切換 Judge，先凍結新版問題、模型版本、預期動作與不同風險的
   接受門檻，再用新留出題和完整 Agent 任務分開驗證品質、成本與等待時間。
4. 路由軌跡與報告須分開列出模型原始答案、Python 最終動作和實際任務結果；
   未提供真實下游結果的題目只能稱為固定標籤符合率。
5. [Jev 分動作門檻留出驗收](../reports/jev-choice-action-gate-20261001/README.md)
   顯示，全動作統一採用 `confidence >= 0.55` 且獲選項概率 `>= 0.70` 會
   錯誤批准一條明確缺陷；按動作保留較高的最終批准／放行門檻擋住該反例，
   但在 24 條新題上沒有比舊規則多符合預期。兩種量來自同一概率分布，
   不能視為獨立複核；實驗設定不自動進入在線預設。
