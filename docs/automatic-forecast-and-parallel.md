# 自动路由费用预测、节点选模与 DSH 并行

## 适用范围

本次改动用于独立的自动路由 DAG 研究入口。标准 Base URL 模型接口继续采用规划路由策略，
不进入 DAG 调度。核心负责费用预测、节点模型选择、调度和账本；DSH 插件负责模型通信及展示，
宿主继续拥有工具执行、权限、上下文与委派。

对应核心版本 `0.16.21`、DSH 插件 `0.33.5`，已核对宿主 `0.1.5-rc.3`。

## 三种费用口径

| 口径 | 用途 | 计算依据 |
|---|---|---|
| 预计费用 | 比较 Direct／DAG 和候选模型 | 本次序列化输入、计划输出及匹配的节点用量观测 |
| 安全预留 | 保护调用与必要审核所需额度 | 实际请求的保守输入上界及允许的输出容量 |
| 实际费用 | 已计费调用结算 | 提供方确认的输入、缓存与输出用量 |

金额版配置 v6 也传入预计用量，不再把完整上下文容量或模型最大输出当作每轮预计消费。
初始输入费用按序列化字节数除以 4 估算；父节点预计输出按原计划传递。
输出采用明确的路由画像预测，或计划的 `expected_output_tokens`；匹配独立节点观测时，
取观测输出均值与计划输出两者较大值。模型容量仍用于实际调用准入和安全预留。

最终审核的预计输入包含计划交付包络，预计输出不超过 1024 tokens。
实际审核保留原配置的输出上限、等待时间及预算保护，不因预计费用降低而缩小预留。
轨迹记录 `planned-usage-cost-v1`、字节估算来源以及未校准标识。预计值不是费用上界，
工具续接和新的执行工作仍逐次检查；没有宣称 DAG 必然比 Direct 便宜。

订阅路线按公开价格记录 CNY 参考估值，单次现金为 0；按量费用另列。
参考估值已经包含按量费用，两种账本不能相加。历史未知用量预留不自动释放。

## 节点能力档案

自动模型池新增可选 `nodeProfilePath`，设置页「高级配置」可填写档案路径。
Python 在预检时读取、冻结并验证文件；插件不生成分数、不复制选模逻辑。

档案使用 `node-quality-bundle-v1`，要求：

- 真实独立节点观测；按模型、节点类型、难度、风险和输入预算区间分层。
- 同一校准节点的所有候选收到相同输入及上游材料，形成完整候选矩阵。
- 校准集与保留集任务 ID 分开，至少三条校准观测才能形成正面分层。
- 哈希绑定原始输入、输出、评分规则、当前模型、推理参数、价格及实际输出容量。
- 只使用独立節点评价；整任务得分、模型名称和价格不转换成节点能力成绩。

保留集只否决已知失败，不用于提高校准分数或拟合用量。语义失败、合同拒绝和保留集失败
将该分层记为 0 分；按现有质量门槛拒绝。没有精确匹配时，同类节点的已知失败也不能因为
输入区间变化而退回更乐观的全局先验。新分层取得独立正面证据后可覆盖这一保护。

没有覆盖的其他分层继续使用用户现有先验，并明确标为「没有匹配的节点实测」。
分数不是任务成功率。模型池可以继续选择同一模型执行全部节点；不同模型必须有真实依据，
不能为了展示异构路由而人为增加某模型的分数。

此次两款 Ark 模型的小样本只覆盖公开账本和调度材料。档案作为受控验收数据保存，
不默认应用于用户所有日常任务。扩大适用范围需要独立节点材料与保留集证据。

## DSH 并行派发

核心在并行执行前通过 `refractrouter-host/v1` 核对宿主能力。
同一通道允许最多 8 个模型请求在途；实际数量同时受任务的 `maxConcurrency`、
provider 并发设置和启动间隔约束。原模型与工具协议的操作名称保持不变。

每个请求使用唯一 ID，响应按 ID 关联；模型完成顺序可以不同于派发顺序。
Python 只在父节点成功且输出合同成立后启动下游，原子预算预留在真实派发前完成。
DSH 桥接不再等待一个模型完成后才读取下一个请求。工具请求仍进入宿主串行队列，
不把模型并发变成工具并发执行，也不创建新的内部 Agent 工具循环。

取消、EOF、非法回执、通道中断或未知用量停止后续受管派发，在途调用结算或保留待核对。
迟到响应不能误配其他节点，进程恢复不自动重发。主入口结束时关闭桥接。

## 路由轨迹

新增逐节点的全部候选比较，展示实际 provider/model、推理等级、准入结果、选择状态、
质量依据、校准／保留集样本、预计输入输出和参考费用。
执行记录显示配置并发上限、实际峰值以及父子启动关系；可并行的拓扑不冒充已经并行执行。
原任务 DAG 页签、规划路由设置卡片、模型目录和历史继续保留。

## 可复现验收

`experiments/run_automatic_node_quality.py` 默认零调用预检。冻结公开题目、两款既有订阅模型、
原宿主上下文及参数，分别记录校准和保留集；不增加生成式 Judge。
`--reassess-from` 只创建新的派生评价，不修改原回复、原评分和账本，不调用模型。
派生语义评价只可移除完整 JSON 代码围栏，格式不合规另列；内容错误、额外文字和字段仍拒绝。

`experiments/run_automatic_parallel_acceptance.py` 默认零调用预检。
四节点固定夹具包含三个独立根节点和一个汇总节点，最多五次既有订阅调用，五分钟，
零 Jev、零工具、零 HTTP 自动重试。它验证实际 DSH 派发和汇总依赖，属于受控功能验收，
不能用于证明自然任务拆分收益。

费用复算与本次验收结果见
[费用审计](../reports/automatic-quality-20261009/cost-forecast-audit.md) 和
[节点与并行验收](../reports/automatic-quality-20261009/forecast-node-parallel.md)。
