## 原因与修复边界

1. 规划描述包含完整案例、字段和验收，超出 Python 180 字符合同。
   原提示写“180 字”，没有明确英文标识中的每个字符也计数。
   已补充字符计数和简短职责说明，不提升硬上限、不截断模型产物；实际改善尚待验证。
2. text 节点系统指令禁止 JSON 正文，与任务明确要求 JSON 冲突。
   已区分额外 `{"text": ...}` 包装与任务要求的正文格式。此修改不是原批结果。
3. 最终评审输出含未转义英文引号，严格解析失败；没有修复调用或伪造评审结论。
   这是评审格式失败，不能说已经判定候选答案质量不合格。
4. 费用案例中的订阅已结算参考 0.08 加现金已结算 0.03，已知参考为 0.11；
   现金已结算 0.03 加未知预留 0.20，现金占用为 0.23。
   候选给出 0.08／0.20，模型评审却给出 96 分并批准。
   可计算事实必须独立检查，评审高分不能替代事实验收。
5. 工具任务记录仅保留 provider-error，无法定位超时、断流或提供方拒绝。
   新增本机脱敏通信诊断，不记录请求正文或凭证，不公开原始错误正文。
   新诊断不能追溯重建旧错误，也不能认定该错误属于模型能力失败。

原始配置、账本和失败产物只保存于本机忽略目录，本文件仅给出脱敏汇总。
重发可能计费的调用需要新的明确授权；未知记录不自动释放、不自动续跑。
