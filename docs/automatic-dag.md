# 自动拆分与动态执行

RefractAgent 的 `auto` 模式由快速规划模型描述节点职责与依赖，Python 编译完整契约，
再选模型、并行执行就绪节点、核对最终答案。默认入口仍为 `single`；`compare` 为固定模板。
预检和模拟不会调用规划模型，不能当作拆分质量证据。

## 快速规划

规划模型只输出 `reason` 和最多六个节点，每个节点仅含 ID、类型、短指令、父节点、难度及风险。
不让小模型生成冗长契约、费用画像或任务解答。Python 补齐字段交接、验收覆盖和输入容量。
所有节点获得原始任务；共享材料不会被编译成依赖，只有消费上游结果才需要等待。
最终节点完整呈现各分支成果；简单任务可以保留单节点，不为并行而强行拆分。

默认按用户配置预测的响应时间优先、价格其次选择规划器；清单没有时延预测时按价格优先。
Ark 示例预测的时延相同，因此按价格选择豆包 mini。价格与能力声明不等于实际参数规模；
接入其他供应商时，应配置小模型并用 `plannerModelId` 明确指定。
执行节点仍独立按质量、费用和时间策略选择，可使用较强模型。

自动紧凑规划使用模型声明的完整输出容量，不再附加 1200 token 上限或规划超时。
Ark 官方模型采用目录声明的输出容量；其他模型采用用户配置的容量。
规划等待不消耗后续节点执行的时间额度，用户仍可主动取消；供应商自身限制仍然有效。
`maxPlanRepairs: 1` 可允许一次结构修正，各次请求独立计费；默认不自动修正。
截断、结构无效及未知用量仍如实失败，预算检查和实际用量记账保留。
历史低层协议的显式规划上限与冻结实验不变。

设置 → 插件 → 插件配置 → RefractAgent 路由中的“规划器思考方式”支持继承模型设置、
开启、关闭，对应 provider 配置的 `plannerThinking: "inherit" | "enabled" | "disabled"`。
默认继承，不再按型号强制关闭；显式设置只作用于规划副本，不改变执行节点。
不支持关闭思考的模型或不支持该开关的接口会给出配置错误。

直接 HTTP 自动模式默认最多四个并发节点，可用 `maxConcurrency` 降低；
同时遵守 `providerConcurrency` 和 `providerMinIntervalMs`。DSH stdio 桥接仍默认串行。
调度器按实际完成事件释放下游，不等待同一波次里与该下游无关的慢分支。
DSH 自动模式持续展示核心进度：规划开始、计划就绪、节点模型分配、排队、运行、完成或失败。
展开回答中的运行过程，可以看到节点职责、依赖、物理模型及推理档位和状态；
新增动态节点会以更新后的节点清单展示，已完成的兄弟节点保持原状态。
`plan_ready_ms` 记录核心计划完成时刻；预检和模拟会明确标记，尚未执行不显示为已完成。

进度通过 `refractagent-progress/v1` NDJSON 与最终结果、宿主模型桥接消息复用 stdout。
Python 在保存检查点后生成状态；TypeScript 只校验、脱敏和展示，不推导业务状态。
退出、取消或流中断时显示最后收到的状态，已派发请求的未知用量仍须核对。
最终答案与进度分块展示，保留用户要求的正文或 JSON 输出格式。
记录目录新增 `progress.ndjson`，`summary.json` 的 `dag` 保存最终节点快照。

## 执行中的有界再拆分

自动模式默认 `maxDynamicSplits: 1`，可设为 0 关闭或设为 2；深度固定为一层，总图最多八个节点。
触发条件包括已结算的截断／空输出、无效交接、确定性依赖检查失败，以及模型明确返回
`{"status":"needs-decomposition","reason":"具体困难"}`。不会把所有不确定性都视为可以拆分解决。

1. 暂停新节点派发，结算所有在途调用；保留已完成结果，不重新执行成功的兄弟分支。
2. 快速模型只把困难节点分成两至三个职责，其中最后一个继续使用原节点 ID 和输出契约。
3. 原上游字段保持冻结，新节点按声明取得同一上游状态；原下游继续等待原节点出口。
4. 按剩余费用、时间、容量和质量重新检查尚未执行部分，通过后加入同一个并发队列。
5. 新增节点及其汇总出口不能再次递归拆分；没有可行路线或额度耗尽时停止并保留证据。

认证、未知用量、账本异常、取消及全局截止时间不会触发再拆。全部初次失败、再规划和
新增执行均记账。此版暂不同时启用动态拆分和 `maxNodeFallbacks` 模型切换。
结构有效且未被确定性检查发现的语义错误，不会自动触发再拆；本版没有逐节点通用语义评审。
这是一条可运行的恢复路径，不等于已经证明拆细比原节点或换强模型更划算。

## 展览依赖错误的修复

应用默认 `verifyDependencies: true`。对于明确写成「第 0 天开始；A 需要若干天；
B 需要若干天且必须等 A 完成」的封闭排程材料，Python 提取原文证据并拓扑复算，
把原始和延误情景的时间、关键链提供给执行节点。

每个节点的显式箭头链都必须使用材料中真实存在的边。最终答案还必须列出原始及延误后
的完整关键链；错误链后再追加一句修正仍视为冲突。展览的 `A→C` 会被拦截，
正确延误关键链为 `C→D→E`。若允许再拆则进入上述恢复流程，否则返回
`content-verification-failed`，保留错误正文，模型评审不能覆盖这个失败。

这项检查不是任意自然语言事实验证器：它只覆盖明确句式、显式箭头依赖与关键链覆盖。
无法识别的材料标为 `unsupported-source` 或 `not-applicable`，检查结果为 `null`，
不能说已经验证通过。其他数值、因果关系、自然语言转述及漏项仍需独立评审或人工复核。

## 使用与参数

```bash
refractagent run --task '分别核对给定方案的费用和实施风险，再汇总建议。材料：……' \
  --template auto --provider-config ./provider-config.json \
  --mode live --execute-paid-run --max-output-tokens 2048 \
  --production-budget 40 --evaluation-budget 40 --timeout-ms 180000
```

在请求 JSON 中可设置 `plannerModelId`、`plannerMaxOutputTokens`、`plannerTimeoutMs`、
`maxDynamicSplits`、`maxConcurrency`、`providerConcurrency`、`providerMinIntervalMs` 和
`verifyDependencies`。验收条件使用 `acceptanceCriteria`，会原样进入完整执行任务和最终评审。
CLI 可用 `--request-file` 或 `--request-stdin` 传入；DSH 配置支持规划模型、规划额度、动态次数、
总并发与依赖检查开关，Python 保持业务规则的唯一实现。

核心原有完整契约规划仍可用 `planningMode: full` 作兼容验证；正式自动模式默认 `compact`。
显式计划默认不动态改写；只有明确设置 `maxDynamicSplits` 才启用其有界再拆。
历史冻结实验必须使用各自冻结源码与协议，不把本次默认值变更混入旧结果。

## 容量、费用与证据

自动配置画像按实际节点生成，仍是 `configured`、零观测。输入容量、预计用量与真实请求
预留分别记录；缺少实测画像时不重标风险、不虚构覆盖。每次调用仍通过原子硬预算检查。
同一画像区间出现不同预测用量时取较高费用，避免受节点遍历顺序影响而低估。

结果目录保存原始计划、编译计划、修订图、每次节点尝试、冻结上游及摘要、原始用量和费用。
动态事件位于 `result.json` 的 `dynamic_decomposition.events`，其中保留重新路由的画像与预算。
`summary.json` 分列初始规划、动态规划、节点执行、最终评审费用，以及计划就绪时间和完整墙钟耗时。
AFP 是订阅用量记账，不等于新增现金账单；未知用量单列保守预留。
