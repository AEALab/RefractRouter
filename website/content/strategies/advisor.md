# Advisor Gate · 审核

Advisor 使用固定执行器，在准备交付最终回复时审核候选。
默认最多 **两次审核、一次返工**，最终或复审通过才交付。

## 审核闭环

| 边界与判定 | 行为 |
| --- | --- |
| 正常工具请求 | 交给宿主执行，不做结束轮审核 |
| 首次最终候选 APPROVE | 放行候选 |
| 首次最终候选 REDO | 丢弃候选，保存反馈，请原执行器修正 |
| 返工需要工具 | 宿主正常执行，反馈与计数跨请求保留 |
| 修正后的最终候选 APPROVE | 放行并标记复审通过 |
| 第二次未通过，或无法判断 | 未审定停止，不交付该候选 |

被丢弃内容只保留在审计记录，不能作为已接受历史。返工不重新执行已完成工具。
停滞审核只保留在旧兼容路径，本版严格 Gate 不增加每轮工具审核。

## 在哪里选择 Jev

进入 **规划路由 → 正在编辑的策略：Advisor → 审核器类型**，选择官方 Jev。
再在官方 Jev 的渠道、凭证引用和数据域设置中核对 OpenRouter。
不是在“Advisor 审核 LLM（DSH 模型）”的模型下拉框里寻找 Jev。

该下拉框只用于 LLM 后端；本地 Laya 也是独立审核器类型，不是普通 DSH 生成模型。
当前 Laya 审核质量标为实验；选择它需要显式接受实验状态并提前就绪。

## 判别与故障

审核检查用户要求、已接受历史、工具证据和候选；复审包含前次问题与反馈。
LLM 输出严格校验；非法结构、超容量、认证／传输故障或未知用量停止，不自动修复 Judge。
本地输入不截断，结果分数不解释为正确率。

## 费用与等待

执行前保护执行、首审、必要返工及复审的完整路径。
返工工具续接每轮另检查执行额度并继续保护复审；不能保证任意长返工必有预算完成。
候选缓冲与审核增加用户等待，未接受的候选不会闪现。

## 轨迹应该看到什么

首次审核、返工中、等待复审、已通过或未审定停止；原始结论、接受／丢弃、反馈、
模型首字时间、审核等待、费用与保护额度。Judge 批准不替代团队对实际质量的验收。
