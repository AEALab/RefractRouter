# Stage · 阶段

Stage 从高效模型开始，根据新增的可信执行证据选择下一轮模型。
它调整模型调用，不规划 DAG，也不替接入方执行工具。

## 规则模式

默认窗口为最近 3 条有效工具结果，判断阈值为 0.5，接管保持 2 次执行。
“两次”包含触发切换的当前调用和下一次调用。

1. 工具结果或模型用量未确认，停止后续受管调用。
2. 出现新的同类可信重复失败，切换到指定强执行角色。
3. 保持期内继续使用该角色。
4. 有新证据时计算规则信号；保持结束且无新困难时恢复高效角色。
5. 没有有效信号时使用高效角色；旧事件不重复触发。

单次合理测试失败、正常搜索、权限拒绝和基础设施故障不等于模型能力不足。
失败指纹必须关联工具、规范化参数和可信失败信息，不能仅比较错误码。

## 规则与 Jev 如何协作

可选协作模式在受控边界询问本地结构化 Judge 或官方 Jev。
规则处理工具事实、去重、安全和保持；Judge 提供有限回答信号，Python 决定最终动作。
它不会为每条模糊文字无限增加判别链条。

协作参数包括判别间隔、每任务判别批次上限、保持和降回确认次数。
该模式保留实验标识；超时或后端崩溃停止，不自动切换云端或重发。

## 必要设置

高效、强执行模型与各自推理等级；规则参数；协作模式另选择 Judge、数据域及期限。
两个角色绑定相同模型与参数时可按准入运行，但不会产生实际模型切换。

## 工具证据的来源

DSH 原生事件能携带结构化工具结果。纯 Base URL 的普通文本结果往往没有可信退出状态，
会记为 `unclassified`。Codex CLI 的可选证据适配另见[接入说明](../integrations/codex.md)。
Router 不从正文“成功／失败”猜测退出状态。

## 轨迹应该看到什么

证据 ID、评分、重复失败／保持／恢复原因、保持前后计数、实际模型、推理等级与费用。
规则模式应没有额外 Judge 调用；协作模式记录实际 Judge 批次、原始答案和实验状态。

### 真实案例

stage-01 任务：第一轮无有效工具信号（`no-signal`），使用高效模型 `deepseek-v4-flash`；
用户要求只执行一次 `printf %s STAGE_01_OK`，读取 stdout 后只回复 `STAGE_01_OK`。
宿主完成一次原生工具调用后，回执判定为 `ambiguous`，保持同一模型继续执行。
共 2 次受管调用，费用 1.254 AFP，首字 1.24 秒，总延迟 4.38 秒，含 1 次原生工具调用。
同批次 24 项 Stage 任务全部成功，每项恰好一次宿主工具调用。
这是[2026-09-29 冻结验收](../planning.md#六策略真实运行案例)，两次执行都用同一个模型。
