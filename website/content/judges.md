# Judge 与 Jev

Judge 提供选择或审核信号，Python 负责准入、组合规则、预算与状态推进。
任务内容、候选正文和工具参数都是待判断材料，不能修改判别规则。

## 哪些环节需要 Judge

| 路线／策略 | 环节 |
| --- | --- |
| Static | 不调用 |
| Stage 规则 | 不调用 |
| Stage 协作 | 有间隔和批次上限的轨迹判别 |
| Task | 新任务多个合格候选的一次选模 |
| Composite | Task 初选；协作模式另有 Stage 边界判别 |
| Advisor Gate | 最终候选首审与必要复审 |
| Escalation | 未接管阶段的起始候选；接管后停止 |
| 自动路由 | 可选拆分有限判别；生成式规划与最终审核另外配置 |

## 三类后端

**轻量 LLM**：通过已配置模型接口生成受约束结果。每个用途有自己的合同，非法输出停止，
不自动调用第二个模型修复。不以名字含 Flash 作为硬性准入条件。

**官方 Jev**：结构化有限回答服务。新配置默认 OpenRouter，模型
`typesafe/jev-1.13`，使用 Decisions 接口；不是普通 Chat Completions 模型。
旧配置保留原直连渠道，不静默更换数据传输路线。

**本地 Laya-MLX**：可选常驻推论，无 API 费用，但占用本机资源。提前明确下载固定权重、
加载和预热，任务时不隐式下载。当前固定 checkpoint 的用途质量仍为实验，不能仅凭
低延迟称为日常可靠 Judge。

## Jev 如何设置

在规划路由设置中配置 **官方 Jev Judge**：

1. 渠道选择 OpenRouter，凭证引用默认 `OPENROUTER_API_KEY`。
2. 在 DSH 凭证服务中登记密钥，配置本身只保存引用。
3. 指定数据域和有效信任策略。
4. 在 Task、Stage、Composite、Advisor 或 Escalation 的 Judge 类型选择官方 Jev。
5. 运行零调用诊断，确认支持当前用途与输入包络。

独立标准网关的 Judge 能力须单独核对，DSH 的 Jev 选项不能自动当作网关已具备同样循环。
普通 LLM 下拉框找不到 Jev 是正常的：它的接口与结果类型不同。

## Choice / Noul / Score

| 类型 | 适合的问题 | 在项目中的用法 |
| --- | --- | --- |
| Choice | 已知且无顺序的一组动作 | Task 选模、Stage 路线、Advisor 审核、Escalation 结论 |
| Noul | 条件明确的是否判断 | 自动拆分中的独立工作与串行依赖判断 |
| Score | 定义清楚的有序尺度 | 保留为适合的能力／严重度实验，不强行用于所有动作 |

问题要能直接映射代码动作。Choice 应含无法确定或信息不足的完整分支；
Noul 的 0.5 表示是／否接近，不是“中等能力”。LLM 使用各自结构化合同，
不会假装返回 Jev 官方的全部概率语义。

## Probability 与 confidence

Choice 的获选项 probability 与整体 confidence 分开记录，均用 0–1 表示。
当前 Advisor／Escalation 默认用获选项概率门槛；confidence 保留供观察。

可选实验分动作规则先要求 `confidence ≥ 0.55`：最终批准／放行再要求概率 ≥0.80，
返工、缺陷／停滞接管或正常工具续接要求 ≥0.70。该规则是项目初始实验规则，
不是 Jev 官方要求，也没有被验证为普遍优于默认值。

门槛未达按该策略“不确定”分支处理；Advisor 停止，Escalation 进入合格接管。
不能把 0.80 叫作 80% 的真实正确率，也不能只降低门槛来宣称验收通过。

## 费用和等待

Judge 成本属于真实运行成本，包含没有最终交付的判别。
OpenRouter 回执费用保留 USD 原值和冻结汇率，折算 CNY；用量或费用缺失保留预留并停止。
零自动 HTTP 重试。输入超容量不截断、不隐式摘要、不自动转另一后端。
