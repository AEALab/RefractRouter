# #52 零调用准备证据

本目录归档三类任务质量协议的开发检查，不是模型收益实验。
协议与运行方式见 [质量协议](../../docs/quality-study-protocol.md)。

## 已验证的范围

- 18 个原创虚构任务：6 开发、12 候选留出，三类任务与三种结构形态均有覆盖。
- 评分校准只使用六个开发任务；18 个样例包括12个正例/等价表达与6个负例。
- 5 个负例被确定性检查判为失败；1 个正文反写依赖的负例保持待判定。
- 作者正例未被确定性规则误杀，但仍待语义审查，不能计为已通过的任务。
- 未取得真人记录，未运行辅助模型评审；真人分歧为未知，不写成 0。
- 预检没有实例化模型客户端；实际模型调用 0，实际 AFP 0。

## 包络的含义

`preflight-01/preflight.json` 列出12条候选路线、3次重复的最大容量包络。
开发侧216个候选运行、最多1404次调用；候选留出侧432个运行、最多2808次调用。
这些数字是把每条路线都跑满上限的声明，**不是本轮已经执行或获准执行的批次**。

按冻结 manifest 最大未缓存容量计算：

| 分组 | 在线 AFP 上界 | 独立研究评分 AFP 上界 |
|---|---:|---:|
| 开发 | 24783.8544 | 7520.2560 |
| 候选留出 | 49567.7088 | 15040.5120 |

该保守上界明显高于短任务的预期实际用量；它不能用作预计账单。
离线画像/训练/搜索尚无包络，因此还不是研究总预算。
真实 runner 的逐请求容量、deadline 与预算预留也未绑定，`formal_run_ready=false`。
正式冻结时须先用开发证据收窄实际可行路线与容量，另出新版本。

## 归档文件

- `protocol.json`：当前草案快照。
- `preflight.json`：材料检查、开发评分校准、路线包络与计划运行顺序。
- `execution-inputs.json`：公共执行输入，不含参考答案与路线标签。
- `material-review-packet.json`：独立材料审核空表及材料/参考事实。
- `blind-calibration-packet.json`：供真人校准评审的匿名样例，意见栏为空。
- `private-blind-mapping.json`：只供协调者解盲，不能和盲审包一起交给审查者。
- `artifact-index.json`：上述文件的哈希。

机器检查和盲审模板都不是签署过的证据。#52 仍需材料独立审查、
用途校准、真人盲审、辅助模型评审与实际路线冻结后才可关闭。
