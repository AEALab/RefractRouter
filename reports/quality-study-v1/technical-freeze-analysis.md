## 暴露的问题与开发修订

第一批在线 judge 放行 11 个输出，但离线确定性核对只留下 3 个待真人确认，
8 个因 `required_edge` 与参考编码不同失败。具体为三次把单条边写成嵌套列表，
五次使用“签名通过”作为步骤名称；另一个 mid 输出带 JSON 代码围栏，被原解析器拒绝。
这些不能直接统计成八次依赖方向答错，也不能当作独立真值的 judge 漏判率。

这个开发结果说明公开的字段编码约定不充分，格式失败与事实错误需要区分。
修订将单条边的列表层级、基本步骤名称和正文中的状态条件说清楚，并对所有模型统一
容许剥离一个完整 JSON 代码围栏。未修复或替换模型的语义内容，未重标历史批次。
历史入口实现保留在提交 `b367ca3`；后续每次预检均有独立实现哈希。

最后两次任务运行都完成节点执行和模型评审。mid 直接输出通过字段检查、待真人；
自动异构输出仍用了“签名通过”，违反新增的基本步骤名称编码约定，保留 `fail`。
这项格式偏离不证明正文依赖方向错误；它说明指令不能保证模型严格遵循结构约定。
不通过再抽样把它改成成功，也不借这两题结果声称质量门槛达标。
[最终分析](ready-live-analysis.json) 的确认前沿为空。

当前保留严格字段比较，避免在没有独立语义依据时自动把看似相近的步骤名归一化。
真人审核应明确该编码约定是否适合用途，或要求在下一版本中统一增加有据可查的等价规则；
不能针对某一路线临时豁免。既有开发控制仍覆盖正文反写依赖、遗漏限制、错引用等问题，
模型通过不覆盖任何确定性失败，缺真人语义审查仍不算最终通过。

## 冻结及复现

最终留出预检最大 2748 次调用，包含 12 次共享图准备与 432 次任务运行的全部阶段。
在线 AFP 保守容量上限 133727.5872，离线上限 57528.2208；它们使用最大输入/输出容量，
不是预计费用、已经花费的 AFP 或已经启动的实验预算。
逐路线 deadline 为 135–384 秒，属于超时控制配置，不是端到端性能预测或硬 SLA。

```bash
uv run python experiments/freeze_quality_protocol.py \
  --rehearsal-results reports/quality-study-v1/ready-rehearsal/evaluated-results.json \
  --live-results reports/quality-study-v1/ready-live/evaluated-results.json \
  --output-dir /tmp/quality-technical-freeze-new
```

输出必须使用新目录。最终证据要求调用路径与统计政策一致；运行后的分析与汇总脚本
可有独立修订，最终冻结记录全部当前实现哈希。分析代码拒绝解释不同统计政策的结果，
不静默用新门槛重写旧协议。`contract-*-preflight` 只是中间零调用文件，没有对应付费批次。

真人剩余工作为：独立材料与参考审核、开发正负例盲审及分歧裁决、用途门槛与探索范围确认。
材料不足时必须先补充再冻结，不能把短构造任务直接推广到现实业务。
未来留出执行后的最终答案双审按同一协议完成。#52 保持开放。

实现规范与命令详见 [运行绑定与研究边界](../../docs/quality-study-freeze.md)。
