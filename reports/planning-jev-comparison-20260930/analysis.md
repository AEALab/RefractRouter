# 规划路由 Jev／Laya 对照分析

## 范围与费用

本批完成 78／78 条固定 Judge 案例，Jev 返回的实际模型全部是 `jev-1.13.0`，
共报告 49,765 个输入 tokens。依据[官方公开单价](https://docs.typesafe.ai/models)
估算 API 费用 **0.00209013 USD**；这不是账户账单核对值。没有 HTTP 自动重试。
逐题原始答案、用量和耗时见 `calls.jsonl`，按案例 ID 对齐的比较见 `comparison.json`。
与 Laya 的对照沿用既有题目和阈值，不把五类不同任务的符合预期次数相加成单一准确率。

| 用途 | Jev／Laya 符合预期 | 关键现象 |
| --- | ---: | --- |
| Task 开发题 | 5／6 对 3／6 | 英文终端任务原始首选正确，但未达到 0.8 门槛 |
| Task 留出题 | 6／8 对 6／8 | 两条中文能力题原始首选正确，但未达到 0.8 门槛 |
| Stage | 7／16 对 4／16 | 8 条应使用高效模型的案例均归为无法确定 |
| Advisor | 20／24 对 7／24 | 明确缺陷与证据不足均未获批准；合格回复仅 3／6 获批 |
| Escalation | 22／24 对 5／24 | 6 条正常继续、6 条明确缺陷及 6 条无法判断均分类正确；停滞 4／6 |

Jev 各组单题耗时中位数约 0.41～0.42 秒，包含网络往返；本地 Laya 各组
约 0.014～0.089 秒。这是不同服务条件下的实际等待比较，不能单独推出完整任务的
端到端时延或成本收益。

## 规则映射诊断

Stage 的 8 条正常探索或恢复高效模型案例，Jev 的 `route` 原始首选均为
`EFFICIENT`，该选项概率约 0.87～1.00；但 `progress` 首选概率仅约 0.45～0.76。
当前 `stage-decision-v2` 只有两项都满足门槛才输出 `EFFICIENT_OK`，因此这些案例
全部映射为 `UNCERTAIN`。这是本批可复现的规则瓶颈；不能仅据 7／16 说 Jev
不会判断哪条模型路线较合适。也不能直接在这批题上调低门槛后，把同题成绩当成新验收。

Advisor 的 4 条未通过案例，原始首选都为 `APPROVE`，所选项概率分别约为
0.75、0.49、0.78、0.52，因低于既有 0.8 门槛映射为 `UNRESOLVED`。
六条明确缺陷均为 `REDO`，六条证据不足均为 `UNRESOLVED`，本批没有观察到
错误放行。但按先前冻结的“六条合格案例至少五条批准”门槛，只有 3／6，
**Advisor 尚未通过日常使用准入**。降低门槛可能改变误放行率，需要新留出题验证。

Escalation 的两条差异都出现在停滞类别，分别以低于 0.8 的原始概率归入
`UNCERTAIN`。按既定产品规则，无法判断会交给接管模型，安全方向没有倒转；
不过它可能增加不必要的接管费用。24 条题只证明固定分类合同，不证明 DSH
工具续接与整任务质量。

Task 的三条能力题差异中，Jev 原始首选均为预期模型，但所选项概率分别为
0.70、0.68、0.79，低于 0.8 门槛，因此按既定规则走资料不足备援。
留出题的两条平分案例原始首选却是某个候选，概率为 0.60、0.74，
现有门槛恰好防止将其误选。因而**不能简单整体降低 Task 门槛**；需要
检查能力卡、判别问法及不同模糊度的独立校准题。Task 题集属于候选能力探针，
不能用 11／14 宣称真实任务选模已达到某种成功率。

## 产品判断

本批不宜把规划路由所有 Laya Judge 一次性切成 Jev 默认。Escalation 的固定
判别题已达到此前“明确缺陷不放行、正常继续至少五条”的门槛，可进入有界的
DSH 端到端接线验收。Stage 需要先修改并冻结规则，再用新留出题验证能否恢复
高效模型而不误降困难任务；Advisor 需要独立校准及新留出题；Task 需要真实
任务级选模验收。Laya 保留为可替换的实验后端，Jev 可作为云端结构化 Judge
候选，但这批离线证据不足以支持全部策略立即替换。

按产品优先级，先检验质量门槛，再核对每次 Judge 与被接管调用的总成本，
最后评估约 0.4 秒的网络等待是否可接受。本批官方 Jev 调用并未接入 DSH
在线规划路由配置，也未修改自动路由 DAG 路线。
