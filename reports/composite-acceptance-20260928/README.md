# Composite v6 有限验收

## 范围与结论

本批验证 Composite 的一次 Task 选模、首次执行跳过 Stage、规则切换／保持／恢复、本地
Laya 实验接线，以及 DSH、Codex、Hermes 的标准 Base URL 工具续接。没有开展收益对比，
没有调用付费上游模型。

零调用预检冻结的 AFP 和 CNY 上限均为 0；本批未消耗既有累计 2000 AFP 授权。

## 三客户端正常流程

三个已安装客户端均连接 `refract/composite`，完成一次确定性 Task Judge、一次宿主工具执行
和工具结果后的继续执行。Router 没有执行工具或建立 DAG。

| 客户端 | Task Judge | 执行调用 | 宿主工具 | 付费调用 |
| --- | ---: | ---: | --- | ---: |
| DSH | 1 | 2 | DSH | 0 |
| Codex | 1 | 2 | Codex | 0 |
| Hermes | 1 | 2 | Hermes | 0 |

DSH 首次使用的验收驱动策略白名单未包含 Composite；修正后又发现模块目录指向旧 profile。
两次失败均发生在上游模型调用前，原始本地记录保留。改用当前 profile 的模块目录后通过。

## 可信失败切换

标准 Base URL 的版本化工具证据测试完成以下序列：

1. Task 选择常用模型；
2. 第一次可信失败继续常用模型；
3. 第二次同类可信失败切换接管模型；
4. 下一次执行保持接管模型；
5. 没有新困难后恢复常用模型。

这条测试共 1 次确定性 Judge 与 5 次确定性执行调用，全部为本地夹具。三种纯标准客户端
当前不会自动传递可信退出码，因此没有把相同序列描述为三客户端已完成动态切换验收。

## 本地 Laya

固定 `aac6fef/laya-multilingual-mlx` revision
`f2b4faf51023039425946074e2cf1361d2db11d5`，运行两条独立 Composite Router 接线：

| 案例 | Laya 结果 | 选择 | 推论等待 | API 费用 |
| --- | --- | --- | ---: | ---: |
| 正常完成证据 | `UNCERTAIN`，获选项 0.5084 | 接管模型 | 约 112 ms | 0 |
| 单次失败证据 | `UNCERTAIN`，获选项 0.5678 | 接管模型 | 约 65 ms | 0 |

冷启动约 1094 ms；两条均完成一个真实 forward。接口、异步 job 和不确定分支有效，但结果
再次说明当前 checkpoint 不能作为已通过质量验收的日常 Stage Judge，因此继续标记为实验。

## 确定性覆盖

- v6 配置升级、模型池、指定接管模型、单一和多个候选；
- Task 只分类一次，首次执行不触发 Stage；
- 重复可信失败、保持两次、旧事件去重和恢复常用模型；
- 常用模型等于接管模型时跳过判断；
- 本地 Laya 未就绪阻断、容量回退、异步等待和规则版本；
- 标准 Chat Completions／Responses、DSH 插件工作进程和三个实际客户端；
- Static、Stage、Task、Advisor、Escalation 与自动路由回归。

原始客户端请求、本机路径和本地运行文件保存在忽略目录
`.refractagent/acceptance/composite-v6-20260928/`，不提交仓库。公开报告只保留结论、计数、
判别分数和耗时。

## 限制

本批没有验证自然任务收益、图片／影片审核、长时间并发、P6 子 Agent 共享预算或三客户端
自动发送可信工具状态。上述缺项不影响规则状态机和正常标准接口使用，但不能据此宣称
Composite 已证明比 Static 更省钱或在所有 Agent 中都能自动动态切换。
