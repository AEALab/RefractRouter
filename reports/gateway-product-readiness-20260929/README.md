# 独立模型网关产品化验收

验收日期：2026-09-29。

## 范围

本轮完善 `refractrouter-gateway` 的运行级合同，不增加策略，不执行真实模型调用，也不修改
DSH、Codex 或 Hermes 的日常配置。Router 继续只负责模型选择、审核、模型调用与费用账本；
工具、权限、提示、上下文、委派和任务推进继续由接入方 Agent 负责。

本轮完成：

- 增加版本化网关配置 `refractrouter-gateway-config-v1`，兼容未声明版本的已有配置，并拒绝
  未知顶层字段。
- 增加公开的 `GET /healthz` 存活检查，以及需要服务认证的 `GET /readyz` 就绪检查。
- 就绪检查和零调用预检显示协议版本、软件版本、配置 SHA-256 与可用策略，不显示配置正文、
  上游地址或凭证。
- JSON 与 SSE 响应声明 `X-RefractRouter-Protocol`；模型和工具证据 POST 接口要求
  `application/json`。
- 处理 `SIGINT` 与 `SIGTERM`，退出时关闭 HTTP 服务和本地 Judge 服务。
- 修正文档中的旧版本、四策略清单，以及标准 Base URL 网关和历史任务服务之间的混淆。

## 已确认边界

- 标准接口仍只接通文本与 function 工具；图片、影片、托管工具和 custom tool 会明确拒绝。
- `readyz` 证明配置可编译、凭证引用存在且至少有可发现策略，不向上游探测模型可用性。
- 配置摘要用于确认实例加载了哪一版配置，不能反推出配置内容，也不代表收益已经验证。
- 本轮没有启用 Codex 与 Hermes 日常 profile 的工具证据适配，继续遵守用户要求的延期项。
- P6 子 Agent 共享预算、媒体接入和自然任务收益验证仍是后续里程碑。
