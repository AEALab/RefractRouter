01 / 先读结论

在已测试的短构造任务和当前实现上，DAG 拆分尚未证明能在质量达标的条件下，同时或稳定地降低费用与等待时间。同图节点选模存在局部节省，但不能把它等同于相对直接回答的端到端收益。新的研究框架先排除违反隐私与数据安全边界的路线，再在合规方案中比较质量、费用与时间。

研究决策 · 由当前证据支持的保守选择
在确保用户隐私与数据安全的前提下，先判断整任务直跑或 DAG 拆分是否合法可行；敏感节点必须交由本地或满足信任与驻留要求的云端模型处理。在此可行集内，以用户可接受质量为门槛，只有预计模型价差、并行收益或安全放置收益足以覆盖规划、上下文重复、合流和质量风险时，才启用 DAG，并使最终质量尽量逼近全外部强模型参照。

这是一项下一阶段的策略建议，并非已获确认的最优策略。整任务选模本身也必须通过质量门槛；当前便宜直跑路线尚未证明满足正式留出的质量要求。默认直跑不能理解为默认选最便宜模型。

正式条件路由实际多节点次数。它限制对拆分效应的估计，不证明选择器判断正确。

因此，下一阶段应研究“在安全边界内，什么任务值得拆、敏感节点放在哪里、如何让混合执行质量逼近全外部强模型”。三类优先候选是：长耗时且真正独立的并行子任务；能够可靠交给廉价或本地模型的大量节点；需要把敏感与公开内容分开处理的任务。三类候选目前均不等于已验证的收益场景。

02 / 研究问题与判断口径

研究主线是安全约束下的任务感知模型路由：先识别输入、上下文、工具结果与中间产物的隐私和数据安全要求，形成模型与部署位置的合法可行集；再根据任务内容决定整任务直跑或分解为 DAG。敏感节点优先放置在本地，或用户明确认可且满足信任、驻留与审计要求的云端。在可行集内，以用户可接受质量为硬门槛，尽量降低模型调用总费用，再追求更短等待时间，并把混合执行质量尽量逼近全外部强模型参照。

可行路线：质量达到用户门槛 ∩ 满足启用的放置约束
在可行路线内：优先最小化总费用，再比较端到端时间

质量不是必须高于强模型的“额外红利”。在预先定义的可接受范围内，质量略有波动仍可能允许节省；反过来，便宜但不合格的输出不能作为成功的省钱结果。历史加权策略 B 同时加权质量、费用、时延，与目前“质量先作为约束”的目标并不完全一致，保留为历史对照。

04 / 从节点互补到可靠组合：早期探索

4.1 局部高分能否组成更好的完整答案？

早期固定七节点报告任务使用 Flash、M3、Pro，并对候选节点在相同参考上游材料下做独立评分。任务级 oracle 在已观察单模型整图结果里事后选最好；节点 oracle 按局部评分选模型后再真正组合执行。两者都是分析工具，不能直接当作线上无成本决策器；节点 oracle 也不是全局组合最优上界。

4.2 失败如何改变了比较方式？

v0.3 的组合路线只有后两轮可比，原始均值一度把未执行首轮的低费用混入成本。后续统一了质量、费用和时延的共同样本，同时保留所有失败费用。v5 又发现一笔非空响应被记录为零用量，导致应停止而未停止；该批保留未知预留，不作为完整计量验证。v6 换用新留出材料完成独立验证。

早期成本与质量波动用于发现比较基线、组合契约和记账边界，不能作为跨任务推广的正向证据。接口、恢复准入、网络诊断、预检和模拟排练也不计作新增收益实验。

direct-strong

模型选择：忽略冻结 DAG，构造单一 answer 节点并固定使用 strong。

执行：单调用串行执行，最大并发为 1。

实际分配：比较题：answer=strong；预算题：answer=strong；改写题：answer=strong

边界：它不执行 DAG，不能说明节点路由或并行调度内部的差异。

06 / 迁移、恢复与缓存：机制有效不等于经济有效

跨场景与自动规划（联合 #39/#40）

6个校准任务、8个留出任务、104个预定条件均有尝试记录；430次调用，生产368.713 AFP、评审716.297 AFP。最终为30交付通过、49无可行路线、16质量失败、7规划失败、1生成失败、1评审不可用。

固定图的节点A/B与同图单模型A/B比较只各有4/8完整配对，集中在短输入/中风险。自动路线包含冷规划与缓存设置：32个执行条件实际节点数均为零，25个无可行分配、7个规划失败。不能把未派发产生的零执行费解释为节省，也不能据此说模型一定没有完成任务的能力。

08 / 正式留出：省钱信号与质量门槛分开看

正式留出为12题×3路线×3重复，共108次运行、397次真实调用；后续MoA输出评审与八次定向补审完成，最终统计以v5分析为准。它与上一节六题开发实验是不同批次，不合并样本。

direct-strong

任务图：不拆分；每个任务只有一个 answer 节点。

模型规则：answer 固定使用 strong，不调用 selector 或 planner。

执行：单调用串行执行，最大并发 1。

实际行为：36/36 次均为 strong 单节点直跑。

解释边界：不能说明便宜整任务选模或 DAG 拆分的收益。

task-selector

任务图：不拆分；cheap selector 只为整个任务选择一个模型。

模型规则：selector 可在 cheap、mid、strong 中选择，随后由所选模型一次完成任务。

执行：selector 后接一个 answer 调用；没有 worker 或 DAG 合流。

实际行为：36 次中选择 cheap 31 次、mid 5 次、strong 0 次；全部保持单节点。

解释边界：不能说明节点级异构路由或拆分是否有效。

direct-or-dag

任务图：cheap selector 先决定 direct 或 dag；选 dag 时再由 cheap planner 生成最多 5 个 worker 的任务图。

模型规则：direct 使用 selector 选出的 cheap/mid/strong；DAG 使用显式异构规则：最终节点或高难度/高风险节点用 strong，其他 medium 用 mid，其余 cheap。

执行：DAG 遵循依赖，最多 2 个就绪节点并行；不允许运行中再次拆分。

实际行为：35 次 direct：cheap 28、mid 7、strong 0；1 次 DAG（selector 选择 cheap 0、mid 1、strong 0），DAG 实际节点模型依次为 cheap、cheap、strong。

解释边界：若实际很少选择 DAG，臂间差异只能说明整套政策表现，不能单独归因给拆分。

09 / 质量、评审与隐私：尚未闭合的证据

10 / 由结果推导研究收敛，而不是宣布 DAG 无效

  1. 先确认局部价值。同一图内更换节点模型可以降低费用，真实并发可以减少部分等待，局部恢复可以保留成功上游。这些机制值得保留。
  2. 再检查完整反事实。相对同图全强模型的优势，没有稳定转化为相对直接回答的优势。规划、额外生成、上下文重复、合流和质量保障都消耗资源。
  3. 承认适用范围。主要样本为短构造题、少量独立任务，自动路线覆盖也不足。当前证据支持收窄部署策略，不能证明所有DAG任务无收益，更不能证明质量下降必然由拆分导致。
  4. 把决策改为有条件准入。优先尝试有质量把握的整任务路线；当存在可验证的净收益或启用的放置约束需要时，再选择DAG。保留不拆分、拒绝无可行路线和受控回退的可能。
生成链净节省 = 合格直跑的预计生成费 −（选择 + 规划 + 各节点 + 合流 + 预期失败/修复费）
部署净节省再计入两侧实际采用的在线保障费；离线研究费另列。
时间独立判断：依赖、队列、规划与合流后的墙钟是否满足目标。

成本与秒数不直接相加。若追求严格费用优先，则先冻结质量门槛与可接受时间上限，再在可行集里选低费路线；若允许花更多钱换速度，须明确用户的时间偏好。启用硬隐私约束后，违规云直跑不可作为可部署低成本基线，应与全本地直跑比较。

值得保留的候选场景为何可能成立目前缺少的验证
长耗时独立子任务分支执行重叠足够大，可覆盖规划/合流等待依赖稀疏度、任务规模、限流与排队下的收益边界
大部分节点可可靠使用廉价/本地模型模型价差或可用本地容量抵消新增调用节点合同、最终质量以及本地真实成本与吞吐
敏感与公开内容可分开处理敏感节点留本地，允许的公开部分用云从入口规划到输出/日志的泄露控制，以及相对全本地的质量成本

这三类是下一阶段的候选假设，不是本项目已经证明有效的三个领域。隐私与数据安全是所有路线的前置可行性约束；主线是在合法可行集内实现“质量达标、费用最低、时间次优”，并衡量相对全外部强模型的质量差距。

11 / 下一阶段：研究“安全约束下选择拆分的价值”

下一阶段以可交付的条件式路由能力和明确止损点为目标。将工程修复、测量校准与收益实验分别验收，避免用持续补跑代替预先界定的研究终点。

阶段要交付什么验收/停止条件
A · 零调用收尾证据与路线字典、费用分账、历史失败回放；核对已有拆分准入实现能复算现有报告；不重跑已完成历史批次；协议例外明确
B · 有限开发先判定数据等级、模型信任域与允许的数据流，再给直跑/DAG估计质量、生成费、在线保障费与墙钟隐私或驻留违规路线直接淘汰；预测不足时保守选择有质量把握的合法路线
C · 真实场景小验证从团队实际需求取独立任务，包含短题负对照与三类候选；开发/留出隔离预算、样本量、质量门槛、停止规则在调用前冻结；没有正收益也可完成
D · 选择器与放置验证在同题可比直跑与DAG基础上评估条件策略、敏感节点放置、误拆率与错过收益率零隐私违规；相比最佳合法基线质量达标，并使质量差距、费用或时间达到预定目标
E · 学习与团队记忆若有稳定可迁移信号，再学质量阈值与成本预测，记录团队反馈先证明胜过简单规则；记忆检索/探针成本一并记账，失败则停止复杂化

预算有限时采用分阶段设计：先在开发集做必要消融，留出集只保留关键主对照。不能通过只挑已知拆分有利题来估计总体收益；目标任务分布需提前定义，并保留小任务、依赖密集任务等负对照。

预先冻结的判定与停止

  • 隐私与安全：冻结数据分级、信任域、驻留规则、允许的数据流与日志策略；任何违规即判该路线不可部署，不能由质量、费用或速度抵消。
  • 质量：用户/团队定义必须满足的事实与可接受误差；盲评和确定性核验一致使用，pending保留在质量分母；另报告相对全外部强模型参照的质量差距。
  • 费用：生成链、在线保障、离线研究与本地资源分别记账；全部失败尝试进入对应分子。报告配对成本与每个合格任务成本。
  • 时间：使用端到端墙钟；独立任务不足时只报告描述统计，不声称总体p95。费用收益与时间收益分别声明。
  • 有用增益：下一批调用前由使用需求确定阈值、非劣界限与任务级区间方法，不复用最有利的历史阈值，不以“不显著”等同无效。
  • 止损：预定批次完成后若出现隐私违规、质量未达标，或节省不足以覆盖复杂性，就停止对应路线；修复采用新版本和新留出，不能不断补到成功。

关于自学习、强化学习与团队记忆

第一步是得到可信的反馈：任务类型、质量接受/拒绝、原因、实际费用、时延和放置约束。优先验证规则或简单监督预测，再考虑上下文bandit或基于模型的规划；当前证据没有支持直接引入强化学习的必要性。若引入OpenViking类团队记忆，先把它视为反馈与任务知识的可替换存储层，另行验证检索增益、泄露风险和维护成本，而非默认会改善路由。

拟议研究问题：能否在不泄露受保护数据的前提下，用调用前可获得的内容特征与少量校准，决定整任务直跑或 DAG 拆分，并将敏感节点放到本地或可信云端，使质量尽量逼近全外部强模型，同时可靠识别费用与时间的净收益区间？成功产物既可能是一套条件式路由与放置策略，也可能是可复现的“不值得拆”或“必须全本地”的适用边界。

13 / 结语：Harness 之外，任务路由还应解决什么？

这段补充讨论把研究推进到一个更具体的问题：当通用执行与反馈闭环能够由现成的 Harness 承担时，RefractRouter 应把研究投入放在哪里，才能为小型团队创造可测量的额外价值？

讨论来源：用户与 Google AI Mode 关于 DAG、Harness、隐私与成本的问答，2026-09-20读取。以下为研究者整理与判断，并非原回答的逐字结论。

13.1 把 Harness 作为可复用执行层和公平基线

讨论中，用户指出工具调用、检查与修复可能已由 Codex、Claude Code 一类 Harness 承担。这是值得验证的竞争基线：若既有执行环境已经能完成任务，再叠加规划与多模型交接，必须证明增量价值。不能只与缺乏工具或反馈能力的单次裸模型请求比较，就宣称整套路由系统更优。

由此提出的职责划分是：尽量复用执行层提供的工具、状态与反馈能力；RefractRouter 聚焦是否拆分、节点选模、执行位置、质量约束及总资源分配。已有 DAG 校验、调度、账本与宿主适配仍可保留，不必为此推翻前期工程。下一阶段同时报告裸模型与可用 Harness 基线，并对齐工具权限、材料、可用模型、修复次数和记账范围。

本项目尚未做完整的原厂 Harness 对照，不能据分享中的强判断宣布“应用层 DAG 已过时”或“原生推理必然更快更便宜”。同样，单模型多轮自我修正只能作为候选对照；有无外部反馈应分开设置，其调用、延迟与错误修正效果都要实测。

13.2 安全性：在允许的数据流中寻找可行路线

第一层是所有任务都必须经过的隐私与数据安全约束。以“内部经营材料结合公开行业资料形成分析”为例，内部材料的读取、抽取和涉及敏感信息的合流留在本地或经用户认可的可信云端；只有经策略允许的公开查询或中间信息可发往其他外部模型。规划器不能在分流前就把原始秘密送出，最终强模型也不能因负责合流就自动取得全部本地输出。

这类 DAG 的价值首先是让不同信息在各自允许的位置处理，再在合法路线中比较质量、费用和时间。基线应包括全本地直跑及可行的本地工作流，而不是违反驻留要求的全云答案。去标识化或语义摘要也不自动等于安全，须验证字段外泄、推断与组合泄露风险。

13.3 成本性：以可接受质量换取可验证的节省

第二条研究分支延续原始主线。选择真正独立、工作量足够大的分支，例如多份独立材料的字段抽取或逐件检查，使用廉价/本地模型并行执行，再按所需能力完成合流。用户允许的质量损失应在运行前明确为质量底线或非劣界限；只要达到该标准，就不要求 DAG 额外赢得质量红利。

关键变量包括任务规模、依赖密度、模型价差、本地吞吐、上下文重复量和合流负担。结构化交接是一项值得消融的设计，但必须保留证据、约束与不确定性；强模型合流也应与低价或确定性合流比较，不能把它当作固定最优答案。本地模型的边际接口费可以设为零的模拟情景，真实运行成本和排队时间仍应单列。

研究展望

因此，RefractRouter 下一阶段的贡献应落在：在确保用户隐私与数据安全的前提下，判断何时保持整任务执行、何时值得分拆，将敏感节点交给本地或可信云端模型，并让混合执行质量尽量逼近全外部强模型。安全约束先定义哪些方案合法可用；质量门槛再排除不可接受的结果；费用与时间用于选择剩余方案。DAG 是实现这种条件式选择与安全放置的工具；对不值得拆分的任务可靠地选择直跑，对无法安全外发的任务选择全本地，也都应被视为研究成果。
