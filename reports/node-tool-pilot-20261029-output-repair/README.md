# 模型输出容量与错误回执修复

本修订按用户明确指示取消人为低输出上限，并继续已批准的 node-as-tool 三路线先导。

## 原因

`live-01` 首个真实请求使用 8192 输出额度，提供方返回 `length`。
这证明该请求没有完成；不证明模型能力差，也不能证明思考是唯一原因。
DSH 原生适配器错误路径仍发送用量，但 `PlanningController` 在错误时直接取消、跳过结算，
让可结算的错误变成了未知用量。原始宿主未归档流事件，因此不能事后虚构该次实际用量；
旧账本的 0.63 AFP 保守预留继续保留。

## 修复

- 主请求、专家、规划器、DAG 节点均使用目录支持的 384000 输出容量；保留思考设置。
- 规划账本按实际请求容量预留，取消旧文本协议隐藏的 8192 上限，输入和流缓冲随容量调整。
- 错误带有效用量时先结算；SDK 错误默认零用量仍不能冒充真实账单。
- 取消后的迟到回执仅结算，保留取消状态，不能交付候选。
- 长度不停止整批；未完成交付与事实错误分开统计。
- 原始请求和响应直接归档，不新增请求、不记录认证头或凭证；归档失败不能被成功结果掩盖。
- 新协议累计包含原一次请求和 0.63 AFP；286 AFP 与 135 次请求不按目录重置。

官方容量来源：[Ark Agent Plan 模型清单](https://www.volcengine.com/docs/82379/2366394?lang=zh)，
于 2026-10-29 重新核对 `deepseek-v4-flash`：上下文 1024k、最大输出 384k。
