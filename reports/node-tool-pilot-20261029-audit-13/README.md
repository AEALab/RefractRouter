详见前一份审计。本例不能归因于专家协助，因为它没有发生。
主分析仍保留这个样本，机制覆盖分析另标记未触发，不按结果筛除。

一次性回答缺少 `technical_finish`、`critical_path` 规定的来源；
规划路径缺少 `technical_finish` 规定的来源。这些是冻结覆盖规则的差异，不是数值错误。
同模型也不等于完全相同请求：工具说明、主提示追加提醒和各路线上下文投影不同。
本组不能当作专家调用或拆分的单因素因果证明。

输出量也有明显差异：一次性回答 19705 token；工具可用路线 5829；
规划、提取、排程计算和最终交付共 31002。均包含思考，输出容量都是 384000。
不同输出量影响费用和等待，不能仅凭这一次结果解释模型内部为何这样生成。

包含旧诊断和原始失败预留，在途调用另有保护。原始回执、关联、参数及费用审计错误数为 0。
