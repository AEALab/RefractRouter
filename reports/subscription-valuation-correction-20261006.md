# 保留 Ark 订阅执行的金额估值修正

## 决策

用户明确要求保留 Ark 订阅模型，仅取消 AFP 计价。公开价格用于参考成本；
订阅调用不能据此计为现金扣款。实际执行渠道不因估值来源而更换。

## 本次实现

`currency_pricing.subscription_valuation` 分开保存执行路线与价格快照，要求
明确的版本映射证据，并保留原始币种、汇率和用量。结果标记为订阅参考估值，
现金费用为未按调用归集，不参与现金预算；没有假定订阅月费为零。

更新迁移设计，保留订阅渠道偏好，分别规划参考成本与按量 API 费用上限。

## 订阅优先独立于价格单位

统一 CNY 后，原混合 AFP／CNY 排序不会自动保留订阅优先。因此新增明确的模型计费
属性用于 v6 自动执行的节点分配和执行候选比较：先满足质量及运行约束，再减少额外
现金支出，最后按既有参考成本目标排序。候选支配消除也检查现金成本，不能提前删掉
参考价较高但不逐调用扣费的订阅候选。历史配置和基线保留原排序。

针对性测试 63 项通过，覆盖订阅优先、质量不合格排除、历史排序、DAG 参考成本更高
但新增现金更低的不同结论，以及媒体迁移。完整回归已另行启动；安装仍未进行。

补充边界检查：参考预算预留现在与底层预留一致，采用未缓存输入与缓存写入的较高价，
避免订阅缓存写入较贵时绕过参考上限。13 项订阅账本测试通过。新增宿主契约用例检查
迁移前补齐缺失缓存价格且不修改原配置。原 profile 的插件列表已通过官方 CLI 核对，
仍链接本工作树；尚未更新已安装 Python 核心。
