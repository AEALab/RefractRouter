2026 年企业 LLM Agent 平台选型研究报告

报告编号：report_001 ｜ 面向场景：RefractRouter v0.1（任务 DAG 节点级模型路由）｜ 依据：冻结来源包（8 份）

一、执行摘要

本报告针对企业级 LLM Agent 平台在 RefractRouter v0.1 场景下的选型进行系统评估。RefractRouter 的核心研究问题是：现有 LLM 路由工作大多针对整个请求选择单一模型，而 RefractRouter 探索在任务 DAG 的每个节点上分别选择模型，能否改善质量—成本—延迟的帕累托前沿[source_005]。

基于冻结来源包中的证据，本报告得出如下核心结论：

  • 执行底座选 LangGraph：LangGraph 是面向复杂工作流的图状态机框架，支持显式节点、边、持久化状态与检查点，RefractRouter 将其用作固定任务 DAG 的底层执行基座[source_002]。
  • 上层编排选 DeepAgents，但须收敛能力边界：DeepAgents 是基于 LangGraph 构建的 LangChain 编排壳（harness），提供规划、子代理、文件系统抽象与人机协同控制；在 RefractRouter v0.1 中可用作固定 DAG 执行壳，但其自主规划与动态子代理生成能力必须保持禁用[source_001]。
  • Pydantic AI 暂不纳入核心依赖：Pydantic AI 提供类型化工具定义与结构化模型输出，适用于严格 schema 场景；但 v0.1 阶段除非结构化输出解析成为瓶颈，否则不作为核心依赖[source_003]。
  • DeepSeek Harness（DSH）限定于外围验证环境：DSH 是一种"代理循环本身即插件"的代理壳，在 v0.1 中保留给外部验证环境使用，不进入核心路由循环[source_004]。
一句话结论：采用"LangGraph（执行基座）+ DeepAgents（受约束的编排壳）"的双层架构，Pydantic AI 作为条件性备选，DSH 隔离于验证侧——该组合最贴合"固定 DAG 输入 + 节点级模型选择"的 v0.1 边界定义[source_001][source_002][source_006]。

二、背景

2.1 问题域：从"请求级路由"到"节点级路由"

企业 LLM 应用的成本与延迟压力，使"为任务选择合适模型"成为平台选型的关键议题。然而，现有 LLM 路由研究大多为整个请求挑选单一模型，粒度偏粗。RefractRouter 提出的研究问题是：若在任务 DAG 的每个节点上独立选择模型，能否在质量、成本、延迟三者之间取得更优的帕累托权衡[source_005]。这一研究定位直接决定了平台选型的技术前提：平台必须支持显式、固定的 DAG 结构与节点级执行控制，而非黑盒式的自主代理。

2.2 架构边界：静态分解归应用层，动态重拆分延后

选型必须尊重已冻结的架构边界：静态任务分解属于应用层职责，路由器接收 DAG 作为输入，专注于逐节点的模型选择；动态重拆分（dynamic re-splitting）在节点级路由得到验证之前予以延后[source_006]。这意味着平台评估的首要标准不是"自主规划能力有多强"，而是"能否在固定 DAG 上提供可控、可观测、可复现的执行"。

2.3 评估基础设施：基准与评分体系先行

选型的有效性依赖可复现的评估。一个有用的路由基准需要：固定任务 DAG、多个候选模型、逐节点与逐任务评分、成本核算以及关键路径延迟；首个基准应保持足够小以便复现[source_007]。同时，v0.1 评分细则对需求覆盖、证据准确性、分析深度、结构与可读性、HTML 有效性进行加权，且评分提示词与细则版本必须与运行记录一起版本化[source_008]。因此，所选平台必须能与该基准/评分体系协同，支持逐节点指标采集。

依据上述背景，本报告提炼出六项选型标准。每项标准均可追溯至冻结来源：

4.3 取舍分析

为什么是"LangGraph + DeepAgents"而非单一平台？ LangGraph 提供的是底层图状态机能力（显式节点/边、持久化状态、检查点），它解决"确定性执行"问题，但不直接提供编排层的人机协同与文件系统抽象[source_002]；DeepAgents 恰好构建于 LangGraph 之上，补齐编排壳层能力[source_001]。二者是"基座—壳层"的互补关系，而非互斥替代。选择组合的代价是必须治理 DeepAgents 的自主能力：其自主规划与动态子代理生成与"静态分解归应用层"的边界相冲突，必须显式禁用[source_001][source_006]。

为什么 Pydantic AI 不进入核心？ 其价值（类型化工具定义、结构化输出）在严格 schema 场景下显著，但 v0.1 的首要矛盾是节点级路由而非输出解析；来源明确指出除非结构化输出解析成为瓶颈，否则不应作为核心依赖[source_003]。提前引入会增加依赖面与认知负担，违背"首个基准保持足够小以便复现"的原则[source_007]。

为什么 DSH 被隔离到验证侧？ DSH 的差异化在于"代理循环本身即插件"，这对验证环境极具价值——可在不触碰核心路由循环的前提下替换执行策略进行对照评估[source_004]。但正因如此，它应被保留在外围，避免核心循环的执行语义被插件化机制稀释，从而保证基准的可复现性[source_007]。

五、风险

R1 能力越界风险（高优先级）。若 DeepAgents 的自主规划或动态子代理生成被意外启用，DAG 结构将在运行期被改写，直接违反"静态任务分解属于应用层、路由器仅做逐节点选模型"的边界定义，使节点级路由实验失去对照意义[source_001][source_006]。缓解：在平台接入层以配置与代码评审双重手段锁定相关能力，并将该约束纳入运行记录的版本化资产[source_008]。

R2 指标不可复现风险。路由研究依赖固定 DAG、多候选模型、逐节点/逐任务评分、成本核算与关键路径延迟；若基准过大或评分资产未版本化，结论将无法复现[source_007][source_008]。缓解：首版基准保持小规模；评分提示词与细则版本随运行记录一并版本化[source_007][source_008]。

R3 依赖膨胀风险。将 Pydantic AI 过早纳入核心依赖，会在尚未出现结构化输出瓶颈时增加系统复杂度[source_003]。缓解：以"结构化输出解析是否成为瓶颈"为显式触发条件，按需引入[source_003]。

R4 验证环境污染风险。若 DSH 的插件化代理循环渗入核心路由循环，核心执行语义将随插件变化而漂移，损害实验稳定性[source_004]。缓解：在架构上将 DSH 限定于外围验证环境，核心循环仅依赖 LangGraph 基座与受约束的 DeepAgents 壳[source_001][source_002][source_004]。

R5 范围蔓延风险。动态重拆分具有吸引力，但来源明确要求在节点级路由被验证之前予以延后；提前引入会混淆研究变量[source_006]。缓解：将动态重拆分列入 v0.1 之后的路线图，以节点级路由验证结果为前置条件[source_006]。

5.1 本报告的局限性

  • 本报告仅基于 8 份冻结来源，未纳入各平台的性能基准实测数据、价格信息或社区生态指标；相关维度无法在来源内得到证据支持，故不作断言。
  • 来源对 Pydantic AI 与 DSH 在 DAG 执行、可观测性等维度的能力描述有限，比较表中相应单元格标注为"未覆盖/不适用"，反映的是证据缺口而非平台缺陷[source_003][source_004]。
  • 结论的适用范围限定于 RefractRouter v0.1 的"固定 DAG + 节点级路由"场景；当动态重拆分被提上日程时，选型结论需重新评估[source_006]。

六、结论

综合六项选型标准与四平台证据，本报告给出如下有依据的结论：

  1. 采用"LangGraph + DeepAgents"双层架构作为 v0.1 核心。LangGraph 作为固定任务 DAG 的底层执行基座，提供显式节点/边、持久化状态与检查点[source_002]；DeepAgents 作为其上的编排壳，提供规划、子代理、文件系统抽象与人机协同控制，但其自主规划与动态子代理生成必须保持禁用[source_001]。该组合直接服务于"在任务 DAG 每个节点上分别选择模型以优化质量—成本—延迟帕累托前沿"的研究目标[source_005]。
  2. Pydantic AI 设为条件性备选。仅当结构化输出解析成为瓶颈时引入，利用其类型化工具定义与结构化输出能力；在此之前不作为核心依赖[source_003]。
  3. DSH 固定于外围验证环境。利用其"代理循环即插件"的特性支撑对照验证，但不得进入核心路由循环[source_004]。
  4. 以小型可复现基准与版本化评分体系作为选型的验收闸门。基准须包含固定任务 DAG、多候选模型、逐节点/逐任务评分、成本核算与关键路径延迟，并保持足够小以便复现[source_007]；评分细则（需求覆盖、证据准确性、分析深度、结构与可读性、HTML 有效性加权）及其提示词版本须随运行记录版本化[source_008]。
  5. 严守范围边界。静态任务分解留在应用层，动态重拆分延后至节点级路由验证之后[source_006]。
