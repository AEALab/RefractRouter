# 采样控制修订与原授权接续

## 发现与处理

预检曾检查模型身份、输出容量、次数和费用，但漏掉了两套客户端实际 HTTP 正文的采样对照。
DSH 的原始请求显式 `temperature=0`；旧 Python DAG 的 Responses 正文未显式携带温度。
原因是客户端为 Responses 重建正文，Chat Completions 默认正文中的零温度没有被继承。
这是研究控制项遗漏，不能把旧 DAG 与 Native 的差异归因于路线。

`live-03` 在最后一个在途 DAG 请求完成并结算后，以 `stopped-implementation-changed` 结束。
保留 31 个阶段样本、原输出、轨迹、评分和费用；其中导入的 3 个基线样本不重复计费。
只读账本审计见 `../node-tool-pilot-20261029-audit-07/audit.json`：54 次累计真实请求，
32.987900 AFP（包含历史未知用量预留 0.630000 AFP），证据核对无差额。
这项审计只核对费用与证据，不证明旧比较具有同采样条件。

## 付费前的防复发检查

三条路线的实际序列化请求必须显式 `temperature=0`，完整输出容量 384000；
思考和 `top_p` 均为提供方默认。DAG 派发前拒绝不符合冻结控制的正文，
DSH 传输边界也检查实际温度。并发 DAG 使用线程局部的原始 HTTP 关联，
本地模拟两节点并行验证它不会随响应完成顺序串账。

新增测试通过真实客户端序列化路径，将规划、工作与最终交付的模型、温度、输出容量、
`top_p` 和思考字段与已保存的 Native 请求对照。原始响应记录提供方精确模型版本和用量，
审计另行重算 AFP，不把 `reasoning_tokens` 再加到总输出上。
该检查不发送真实模型请求，不读取或归档认证头。

已取消的小输出额度和人为超时不恢复：主循环、专家、DAG 规划及执行使用完整模型输出容量，
不限时贯通 Python 调度、HTTP、DSH 和专家层；真实费用、调用次数、人工取消与未知用量规则继续有效。

## 时序与结论边界

复用样本节省重复调用，也使部分配对不再保持原先的时间交错。
除完整 9 组主分析外，在新预检时按来源预先冻结 5 组全新采集配对：
发布与流水第 2 轮、三个任务第 3 轮。补充分析不按结果选组。

DSH 流式和 Python 非流式路径、职责提示与上下文投影仍有差别；此先导比较当前整体实现，
不能当作单因素因果实验。字段与来源覆盖检查也不能替代独立语义审查。
先前首组三路线和第一轮报告已加醒目标注，涉及旧 DAG 的费用与时延差异只供诊断。
Native 对 Native 的原始比较未因这一采样遗漏失效，但仍只是三个开发任务的有限观察。
