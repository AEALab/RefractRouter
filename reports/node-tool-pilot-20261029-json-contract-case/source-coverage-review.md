# 冻结来源覆盖规则的解释边界

本记录为助手的事后规则回读，不是独立人工评审，也不改冻结分数。
它同时适用于一次性回答、按需专家和 DAG，不用于重新选择提示或调优当前样本。

## 已核对的具体规则

公开材料 s1 标题为“有效工作清单”，完整给出 A—G 的当前时长、依赖与两槽限制。
s2 是“版本修订”，说明旧 A=4、C 依赖 B、F=1 三项已经被有效清单替代。

冻结参考对 `technical_finish` 与 `critical_path` 要求每个字段同时引用 s1、s2。
公开交付合同只规定 sources 使用材料 source_id，没有逐字段公开这个必引集合。

仅用 s1 的有效图即可推出 A—B—F—G、总长 12，以及达到该下界的可行排程。
s2 为版本选择提供额外背景，但不提供计算 12 所需的新时长或依赖。
因此“计算正确、字段仅引 s1”被当前检查器扣分，准确含义是：
**未达到冻结的来源覆盖口径**，不能直接推成数值错误，
也不能据此单独证明结论缺乏逻辑支持或整份业务答案不可接受。

## 本案例的两个问题分别保留

发布排程第一轮按需专家样本原始 JSON 含未转义换行，原主判据仍为 fail。
只读宽容解码后，数值和条件字段核对正确，但上述两个字段仍未达到来源覆盖口径。
一次性回答对应样本也有相同两个来源覆盖扣分，但其 JSON 解析成功。
这些不同性质的问题不能压成“两个模型都算错”，也不能因为宽容解码可读就把原分数改成通过。
