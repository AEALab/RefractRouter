# Advisor Gate v2 有限验收

## 范围

本批次验证严格两次审核、一次返工、标准 Base URL 接口、三个客户端的宿主工具边界，
以及 LLM 与本地 Laya 两类审核器。此次不做收益对比，也不以小样本推断普遍准确率。

冻结题集为 `data/benchmarks/advisor-judge-v1.json`，共 24 条，中文、英文、混合语言
各有覆盖；合格、明确缺陷、证据不足、返工复审各 6 条。

## 审核器结果

| 批次 | 匹配 | 明确缺陷被批准 | 合格批准 | 证据不足被批准 | 复审匹配 | 费用 | 结论 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | --- |
| LLM 原合同 | 22/24 | 1 | 6/6 | 0 | 6/6 | 0.40775 AFP | 未通过 |
| LLM 修订合同 | 23/24 | 0 | 6/6 | 0 | 6/6 | 0.46560 AFP | 通过有限门槛 |
| Laya 原合同 | 7/24 | 3 | 0/6 | 1 | 2/6 | 无 API 费用 | 实验 |
| Laya 修订合同 | 7/24 | 2 | 0/6 | 0 | 1/6 | 无 API 费用 | 实验 |

LLM 修订批次唯一不匹配案例是把一条明确缺陷判为 `UNRESOLVED`。该结果会停止交付，
没有误放行，因此满足“明确缺陷不得批准”的安全门槛。两次 LLM 批次合计 0.87335 AFP，
均为一次派发、零 HTTP 自动重试，旧失败证据没有覆盖。

本地修订批次冷启动 1160.9 ms，暖机中位数 35.2 ms；响应很快，但质量没有达到日常
使用门槛。它继续显示为实验选项，不能静默替代 LLM 审核器。

## 三客户端接线

DSH、Codex、Hermes 均使用实际安装的 Agent 循环连接 `refract/advisor`。每个客户端
运行两条确定性流程：

1. 执行模型请求宿主工具，工具结果续接后形成最终回复并首次审核通过；
2. 受控错误候选被首次审核要求返工，返工请求宿主工具，工具结果续接后经过第二次审核。

| 客户端 | 正常流程 | 返工复审 | 工具归属 | 上游费用 |
| --- | --- | --- | --- | ---: |
| DSH | 通过，3 次模型步骤 | 通过，5 次模型步骤 | DSH | 0 |
| Codex | 通过，3 次模型步骤 | 通过，5 次模型步骤 | Codex | 0 |
| Hermes | 通过，3 次模型步骤 | 通过，5 次模型步骤 | Hermes | 0 |

这六条使用确定性模型夹具和真实 Router 核心，证明客户端协议、工具归属、候选缓冲、
返工状态及复审闭环。它们没有调用真实上游模型，不能单独证明自然任务质量。真实审核
质量由上述 24 条 Ark Judge 批次提供；两类证据不得合并成“完整真实任务收益”。

Hermes 当前安装的源码入口使用 Python 3.11，但活动依赖环境为 Python 3.14。初次按旧
入口运行因二进制扩展版本不匹配而在零上游调用时失败；验收驱动改为显式使用当前活动
环境后通过。失败证据保留在本地，不把环境问题归因于 Router 策略。

## 确定性覆盖

- 首次通过、返工后通过、返工工具续接、第二次拒绝、无法判断、非法 Judge 输出。
- 被丢弃工具调用不执行，已完成工具不重复执行，候选不进入正常历史。
- v6 显式升级、旧配置读取、预算完整路径、调用上限、费用与轨迹。
- 标准 Chat Completions／Responses、DSH 插件工作进程和三个客户端原生工具循环。

完整回归结果在 PR 中记录。原始付费回执保存在 `llm-judge/` 与 `llm-judge-v2/`；
本地结果保存在 `local-laya.json` 与 `local-laya-v2.json`。客户端原始请求与宿主路径仅
保存在本地忽略目录 `.refractagent/acceptance/advisor-gate-20260928/`。

## 结论与限制

严格 Advisor Gate 的产品状态机和 LLM 有限审核门槛已经通过。Laya 路线保持实验状态。
本批次没有验证图片或影片审核、自然任务收益、长期并发、P6 子 Agent 共享预算，也没有
把确定性接线结果描述为真实模型质量证据。
