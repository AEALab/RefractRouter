# DSH 与官方 Jev 真实接线验收

2026-10-03 在用户原有 DSH `web` profile 上，以临时启动补丁完成有限真实验收。
用户授权 Jev 在本次验收中接收可能含本机绝对路径的判别输入，并授权最多
12 次官方 Jev 调用、0.25 CNY。执行模型继续按 Ark AFP 单独记录。
[冻结预检](preflight.json)保留调用前的原始状态；其中的「未授权／未执行」
描述是当时的快照，不代表本报告的最终状态。

## 结果

- 官方 Jev `jev-1.13.0` 实际派发 **10 次**，按各调用确认的输入 token 和
  冻结价格合计 **0.017126882 CNY**，低于授权上限。
- 13 次有记录的 DSH 尝试消耗 **62.73045 AFP**，其中 10 次完成、3 次在
  Jev 派发前失败。完成的 10 次中，有一次 Composite 因接管模型缺能力卡而
  没有调用 Jev；修正临时验收配置后，Composite 的 Task 与 Stage 两个判别
  环节均被真实调用。另有一次更早的零调用阻断未产生运行记录。
- 这 13 次运行的 29 条受管调用均为已确认计费状态，没有未知用量或待核对预留。
- Advisor 最终回复审核通过，并在另一任务中完成一次宿主原生工具续接。
  Escalation 正常放行；通过仅用于验收的高门槛配置，另验证了不确定时
  丢弃高效候选并由接管模型完成回复。
- Task 完成一次任务级选择，原始概率 0.48 时按规则选择备援。
  Stage 在宿主原生工具后调用 Jev，选择继续高效模型。
  Composite 在受控设置下先完成 Task 选择，再于工具后完成 Stage 判别。
- 重启后的补验确认「路由轨迹」同时显示实际模型、Judge 原始分类、
  单次 Jev CNY 与累计 CNY；本次补验显示 **0.00202324 CNY**。
  [逐次摘要](results.json)只包含运行 ID、用途与费用，不含请求内容或凭据。

## 验收中发现并修正的问题

1. 旧安装核心以 **32,000 字节**限制 Jev 判别输入，误把 32k token
   容量当成字节数。测试临时服务改用本工作树核心后，改为 96 KiB 本地
   技术保护上限，并投影必要的消息与候选字段，避免重复发送 replay 数据。
   服务端仍负责实际 token 容量判定，超出时不会隐式截断。
2. Jev 单次 CNY 费用已记录，但旧代码在任务结束重算汇总时遗漏非 token
   调用，导致历史运行的汇总显示 0 CNY。已修正账本并以新真实调用验证。
   历史原始记录未被篡改；本报告按已确认的单次费用重新求和。
3. 路由轨迹遇到本地 Judge 时延等可选字段为 `null` 时会整页空白。
   已修正前端数值显示，并在浏览器验收。

## 验证与边界

- 完整无网络测试：`1480 passed, 5 subtests passed`；TypeScript 类型检查和
  插件构建通过。普通沙箱曾阻止 13 项测试绑定本机回环端口；允许本机端口后
  全部通过，该失败并非策略断言失败。
- 真实案例证明五种策略的上述接线流程，并不证明 Jev 在自然任务中的
  判别正确率或 Router 的质量收益。Advisor `REDO` 与 Escalation 自然
  缺陷触发仍由确定性测试覆盖，未在本批付费样本中声称完成自然场景验收。
- Composite 的两段判别和 Escalation 接管使用了明确标记的临时受控设置；
  不作为默认参数效果证据。本批未验证 Codex、Hermes 接入。
- 原 DSH 设置在验收后从字节级备份恢复，SHA-256 均为
  `1550425629e5c8d139b614b1826d6885282f02e1ede39a59890f2be05c1c5dea`。
  原端口 `3080` 的用户服务未被替换；临时端口 `62581` 已关闭。
