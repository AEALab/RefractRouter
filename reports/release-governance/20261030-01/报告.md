## 交付内容

- 固定 Gateway v2 配置、schema、价格单位、精确版本声明、核心源码及资源身份。
  原生费用包络无法证明时拒绝新治理入口，不截短原生输出。
- Python 本机管理命令及可选 Gateway v3：登记资格、有限显式试用、停止、回滚、漂移待复核、
  历史查询和监控。新任务固定发布，任务内仍执行原策略；不新增工具执行或第七种选模策略。
- Composite 校验真正内嵌的 Task / Stage 及每种可能初始模型，逐题关联组件费用、质量、
  相同工具/宿主/交付边界和强基线；对两组件都没有增量收益则拒绝准入。
- 单机单派发进程、固定执行根、持久所有者及请求摘要；旧任务重启只查询，不自动重发。
  回滚只改变新任务，未知预留和在途费用保持。
- 实际 Chat 模型及 provider 回执身份观测，费用或身份未知即停止；完整交付、独立误升级、
  返工、可比全费用预测误差与费用异常的只读监控，不在线训练或静默修改模型池。

使用方法及可信边界见[版本治理说明](../../../docs/routing-release-governance.md)。

## 独立审查与修复

两位独立 AI 分工审查，并在精确提交 `3167685dc` 上复核最后四项 P2：

| 问题 | 修复与反例 |
| --- | --- |
| 核心结算才发现缓存写入费用未知，试用仍活动 | 最终原账本未知即待复核并停止试用；预留不释放 |
| 历史与执行缓存互相覆盖，丢失新任务结果归属 | 历史对象提升为执行对象，共享状态与内锁；并发 save、再次重启仍可读 |
| 缺少原记录时合计把未知预留表示为零 | 汇总完整性为 false，金额为 null；仅另列可读小计 |
| 较早正文 PASS 越过后续工具候选 | 先取最后接受候选，再要求正常终止及独立完整标签，否则 UNKNOWN |

此前已修复重复派发、匿名历史前缀、匿名任务结束、实现身份与资格上下文、混合费用单位、
组合实际参数和增量基线关联等问题。最终限定复核确认所报问题闭环；AI 审查不冒充人工审批。
