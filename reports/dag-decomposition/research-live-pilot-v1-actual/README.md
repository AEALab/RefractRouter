## 发现并修正的执行缺陷

SQLite 两个失败答案都没有明确给出读取外键状态的步骤，K3 据冻结条目判为未通过。
检查实际请求后发现，完整验收条目传给了自动规划器与最终评审，
却没有显式传给人工计划、直接回答和节点探测的生成请求。
模板中的 `covers` 只是条目序号，不能替代条目正文。

因此本批路线间并非完全相同的信息条件，不能用 SQLite 的分数差推断自动规划收益。
这是输入契约缺陷；原始批次在冻结实现下完成并归档后，才修改研究执行器。
修复将原始验收条目追加到各生成请求的任务正文，并同时用于校准节点探测。
三项新测试在修复前全部失败，修复后通过；未修改原始任务条件或这批响应、分数。

另在新目录开展 SQLite 直接回答与人工 DAG 的针对性真实回归，最多 6 次调用、203 AFP。
首批实际用量与回归最坏情况之和仍低于初始 84 次调用及 2219.2129 AFP 包络。
该回归重复已观察材料，只验证修复，不能作为新的独立留出样本。
