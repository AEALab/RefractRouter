# 研究开发执行演练

本记录是 #39、#40 的开发流程验证，不是真实迁移或收益实验。真实模型调用为 0，实际付费为 0。

## 执行与结果

```bash
uv run python -m experiments.rehearse_research_execution \
  --output-dir /tmp/research-development-new
```

入口强制禁用网络，使用模拟客户端和草案开发夹具。三份草案校准材料降为开发夹具，
另一个开发任务用于执行验证；没有使用草案 test 材料。

- 100 次模拟调用全部结算，15 条对照运行全部通过模拟交付评审。
- 27 条独立节点探测记录绑定各自的输入、输出及评审哈希，生成的 profile 明确标为 `synthetic`。
- 整任务 A/B 从完整校准矩阵冻结；测试检查留出 ID 重叠、矩阵缺项和重复记录均被拒绝。
- 跑通节点 A、同图单模型 A、固定强模型人工及自动 DAG，以及同一计划的两次复用。
- 缓存设置仅发生一次；复用不会再次规划，也不会把初始设置费用当作零。
- 101 个归档文件哈希全部核对通过。模拟账本为生产 3.276、评审 7.92，
  两者之和与 `runs`、`probe_runs`、`plan_setups` 的费用总和一致；这些数值不是实测费用预测。

原始产物位于 [output/session.json](output/session.json)，
完整性索引位于 [output/artifact-index.json](output/artifact-index.json)。

## 故障验证

新增 17 项执行与校准测试通过，覆盖：

- 已结算的不合法节点输出保留费用，允许下一独立样本继续，不重置预算或调用计数。
- 未知用量、证据写入异常、缓存内容变更停止整批。
- 结构不合法的计划归档后拒绝，失败缓存不重新生成计划。
- 缺少 profile 时明确无可行路由，不强制混用模型。
- 节点探测失败保留账单并作确定性拒绝，不用整任务分数填充节点观测。
- 不允许用 test 材料校准，也不忽略校准矩阵中的失败样本。

完整回归：`uv run pytest -q`，577 passed、5 subtests passed，耗时 55.71 秒。
新增 K3 精确代码快照兼容记录；既有 K3 runner、调用提示和历史原始证据均未修改。

## 适用边界

`ResearchSession` 已接入现有节点执行器、评审和账本接口，但正式研究仍需完成矩阵编排、
真实异构交接、独立材料审查、成本分类及 #40 人工复核。没有新增正式付费 CLI。
规划语义不通过的结构合法计划会继续执行以观察错误传播；这不表示该计划已经通过验收。
开发演练中固定强模型的自动规划不冒充节点 A/B 收益证据。

`session.json` 的局部 `deployment_cost` 暂含本次样本的生产和全部评审费用；
正式分析须另外拆分部署必要评审与纯实验评审，校准及缓存设置也不能遗漏。
#39、#40 仍保持开放，#41 按用户要求不处理。
