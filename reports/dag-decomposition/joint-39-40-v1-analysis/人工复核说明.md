# 人工复核说明

本目录中的 `human-review-packet.json` 在批次结算后生成，包含预先抽样的计划、
实际节点输出和最终交付；不包含路线、模型和自动评分。请先不要打开单独的映射文件。
计划风格和节点命名仍可能透露生成方式，因此只做身份字段盲化，不宣称完全消除评审偏差。
请按题目证据判断，不因节点多、文本长或看似人工编写就提高评价。
`reference_for_review` 是冻结参考；长材料的全部统计字段已另用脚本从原始文本重算。
同一题只需先理解一次来源与正确结果，再分别核对各编号的计划和交付，不必机械重复手算全表。

请复制一份复核包，在每条记录中填写以下字段，保留原始题目、计划及输出原样：

- `reviewer`、`reviewed_at`：真实复核者和日期，可使用团队能识别的姓名或昵称。
- `decomposition_appropriate`：拆分是否适当；短任务单节点可以通过。
- `original_delivery_covered`：计划中的节点职责是否覆盖原始交付要求。
- `dependencies_correct`：计划依赖是否真实必要、交接字段是否充分。
- `parallelism_appropriate`：并行或串行安排是否符合信息依赖。
- `handoff_risks`：来源、条件、计算或信息在交接中是否丢失；没有也需注明。
- `execution_findings`：实际输出是否完成交付，是否发现错误传播；未执行或缺失时如实注明。
- `overall_passed`、`rationale`：计划语义的总体判断和具体理由，不替代实际交付评分。

判断字段填写 JSON 布尔值 `true` 或 `false`。计划无效、未执行或输出缺失也必须复核，
不能删掉记录。计划覆盖要求与实际完成交付分开记录；缺少输出不能写成已经完成交付。
拒绝的计划可以说明其失败合理性。
缺乏足够证据判断时填写 `false` 并在理由中明确“证据不足”，不要虚构已经观察到的错误。

在顶层添加 `reviewer_attestation`：

> 本人已阅读材料并独立填写，以下记录为真人复核。

完成后运行：

```sh
uv run python reports/dag-decomposition/joint-39-40-v1-analysis/review.py /绝对路径/已填写复核包.json
```

该入口只校验原始材料未变、样本完整、字段和判断一致，生成带文件摘要的回执。
它不能验证真实身份，也不代替真人阅读。不要让模型自动填写或签署真人声明。
复核结论可以不通过；完成复核不等于证明自动规划有收益。
