# Issue #38 真实恢复对照

本轮完成 18/18 个计划样本及独立最终评审，14 个通过交付标准。
观察到一次真实的局部节点切换，并保留成功上游；另外两组没有触发节点恢复。
**不能据此证明局部恢复提高总体交付率，也没有观察到局部组节省平均费用或时延。**

实际调用 73 次，生产 **26.62985 AFP**、评审 **35.089 AFP**，合计 **61.71885 AFP**。
全部 73 次用量完整结算，没有未知用量预留，没有底层 HTTP 重试。
代码、模拟机制验收及此前预检见 [PR #46](https://github.com/AEALab/RefractRouter/pull/46)；
本报告不替代 #22 的 oracle 实验、#8 的最终报告或自动规划验收。

## 唯一真实恢复

排班工具第 1 次重复的局部组中，M3 风险节点返回了包含未转义英文双引号的 JSON；
原始文本在字符偏移 567 处不能解析。请求结束标记为正常结束，但输出不满足结构契约。
该失败请求结算 **0.35275 AFP**，没有当作免费失败丢弃。

风险节点切换到 V4 Pro，替换调用结算 **0.4851 AFP**；两次风险请求输入 SHA-256 相同。
成功的成本节点仅执行一次，汇总节点仍为 M3。最终路线实际是
`cost=M3, risk=V4 Pro, answer=M3`，属于异构分配。
样本最终评分 92、通过，含评审总费用 **3.8781 AFP**、墙钟 **98.45 秒**。
逐次记录在 `run/result.json` 的 `recovery38_support_v1 / repeat=1 / local-node-switch`。

这个样本证明了真实结构故障后的局部替换、成功分支复用及全量记账路径可用。
另外两组对应任务没有遭遇同一故障，不能充当这次失败的同事件反事实。
全图重跑只完成了真实对照组执行，没有观察到实际的整图替换触发；
其重跑和废弃分支记账仍由此前确定性故障证据支持。

## 共同配对与不确定性

每项比较使用相同的 6 个任务/重复配对，包含质量未通过但已评分的产物；没有排除配对。
只有 **3 个独立任务**，不能把两次重复当成 6 个独立任务。
按冻结的任务聚类 bootstrap（2000 次、种子 38）报告探索性 95% 区间。

## 评审口径的限制

人工核对发现内部翻译第 1 次重复的全图组评审理由也含算术矛盾：
它一处称计入复审费后没有盈亏平衡点，另一处又提到 360 千字。
按冻结材料，两个方案的复审单价相同，差额为 `9000 - 25 × 千字数`，
盈亏平衡点应为 **360 千字**。被评产物中的 **1800 千字**也确实不正确。

本报告仅复算材料并记录这一限制，不更改 K3 的原始评分、通过标记或配对集合，
也不把局部人工核对称为全面人工验收。后续若改进评审提示或加入标准事实，
须建立新协议；不能事后修分以改善当前结果。
