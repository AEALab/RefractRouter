# Issue #32：对称基线与真实跨模型交接

本轮补齐同一 DAG 的单模型 A/B 对照，并取得四种显式异构组合的真实交接证据。
六种组合未全部通过；八组收益对照在校准阶段失败，未进入留出测试。
**不能据此宣布节点路由优于整任务路由，Issue 第 4、6 项仍未验收。**

代码基于已合并的 PR #34（`831f71f965f81cc592063519e1b7ca2371147ea0`），
本轮变更位于 `codex/issue32-fair-baselines`，归档时尚未提交或发布。
所有真实调用均使用 Ark Agent Plan `/api/plan/v3`，沿用用户订阅验证授权。
两项独立实验顺序执行，各自零自动重试、首错停止；没有修改后重跑或筛除失败。

## 实现与对照设计

- `route_nodes` 增加 `assignment_mode=single-model`。先在完整候选空间计算统一标尺，
  再限制同一 DAG 全部节点使用一个模型；质量底线、成本上限、调度、时延约束和 A/B
  目标均与节点路由一致。测试确认 A/B 标尺一致、异构方案可行时单模型仍可能不可行。
- 八组协议增加 `dag-single-a/b`，保留直接强模型、串行/并行强模型、质量优先单模型
  及节点 A/B。新增两个对称配对比较，方法顺序按冻结种子在每个任务/重复内打乱。
- 三个新留出任务分别验证方案比较、费用测算和带条件改写；校准任务重新采样。
  计划 36 次校准整任务、72 次留出运行，最多 516 次模型调用。只有三个独立留出任务，
  即使完成也只能给出探索性结果。固定人工 DAG 不检验自动规划器质量。
- 对称基线针对「同一 DAG 的单模型分配与节点分配」，仍不等于优化过的一次调用
  整任务路由。新增交接验证则直接指定模型组合，不能算作自动路由收益。

## 六种显式交接：四种成功，一种失败，一种未启动

三个节点为 `cost`、`risk`、`answer`，前两者独立并行，最后汇总。
使用未作为新留出的校准材料：试点投入 12、覆盖 2 组；全面推广投入 40、覆盖 8 组，
并附试点易纠错、推广培训不足的风险材料。最终评审由独立的 Kimi K3 执行。

| 排列 | cost / risk / answer | 最终质量 | 状态 |
|---|---|---:|---|
| 1 | cheap / mid / strong | 95 | 通过 |
| 2 | cheap / strong / mid | 92 | 通过 |
| 3 | mid / cheap / strong | 92 | 通过 |
| 4 | mid / strong / cheap | 95 | 通过 |
| 5 | strong / cheap / mid | 不可用 | risk 多出 `assumptions_note`，拒绝交接 |
| 6 | strong / mid / cheap | 不可用 | 按首错停止规则未启动 |

cheap、mid、strong 分别为 DeepSeek V4 Flash、MiniMax M3、DeepSeek V4 Pro。
四种成功运行的汇总请求逐字段等于真实父节点输出，不是从任务描述重造的输入。
第 5 种两个根节点已派发并结算，`answer` 未启动；没有删除多余字段使输出强行通过。
这证明有限组合的真实交接可行性，不证明六种组合均可用、成功率改善或节点路由收益。

详见 [交接分析](handoff-analysis.json)、[原始运行](handoff/result.json)
及 [交接产物索引](handoff/artifact-index.json)。

## 剩余验收与实施顺序

1. 先改善并测量结构化输出的可靠性：本轮同时遇到多余字段和未转义引号，说明当前
   提示约束不足以确保多节点链路稳定。后续应在开发集独立验证供应商的结构化输出
   能力及模型适配差异，保持本地严格校验；不把解析修复后的输出混入原始成功样本。
2. 冻结新的实现和协议后，完整执行六种交接，保留失败率与最终语义质量；通过有限
   组合也不等于任意任务、上下文长度与上游模型组合已覆盖。
3. 完整执行八组多任务配对对照，满足样本完整性后才判断质量、成本和时延收益。
   如启用重试、修复或降级，必须预先纳入所有对照的用量、时延和失败规则。
4. 继续扩充分层 profile 与任务覆盖，并另行验证自动 DAG 规划质量及一次调用的
   对称整任务路由。第 4、6 项保持未勾选；第 1、2、3、5、7 项沿用既有验收。
