# Issue #32：失败节点的有界模型切换

## 结果

Python 核心已支持在已确认用量的节点结构错误、空输出或截断后，换一个可行模型重做
该节点。DSH 插件传入同一参数，由 Python 完成选择和记账；插件展示当前模型分配。

设置 `maxNodeFallbacks: 1` 开启一次切换，默认 0，最大 2。失败模型不会在该节点被
再次选择；没有可行候选、次数耗尽、取消或截止时停止 DAG。底层 HTTP 客户端保持
零自动重试。最终评审失败无法归因到特定节点，因此不自动重跑。

替换调用使用相同任务、契约与成功父节点输出。成功兄弟节点不重跑，失败内容不传给
下游；全部尝试拥有独立调用标签、输入输出、状态、时序和费用。初始预测不改写为
实际结果，切换前后分配及原因分别保留。容量、质量底线、剩余资源、真实生产预留和
provider 调度限制仍执行；未知用量或基础设施异常不进行切换。

## 边界与后续真实实验

A 根据剩余预测成本选择可行模型；B 使用初次 profile 的归一化标尺和原权重，防止
失败后缩小候选池改变权重含义。其他节点分配固定。在途费用已预留；在途剩余时延按
完整预测保守计算，可能拒绝实际上仍可完成的替换。启用恢复时节点生产准入以 costMax
限制总生产支出，含规划和失败尝试；最终评审另由评审额度限制。

这次验收只证明恢复机制。旧 v1-v6 原始失败及零回退实验不改写，v6 的未达综合收益
结论也不改变。核心指纹已变化，历史冻结协议应使用原报告中的源码归档复现。

后续收益对照须区分无恢复、局部节点切换和全任务换模型重跑。各组先冻结候选、次数、
调用包络和验收，统计全部失败与重做费用及时间。整图单模型若只换其中一个节点，
就属于异构分配，不能仍以整图单模型基线名义比较。当前尚未运行该真实恢复对照。

变更尚在本地待提交，未发布；使用者需更新匹配的 Python 源码并重新构建插件。
