流水第 2 轮按需专家产物中的 5 条引文：第 1、3 条逐字存在于实际传入的 `task`，
第 2、4、5 条逐字存在于 `context`。两条并非专家改写或编造，早先的归因已更正。
逐条匹配结果和原始摘要哈希见 `diagnostic.json`。

旧书面规范与实现只接受 `context`，但模型收到的系统提示与工具说明未清楚表达这一局部边界；
父模型也确实把事件材料放在了 `task`。这条过窄的字段规则造成了不必要拒收，
不能归为专家算术错误或实际输入中不存在的引文。

该样本两个模型请求均正常结束并结算，合计 1.357800 AFP。
专家输出 17190 token，输入 1117 字符，5 条引文，没有触及 384000 输出容量、
6000 字符输入或列表数量边界。核心停止前耗时 385.107 秒，外层耗时 385.734 秒。
原运行仍是 `failed / not-evaluated`，没有最终交付；副本匹配通过不等于原任务完成。

原批次 `live-04` 已等在途采购 DAG 完成后，以 `stopped-implementation-changed` 结束。

51.731700 AFP，包含全部旧诊断、这次误拒收和原始未知用量预留 0.630000 AFP。
原始产物、失败、评分和费用都不追改。
