# DSH 六策略有限端到端验收

验收日期：2026-09-29。

本目录记录 Static、Stage、Task、Composite、Advisor 和 Escalation 在用户现有 DSH profile
中的有限真实验收。测试保留 DSH 原生 Agent 循环；Router 不执行工具，不修改权限、提示、
上下文压缩或委派行为。

## 冻结范围

- 环境：DSH `0.1.5-rc.3`、插件 `0.29.0`、Python 核心 `0.15.4`。
- 配置：`refractagent-planning-v6`，六策略零调用诊断全部可用。
- 批次：六个新会话，最多 14 次远程模型调用，最多 60 AFP。
- HTTP 自动重试和委派关闭；媒体与 P6 子 Agent 共享预算不在本批次。
- Task 使用已安装的本地 Laya-MLX；本地推论不记 API 费用，质量仍按实验路线解释。

冻结任务、单项上限、验收条件和停止规则见 [preflight.json](preflight.json)。执行结果将在
真实调用后追加，不覆盖失败记录。

## 验收结果

六种策略的有限 DSH 端到端流程均已通过，详见 [results.json](results.json)。主批次发生
11 次远程模型调用、使用 16.4543 AFP。Escalation 迁移后的纠正复验再发生 2 次调用、
使用 1.09305 AFP；合计 13 次调用、17.54735 AFP，未超过 14 次和 60 AFP 的冻结上限。

| 策略 | 结果 | 调用与费用 | 核验重点 |
|---|---|---:|---|
| Static | 通过 | 1 次／0.6428 AFP | 随机权重选模、准确回复、轨迹完整 |
| Stage | 通过 | 2 次／1.29245 AFP | 一次宿主终端调用、同任务续接、证据与保持状态 |
| Task | 修复环境后通过 | 1 次／3.2125 AFP | 本地 Judge 一批次、不确定时使用指定备援 |
| Composite | 通过 | 3 次／6.5288 AFP | 一次 Task 判别、工具续接不重新分类 |
| Advisor | 通过 | 2 次／3.6652 AFP | 候选缓冲、审核通过后交付 |
| Escalation | 迁移 v4 后通过 | 纠正复验 2 次／1.09305 AFP | configured 合同、Judge 放行、候选只交付一次 |

没有发生认证失败、未知用量、账本写入失败或 HTTP 自动重试。DSH 原生工具由宿主执行；
Router 只完成选模、审核和模型费用结算。

## 验收中发现并修正的问题

1. 本地 Laya 权重已存在，但 DSH 实际调用的 `uv tool` 环境未安装 `local-judge` 可选组件。
   首次 Task 尝试在远程调用前停止；补齐同一工具环境并预热后复验通过。安装说明和错误提示
   已改为明确区分仓库 `.venv` 与已安装的 `refractagent` 环境。
2. 用户 profile 的 Escalation 仍是兼容旧配置，导致 Judge 放行时轨迹执行行显示“升级锁定”。
   已修正兼容路径的原因码，并通过设置页的显式迁移操作写入独立 Escalation 配置，默认策略
   继续保持 Stage。
3. 新配置改变了冻结摘要，因此另建
   [Escalation v4 纠正复验预检](escalation-v4-retest-preflight.json)。纠正复验使用
   `escalation-decision-v1`，轨迹显示起始候选、0.99 的 `PROCEED` 判定、费用和交付状态。

## 结论边界

- 本次证明六策略在当前 DSH profile 中能完成有限文本和原生工具流程，不证明策略普遍优于
  Static，也不覆盖图片、影片、委派或 P6 共享预算。
- Task 的 Laya 判别分数为 0.636、信息不足值为 0.9352，因此走指定备援。它证明故障安全
  分支可用；本地 Judge 的选模质量仍保持实验状态。
- Stage 与 Composite 的实际工具提示将冻结文本中的“只回复标记”改成“一句话确认输出”；
  一次工具调用、同任务续接和路由解释条件均按冻结要求核验，差异已保留在结果记录中。
