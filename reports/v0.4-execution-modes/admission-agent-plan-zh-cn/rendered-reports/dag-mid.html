2026 年企业 LLM Agent 平台选型报告

执行摘要

本报告针对 RefractRouter v0.1 的执行底座与 Agent harness 选型展开权衡。建议内层采用 LangGraph 作为执行底座，并叠加 DeepAgents 作为固定 DAG 的执行 harness，同时关闭其自主规划与动态子代理生成以保证可控性 [source_001][source_002]。DSH 保留为外层验证环境，不进入核心路由循环 [source_004]。评估层面强调在固定 DAG 下同时报告质量、成本与关键路径时延，以推进节点级选模型的 Pareto 前沿 [source_005][source_007]。

背景

企业级 LLM Agent 平台在 2026 年面临从"请求级选模型"向"节点级选模型"演进。现有路由研究多以整请求为单位选型，难以同时优化质量、成本与时延；RefractRouter 将路由粒度下沉至任务 DAG 的每个节点，目标是在固定任务分解下推进质量-成本-时延 Pareto 前沿 [source_005][source_006]。静态任务分解属应用层职责，v0.1 路由只消费 DAG，动态重切分待节点级路由验证后再考虑 [source_006]。

选型标准

选型从三个维度展开。其一为执行可控性，LangGraph 提供显式节点、边、持久化状态与 check-pointing，是固定任务 DAG 的天然下层执行基底 [source_002]。其二为 harness 边界，DSH 将 agent loop 插件化，在 v0.1 中仅作为外层验证环境，避免与核心路由职责混淆 [source_004]。其三为基准与评分，基准需固定 DAG、多模型并存、节点与任务级双粒度评分，并同时报告质量、成本与关键路径时延，规模须可复现；评分 rubric 覆盖需求、证据、深度、结构与 HTML 有效性，并随运行记录版本化 [source_007][source_008]。

平台比较

执行底座方面，LangGraph 提供节点、边、持久化状态与 check-pointing，适配固定任务 DAG [source_002]。DeepAgents 基于 LangGraph 构建，v0.1 阶段作为固定 DAG 的执行 harness，但需关闭自主规划与动态子代理生成以避免破坏节点级路由可控性 [source_001][source_002]。Pydantic AI 提供强类型工具与结构化输出，v0.1 尚非必需，可待结构化解析成为瓶颈时再纳入 [source_003]。Agent harness 方面，DSH 把 agent loop 插件化，与 RefractRouter 的核心路由职责不同，v0.1 仅作外层验证 [source_004]。

风险

若开启 DeepAgents 的自主规划与动态子代理，将破坏节点级路由的可控性，导致路由策略失效 [source_001]。若将 DSH 引入核心路由循环，会与节点级路由职责边界模糊，弱化 DAG 固定性 [source_004]。若基准未同时覆盖质量、成本与关键路径时延，将无法反映节点级路由的 Pareto 收益 [source_007]。若评分 rubric 与提示词未随运行记录版本化，将影响可复现性与审计追溯 [source_008]。若在 v0.1 阶段过早引入动态任务重切分，会越过路由验证前提 [source_006]。

结论

综合权衡后，建议 v0.1 采用 LangGraph + DeepAgents（关掉规划/子代理）作为内层执行与 harness，Pydantic AI 按需引入；DSH 留作外层验证环境。评估必须同时报告质量、成本与关键路径时延，坚持节点级粒度，待节点级路由稳定后再考虑动态任务重切分 [source_001][source_002][source_003][source_004][source_006][source_007]。
