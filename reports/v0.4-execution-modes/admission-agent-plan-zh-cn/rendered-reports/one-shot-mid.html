2026 年企业 LLM Agent 平台选型研究报告

执行摘要

本报告针对 2026 年企业级 LLM Agent 平台选型问题，以 RefractRouter v0.1 为核心参考场景，对 DeepAgents、LangGraph、Pydantic AI、DeepSeek Harness（DSH）四类候选执行框架/工具进行系统比较。核心结论如下：LangGraph 应作为底层执行基底，承担固定任务 DAG 的状态机管理；DeepAgents 作为 LangChain 衍生的执行外壳，在 v0.1 阶段应禁用其自主规划与动态子代理生成能力，仅保留固定 DAG 执行能力；Pydantic AI 在结构化输出成为瓶颈时按需引入，而非作为核心依赖；DSH（DeepSeek Harness）则保留给外层验证环境，不进入核心路由回路 [1][2][3][4]。

在路由范式层面，现有 LLM 路由工作多以"为整次请求选择单一模型"为前提，而 RefractRouter 关注的是"在固定任务 DAG 上，为每一个节点分别选模"，以期改善质量-成本-延迟的帕累托前沿 [5]。选型标准、基准设计、打分细则与版本化要求均围绕这一目标展开 [6][7][8]。

背景

2026 年企业级 LLM Agent 的落地形态，正在从"单一模型 + 提示工程"向"任务分解 + 多模型协同 + 评测驱动"演进。在这一背景下，平台选型面临两个层面的不确定性：一是执行框架的选择（谁来承载任务图与状态机），二是模型路由策略的选择（如何在多个候选模型之间分配子任务）。

RefractRouter 项目的核心研究问题是：现有 LLM 路由研究大多在"为整次请求选择单一模型"的粒度上工作，是否存在一种更细粒度的范式，即在固定任务 DAG 上为每个节点分别选模，从而整体上推进质量-成本-延迟的帕累托前沿 [5]。在该范式下，静态任务分解被划归应用层职责，路由器只接收已经定义好的 DAG 作为输入，并聚焦于节点级选模；动态重切分则要等到节点级路由被验证有效之后才考虑 [6]。

这一边界划分直接决定了平台选型必须满足两个先决条件：一是需要一个能够稳定执行固定 DAG 的执行基底；二是需要一个可重复、可计费、可打分的最小化基准，以支撑路由策略的实验与回归 [7]。

选型标准

结合 RefractRouter v0.1 的实际需求与基准设计原则 [7][8]，本报告将选型标准归纳为以下五项：

  1. 固定 DAG 执行能力：平台必须能够以显式节点与边的方式表达任务图，并支持持久化状态与检查点，从而保证路由实验可复现 [2]。
  2. 子代理与文件系统抽象：在多步骤任务中，平台应提供子代理与文件系统抽象能力，但 v0.1 阶段需要能够关闭自主规划与动态子代理生成，以避免路由实验被规划层的随机性污染 [1]。
  3. 结构化输出与类型化工具：当结构化输出解析成为性能或正确性瓶颈时，平台应能引入类型化工具定义与强校验；否则应保持轻量，避免不必要的核心依赖 [3]。
  4. 执行回路的可插拔性：外层验证环境需要能够替换核心执行回路以做 A/B 实验与对抗性测试，因此执行回路本身应可作为插件存在 [4]。
  5. 可计费与可打分的最小基准：必须建立固定任务 DAG、多候选模型、节点级与任务级打分、成本核算与关键路径延迟的最小可复现基准 [7]；打分维度应覆盖需求覆盖度、证据准确性、分析深度、结构与可读性以及 HTML 合法性 [8]。

平台比较

平台定位核心能力在 RefractRouter v0.1 中的角色主要限制
LangGraph 图状态机框架（底层执行基底） 显式节点与边、持久化状态、检查点 [2] 核心执行基底，承载固定任务 DAG 不直接提供子代理/规划能力，需上层封装
DeepAgents 基于 LangGraph 的 LangChain 外壳 规划、子代理、文件系统抽象、人机协同 [1] 可作为固定 DAG 执行外壳，但需禁用自主规划与动态子代理生成 若不收敛其自主能力，会污染路由实验变量
Pydantic AI 类型化工具与结构化输出 类型化工具定义、强结构化模型输出 [3] 仅在结构化输出成为瓶颈时按需引入，不作为核心依赖 对简单任务属于过度工程化
DeepSeek Harness（DSH） 可插拔代理回路框架 代理回路本身作为插件 [4] 保留给外层验证环境，不进入核心路由回路 作为核心执行回路会引入额外抽象成本

综合比较可见，四者构成一种"分层 + 边界"关系：LangGraph 负责最底层的图状态与持久化 [2]；DeepAgents 在其上提供 LangChain 风格的子代理/规划封装，但需要在 v0.1 阶段被裁剪 [1]；Pydantic AI 作为侧挂能力，按需启用 [3]；DSH 作为外层验证环境的"回路替换器"，与核心路由回路解耦 [4]。这一分层同时回应了"静态任务分解归应用层，路由器只做节点级选模"的边界划分 [6]。

与"为整次请求选择单一模型"的传统 LLM 路由范式相比 [5]，本选型更强调"每节点一模型"的细粒度，并以质量、成本、关键路径延迟三维联合作为评估信号 [7]。

风险

  1. 规划层变量污染风险：若 DeepAgents 的自主规划与动态子代理生成未被关闭，路由实验将无法区分"路由策略的收益"与"规划层的随机性收益"，导致结论失真 [1]。
  2. 动态重切分过早引入风险：在节点级路由尚未被验证之前就引入动态任务重切分，会同时移动分解边界与选模边界，违背"先单变量验证"的工程原则 [6]。
  3. 依赖膨胀风险：将 Pydantic AI 作为核心依赖会引入额外抽象与解析开销，只有在结构化输出确实成为瓶颈时才应引入 [3]。
  4. 核心回路与外层环境耦合风险：若把 DSH 直接用于核心路由回路，会与外层验证环境耦合，丧失"回路可插拔"带来的 A/B 实验与对抗测试灵活性；应将 DSH 保留给外层验证环境 [4]。
  5. 基准不可复现风险：若基准未固定任务 DAG、未做版本化的打分提示与权重管理，将难以复现与回归 [7][8]。

结论

针对 2026 年企业 LLM Agent 平台选型，本报告给出三点核心建议：

  • 执行基底选 LangGraph：以图状态机承担固定任务 DAG 的执行、持久化与检查点 [2]。
  • 外壳用 DeepAgents，但收敛其自主能力：DeepAgents 是基于 LangGraph 的 LangChain 外壳，v0.1 阶段应保留其子代理与文件系统抽象，但关闭自主规划与动态子代理生成，避免污染路由实验 [1]。
  • DSH 留外层验证，Pydantic AI 按需引入：DSH 仅用于外层验证环境的回路替换 [4]；Pydantic AI 仅在结构化输出成为瓶颈时按需启用 [3]。

在此基础上，应优先建立"固定 DAG + 多候选模型 + 节点/任务级打分 + 成本核算 + 关键路径延迟"的最小可复现基准 [7]，并对打分提示与权重进行版本化以便与运行记录绑定 [8]。选型策略与"为每个节点分别选模"的路由范式相一致：先把节点级路由的有效性验证清楚，再考虑动态重切分与更复杂的协同策略 [5][6]。

参考资料

  1. DeepAgents —— LangChain 外壳，构建于 LangGraph 之上，提供规划、子代理、文件系统抽象与人机协同。RefractRouter v0.1 中作为固定 DAG 执行外壳，需禁用其自主规划与动态子代理生成。
  2. LangGraph —— 图状态机框架，支持显式节点/边、持久化状态与检查点。RefractRouter 以其为固定任务 DAG 的底层执行基底。
  3. Pydantic AI —— 提供类型化工具定义与结构化模型输出。RefractRouter v0.1 不将其作为核心依赖，除非结构化输出解析成为瓶颈。
  4. DeepSeek Harness（DSH）—— 代理回路本身可作为插件的代理框架。RefractRouter v0.1 中 DSH 保留给外层验证环境，不进入核心路由回路。
  5. LLM routing research gap —— 现有 LLM 路由工作多在"为整次请求选单一模型"的粒度；RefractRouter 研究在固定任务 DAG 上为每个节点分别选模是否能改善质量-成本-延迟帕累托前沿。
  6. Task decomposition boundary —— 静态任务分解归应用层，路由器接收 DAG 作为输入并聚焦节点级选模；动态重切分在节点级路由验证通过前不予考虑。
  7. Benchmark design —— 路由基准需包含固定任务 DAG、多候选模型、节点级与任务级打分、成本核算与关键路径延迟；首个基准应保持可复现的较小规模。
  8. Scoring rubric —— v0.1 打分权重覆盖需求覆盖度、证据准确性、分析深度、结构与可读性、HTML 合法性；打分提示与 rubric 版本需与运行记录一同版本化。
