# 自动路由输入费用预测核对（2026-10-05）

## 范围与方法

只读取现有 `reports/` 下的 `result.json`，不新增模型调用。纳入已结算、保留完整
`request_messages`，且能对应到所选节点预测依据的记录。按调用账本的序列化方式，
以 `json.dumps(..., ensure_ascii=False)` 的字节数加 256 作为输入上界，和提供方确认的
输入 tokens 比较。未保存请求内容的记录不能用于这个比例核对。

## 结果

| 项目 | 数值 |
| --- | ---: |
| 可核对运行 | 9 次 |
| 可核对节点调用 | 19 次 |
| 涉及路线 | `ark-plan/deepseek-v4-pro` 一条 |
| 实际输入量 | 653～1864 tokens；中位 938 |
| 序列化字节／实际输入 token | 3.652～5.107；中位 4.558 |
| 用当前初始 4 字节／token 估算的输入量／实际输入量 | 0.913～1.277；中位 1.140 |

现有 `4 字节／token` 是选路费用的初始估计，不是提供方分词器保证。它在这批
记录中有一次方向上的低估可能，保守输入上界仍由完整序列化字节数保护，真实
模型调用仍按请求和输出容量预留，最后按确认用量结算。输出费用也会造成总费用
偏差，不能只凭输入比例推断整次调用费用。

这 19 次调用来自同一 Ark 模型，不能据此调整所有 provider 或模型的系数。本次
保留系数 4，并将预计、预留和结算分开呈现。后续只有取得更多路线、不同输入规模
且保留可信用量的样本，才考虑按实际路线校准；任何校准不得放宽容量准入或调用
前预算保护。

同日有限验收另有 `ark/glm-5.3` 的 7 次所选节点首次调用可从冻结预测和结算用量
直接核对：输入预测／实际为 1.084～1.320，中位 1.091。含工具续接的后续模型调用
不与首次节点预测混算；四节点任务的汇总节点包含父输出预计，因此偏差较大。这批
新记录同样不足以支持跨模型改系数，但没有显示需要放宽保守准入。
