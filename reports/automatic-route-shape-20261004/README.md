## 本轮发现和修正

无网络复现显示：当规划器返回一个可执行节点，而通用 direct 模板因质量画像不可行时，
原记录把选中的单节点方案标为 `dag`。实际上执行只有一个节点，不应计入多节点拆分。

现在比较仍保留两种候选各自的费用、准入和原始选择依据；如果选中规划器单节点候选，
对外路线归为 `direct`，注明选中来源、节点数及「未形成多节点拆分」。规划调用照实计费，
实际执行沿用原计划，不重复调用规划器或执行器。若通用 direct 模板获选，仍执行该模板；
真正多节点候选获选时继续归为 `dag`。DSH 摘要显示这一形态区别。

此修正只校准路线身份和审计记录，不改变模型质量估计、预算、安全准入或原有 DAG 调度。
无网络功能测试覆盖通用 direct、规划器单节点和多节点 DAG 三种选择，以及 DSH 摘要。
完整 `uv run pytest` 为 1494 项通过；插件契约测试为 176 项通过，类型检查与构建通过。
核心 `0.15.9` 已装入原有工具环境，插件 `0.29.6` 的分发包已构建。
原 DSH `web` profile 继续链接本仓库插件；重启后浏览器中的规划路由、自动路由设置卡片、
任务 DAG 和路由轨迹仍共同存在，旧会话正常回放。没有更改 provider、凭证或预算，
也没有用真实模型触发本次单节点分支。
它不能证明拆分质量或收益；#112 的真实绑定和
