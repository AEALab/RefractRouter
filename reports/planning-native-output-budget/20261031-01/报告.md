## 修复结果

预算预检、必要调用路径、现金/订阅参考准入、实际预留共用原生输出合同。
回答专用或旧未知语义使用配置共享上下文和最高边际价；已核对的全部输出上限使用
输入包络加原生输出容量。思考已包含在全部输出费用，不重复计费。
原生请求值不因预算不足被缩减；保留既有调用方及策略合同，不自动加预算、改模型池、
策略算法、阈值或默认值。修正后的预算准入可能拒绝原先错误放行的请求。

用量未知保留完整预留并停止本任务所有币种账本；取消、回滚、重启不释放未知用量，
已知在途用量按实际计费，候选不交付，不自动重发。
思考细分可从 Chat/Responses 及 DSH 原生回执穿过规划包装，缺失或矛盾保留未知。
原生范围、输入、总量、来源及保守价格进入原逐调用证据。

合同、公式、迁移和宿主边界见[原生预算说明](../../../docs/planning-native-output-budget.md)。
旧未核对配置按上下文保守预留，保护金额可能增加；它不是已消费金额，不会自动调高用户预算。
新发布 r2 仍要求明确语义/来源与实际参数一致，不放宽真实质量/收益要求。

## 原问题的零调用反例

固定示例价输入/输出 0.45 CNY/千 token；配置上下文 1024000，原生回答上限 131072。
回执输入100、全部输出250000、思考249000，纯回答1000。

| 观察 | 旧问题记录 | 修复后的本机验收 |
| --- | --- | --- |
| 请求回答上限 | 原生131072 | 仍为131072 |
| 派发前保护 | 原记录仅3.8313 CNY | 共享上下文保护460.8 CNY |
| 70 CNY预算 | 曾允许派发，结算112.545后才停止 | 首次派发前拒绝，本机上游请求0次 |
| 充足预算 | 结算后才能发现漏保护 | 1000预算先预留460.8，按回执结算112.545 |
| 全部输出大于回答上限 | 未区分回答与思考 | 250000全部输出、1000纯回答合法通过 |
| 已核对全部输出上限32768 | 历史通用Chat会按8192预留 | 原生32768预留并实际派发 |

旧3.8313来自原 Issue 中那份输入的固定反例；新回归输入不与其字节等同，
共享上下文保护不依赖该小输入差异。两列均为模拟固定价格算术，不是真实扣款。
已知回执超出合同仍先结算费用再停止；缺少思考细分时不能用占位零证明回答合规。

## 独立预审及修正

两位独立 AI 分别核对预算数学/结算，以及 Runtime/Gateway/发布/宿主。
底层预算另以3888组离线费用上界比较核验，未复现下界缺口。
预审报告的三项 P2 均补正式反例并修正：

| 问题 | 修复 |
| --- | --- |
| DSH无法证明直接HTTP参数映射 | 首次宿主调用前拒绝具体HTTP参数，只接通host-maxTokens；派发边界再检查 |
| 派生r1组件时误用新r2规则 | 保留原版本；已有旧活动试用/默认明确要求重新冻结，事务不改原资格、次数或路线 |
| 网关不支持参数也能取得资格 | r2冻结时拒绝未接通的max_output_tokens，不让无法执行的配置获证 |

限定复核在2480d5a44确认上述问题闭环。最终PR精确头部的复核和CI记录以GitHub为准，
AI审查不冒充维护者人工批准。
