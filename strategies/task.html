Task · 任务 ​

Task 在新任务开始时，从用户自选模型池选择主执行模型，任务内保持。 工具续接、追加指导和上下文压缩不重新执行分类。

一次选模流程 ​

  1. 冻结模型池、优先顺序、Judge、备援、参数、价格和预算。
  2. Python 检查输入、上下文、工具能力、数据域和历史兼容，排除不合格候选。
  3. 单一合格候选直接使用；多个候选执行一次任务级 Judge 判别。
  4. 依据已验证合同与门槛选出主模型；平分按池的优先顺序处理。
  5. 正常无法确定时使用指定备援，备援也必须通过准入和预算。

没有合格候选时停止并列出缺项。认证、传输或未知用量是故障，不作为正常“不确定” 轮流尝试其他模型。

Judge 可以选什么 ​

  • 轻量 LLM：使用已配置路线，严格检查结构化结果，不追加修复调用。
  • 官方 Jev：任务级 Choice，候选与“信息不足”选项明确分开。
  • 本地 Laya：常驻、批次结构化判别，不要求生成理由；当前质量标为实验。

不能把候选适合度或 Choice 概率称为任务成功率，也不直接比较不同后端的分数。 完整输入超出本地容量时按正常容量回退处理，不隐式截断或调用摘要模型。

必要设置 ​

主模型池及各模型推理等级、池优先顺序、Judge 类型、指定备援。 默认要求备援在池内。媒体能力按实际接口记录，专门生成图片或影片的模型不充当主 Agent。

费用与轨迹 ​

付费 Judge 前保护一次必要执行额度；互斥候选不把全部模型上下文费用相加。 记录候选排除原因、一次初选／单候选／备援原因、原始答案、实际执行器、费用和耗时。 Task 固定选择不是全局成本最优保证。
