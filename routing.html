两种路由怎么选 ​

两个入口共享已适配的模型目录、价格依据和安全准入，但采用不同执行结构。

在 DSH 中找到两个入口 ​

两种路由在 DSH 设置中使用独立的配置卡片，互不混放：

配置完成后，在对话输入框的模型菜单中选择对应入口：规划路由显示为“路由模式”， 自动路由显示为“自动路由（真实执行）”。

本组新截图使用 DSH 0.1.5-rc.3、已安装插件 0.33.25，不覆盖已安装版本。 仓库当前插件为 0.33.21，因此实际客户端的新控件与源码下载包可能存在版本差异。 截图中的模型、金额和默认值是当时配置示例，使用时仍须核对自己的模型能力与价格。

建议的选择顺序 ​

日常任务先从规划 Static 开始。固定模型可用后，再根据需要选择 Stage、Task、Advisor、 Escalation 或 Composite。需要验证独立子问题与并行调用时，单独选择自动路由。

自动路由选择 Direct 时，它仍属于自动路由运行记录；不是自动变成某个规划策略。 Advisor 的最终回复 Gate 与自动路由的最终 Judge 也不是同一个策略配置。

三类判断不要混淆 ​

  1. 能否拆分：有没有独立子问题、依赖是否允许分开处理。
  2. 是否选 DAG：准入、质量依据、规划与汇总开销、费用及时间预测是否支持它。
  3. 候选能否交付：实际输出、工具证据和审核结果是否满足任务合同。

Jev 可以为其中适合有限回答的问题提供信号，Python 执行最终规则。 “可以拆分”不等于“DAG 更便宜”，审核通过也不反向证明当初选路最优。

什么时候用规划路由 ​

任务需要边做边看——读文件、跑测试、根据工具结果决定下一步——就属于这类。 Agent 保持完整的原生循环和工具审批，Router 只在每次模型调用前做选择：

  • 日常编码与调试：Stage 依据工具证据在高效与强执行模型之间切换。
  • 多模型团队配置：Task 在任务开始从池中选一个主模型，整个任务内保持。
  • 高风险交付：Advisor 在最终回复前审核，必要时返工一次并复审。
  • 成本控制：Escalation 先用便宜模型，不合格才切换到指定接管模型。

走标准 Base URL 的客户端（如 Codex CLI）用 refract/static 等虚拟模型接入， 和 DSH 插件走的是同一套 Python 策略。

什么时候考虑自动路由 ​

任务包含相互独立、可并行处理的子问题，且模型价差明显时，才值得评估 DAG： 例如多份材料的独立分析、跨多个对象的分别调研。Router 会在规划前先判断结构信号， 不会为简单任务支付规划调用；即使进入规划，规划出的单节点结果也归为 Direct。

自动路由目前定位为研究入口：DAG 的规划、汇总、审核和失败尝试都计入总成本， 尚无证据证明它在同等质量下普遍更便宜或更快。选择它的目的应是验证与探索， 而不是默认的生产路径。

共同边界 ​

Router 不承担技能组织、智能体驾驭工程、工具权限、上下文压缩或子 Agent 任务管理。 DSH 与 Codex 的接入合同不同，不能因为模型 API 返回成功就宣称其全部功能兼容。 本轮产品范围以 DSH 与 Codex CLI 为主；其他客户端的历史实验不扩大当前承诺。
