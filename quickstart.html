第一项任务 ​

建议先用 Static 固定模型 验证安装、凭证和原生工具，再逐一启用需要 Judge 的策略。 一次运行完成不表示所有策略或 Judge 后端已经通过质量验收。

1. 先配置 DSH 的真实模型 ​

进入 DSH 的模型设置，配置自己的 provider、端点、模型 ID 与凭证。 Ark Agent Plan 订阅路线使用 /api/plan/v3；普通按量接口按实际 provider 配置。 Router 复用目录与凭证，不另复制一份密钥。

先用 DSH 的普通模型确认该路线可用。价格、上下文、输出和推理等级以实际路线的资料为准， 不能把另一渠道同名模型的资料直接套用。

2. 启用规划路由 ​

打开 设置 → 插件 → RefractAgent 规划路由：

  1. 启用规划路由，确认正在编辑的是 Static。
  2. 选择“高效执行模型”；当前 Static 固定模式使用这个角色。
  3. 从支持的值中选择推理等级，或选择提供方默认。
  4. 核对数据域；需要发往可信云时登记相应信任策略。
  5. 设置任务现金预算、参考估值额度、期限与调用数。
  6. 运行零调用诊断并保存。

Static 固定模式不需要强执行、任务 Judge 或审核模型。页面上的通用角色不表示每个策略 都必须配置它们。Static 的实际设置列出了当前限制。

3. 选择路由模式并发起任务 ​

在对话模型菜单选择 RefractAgent · 规划路由，再在 路由模式 中选择 Static。 这里选的是策略，底层模型推理等级使用前一步的角色设置。

先问一个简单问题，例如 2 + 2。确认回复来自真实模型，且没有 [SIMULATED] 或验收夹具文字。 再提交一个你已允许 DSH 执行工具的短任务，确认工具仍由 DSH 审批与执行。

4. 检查实际调用 ​

打开 路由轨迹，展开本次记录：

  • 实际 provider、模型、推理等级与用途是否符合固定角色；
  • 是否只有预期的执行调用，没有额外 Task Judge 或审核；
  • 工具调用与结果是否配对；
  • 参考估值、按量现金与待核对预留是否分别列出；
  • 开始时间、总耗时与首字时间是否可见。

5. 再试其他路线 ​

  • 工具任务需要逐轮调整模型：Stage。
  • 每个任务从多个模型中选一个：Task。
  • 最终回复必须审核与复审：Advisor Gate。
  • 先尝试起始模型、必要时锁定接管：Escalation。
  • Task 初选后允许临时切换：Composite。
  • 研究显式任务拆分：自动路由。

每次新任务冻结设置。运行中的工具续接和追加指导沿用现有预算与计数；保存设置供下个任务使用。
