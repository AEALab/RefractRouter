自动路由 · Direct 与 DAG ​

独立研究入口

自动路由先判断任务结构，再比较整任务 Direct 与 DAG 候选。DAG 的节点可以使用不同模型 与推理等级；合法的独立分支可以并行调用模型。

一次运行的过程 ​

  1. 冻结模型池、任务要求、数据域、价格、预算和期限。
  2. 规则或可选 Jev 判断独立工作与依赖；微型任务可跳过额外判别。
  3. 有必要时调用规划模型，生成计划并校验职责、依赖与输出合同。
  4. Python 依据合法性、能力与质量依据、费用和时间预测选择 Direct 或 DAG。
  5. 调用选定模型；DAG 按依赖执行，最终组合候选。
  6. 检查实际工具与候选风险，按自适应最终审核决定审核与交付。

Jev 负责什么 ​

Jev 适合回答是否存在值得分别处理的独立工作、分支间是否必须串行等有限问题。 它提供拆分信号，不负责生成完整 DAG、执行工具、结算费用或保证 DAG 更便宜。 节点计划仍由生成模型产出，Python 校验并作最终路线决策。

为什么可能继续选 Direct ​

可拆分任务也可能有较高的规划、上下文重复、汇总或审核开销。 预算、期限、数据域、节点准入与预测依据不足，都可能使 Direct 更合适。 选择理由应出现在实际记录，不只显示 Jev 的拆分答案。

模型池与节点分配 ​

多个可用模型不表示每个节点必须使用不同模型。 节点类型、难度、风险、资料域、上下文、参数、质量依据和现金／参考成本共同影响候选。 缺少独立节点观测时显示使用全局先验；不能把排行榜分数当作该节点已经证明等质。

模型调用并行与工具执行并行分开处理：独立节点可以并行调用，宿主工具保持既有调度与审批。 汇总等待必要上游完成；节点失败按冻结停止或有界切换规则处理。

系统设置示范 ​

进入 设置 → 插件 → RefractAgent 自动路由。以下均为 2026-10-14 打开实际 DSH 的截图， 使用已安装插件 0.33.25；仓库下载包为 0.33.21。截图值是当时配置，非通用推荐额度。

控件如何理解对运行的影响
RefractRouter 连接本地已安装核心或部署配置本地模式不要求插件复制 Python 业务逻辑；远程路线以实际支持为准
启用开发真实执行允许使用配置的真实模型与模型菜单中的模拟／真实入口分别核对
单任务 DSH 工具调用Router 管理的工具调用上限0 关闭；取消该上限仍受 DSH 权限、预算与期限约束
任务处理方式自动判断或显式处理方式决定是否比较 Direct 与 DAG，不负责最终质量审核
评审方式截图为自适应根据风险、工具事实与候选决定评审强度

先核对各模型真实 provider、上下文与输出容量、工具能力、价格单位、数据域和信任策略。 截图的生产现金上限 5 CNY、评审现金上限 1 CNY 是当前配置，不能拿来补写历史运行预算。

本例拆分 Judge 上限 0.01 CNY 独立记账；0.65 约束是／否答案概率， 不等于“DAG 成功率 65%”，也不是 Task、Advisor 或 Escalation 的 Choice 门槛。 界面中的“无限制”取消对应金额硬上限，不会让模型调用免费；任务实际预算与冻结证据仍须核对。

截图审核器为 ark/glm-5.3（Low），等待上限 180 秒、预留 60 秒，并勾选一次纠正。 等待上限仍受任务剩余期限限制；预留时间留给审核执行，不延长原任务。 更多跳过与升级条件见自适应最终审核。

真实案例一：可拆分，最终选择 Direct ​

下面是 2026-10-07 一次真实自动路由任务的完整记录（证据目录 reports/automatic-routing-trace-20261007），任务内容是独立审查三个互不依赖的文件。

第一步：Jev 判别任务结构。 Judge 对“是否依赖前一步输出”“是否可独立开始”“是否只有 一项工作”三个问题给出概率，规则合并后分类为 SEPARABLE（可拆分）。

第二步：比较两条路线后选择 Direct。 直接路线预测 0.687 CNY，DAG 候选预测 1.385 CNY。该次已知调用的预测成本中，直接路线更低，最终整任务直接执行； 未执行的 DAG 只保留预测，不能拿差额计算真实节省。

第三步：执行、工具回执与费用结算。 任务执行中宿主返回 bash 工具回执，费用账本按用途 分别记录参考成本与现金用量。

同一个任务族里，另一次运行（2026-10-09，reports/automatic-quality-20261009）的 Jev 同样判为 SEPARABLE，但直接路线预测 0.126 CNY 低于 DAG 的 0.307 CNY，同样选择 Direct。 两次真实运行说明：可拆分不等于应该拆分，路线比较才是最终决策。

费用、Judge 与工具回执的完整口径见 10 月 7 日公开报告。

真实案例二：三项目独立分析，执行多节点 DAG ​

2026-10-05 的有限验收要求分别分析三个虚构项目，每项给出目标是否达成、两个量化依据、 一个风险和一项建议，最后汇总优先级，禁止混用数据，不要求工具。

项目目标与输入事实独立节点应核对的重点
甲响应目标 600 ms；实际 920 → 580 ms；故障率 0.4% → 0.8%；月成本 4 → 5 万响应达标并下降 340 ms，同时保留故障翻倍与成本上升的风险
乙成本目标 6 万；实际 8 → 5.8 万；响应 700 → 760 ms；故障率保持 0.2%成本达标并节省 2.2 万，同时说明响应变慢
丙成功率目标 98%；实际 94% → 97.5%；响应 500 → 450 ms；成本 3 → 3.2 万成功率提高但仍差 0.5 个百分点，不把进步写成已达标

读图时从上游向下看：准入完成后，三个项目分析之间没有相互依赖； answer 必须等待三份结果才能汇总。这样的拓扑允许分支并行，但截图本身不能证明 实际调度有多大并发，或与 Direct 相比节省了多少时间。

在 DSH 中配置 ​

使用独立的 RefractAgent 自动路由 卡片：选择执行模型池、数据域与信任策略， 核对规划／拆分／最终审核用途，设置任务预算、期限、调用与输出限制。 零调用诊断通过后，启用真实执行并选择 自动路由（真实执行）。

“省成本／均衡／质量优先”是历史三档入口，不代表新版两种路由的六策略。 旧模型 ID 为历史读取保留；新设置需要按当前模型目录显式初始化或升级。

已知边界 ​

当前没有充分证据证明 DAG 在同等或可接受质量下普遍更便宜、更快。 规划、汇总、审核、丢弃和失败尝试均计入总体费用；只比较成功节点会低估总开销。 DSH 的接线通过也不是任意 Agent 的 DAG 协议兼容证据。标准模型网关不自动进入 DAG。
